📖 The Story — Universal Remote
One Interface, Many Devices

A universal remote controls different devices with one interface. Python database connectors work similarly - one API for different databases.

Imagine a universal remote that can control your TV, AC, and sound system. You don't need separate remotes for each device. Python's DB-API (Database API) works the same way. It provides a standard interface for different databases. Whether you're using SQLite for development, PostgreSQL for production, or MySQL for legacy systems, the basic operations (connect, execute, fetch) remain consistent. ORMs like SQLAlchemy go further - they let you work with Python objects instead of SQL queries.

🔧 sqlite3 Example
Using sqlite3 (built-in):

import sqlite3

# Connect
conn = sqlite3.connect("app.db")
cursor = conn.cursor()

# Create table
cursor.execute("""
  CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE
  )
""")

# Insert
cursor.execute("INSERT INTO users (name, email) VALUES (?, ?)",
    ("Alice", "alice@example.com"))
conn.commit()

# Query
cursor.execute("SELECT * FROM users")
users = cursor.fetchall()
print(users)

# Close
conn.close()
🔧 SQLAlchemy Example
Using SQLAlchemy ORM:

from sqlalchemy import create_engine, Column, Integer, String
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import sessionmaker

# Setup
Base = declarative_base()
engine = create_engine("sqlite:///app.db")
Session = sessionmaker(bind=engine)
session = Session()

# Define model
class User(Base):
  __tablename__ = "users"
  id = Column(Integer, primary_key=True)
  name = Column(String(50))
  email = Column(String(100), unique=True)

# Create tables
Base.metadata.create_all(engine)

# CRUD operations
user = User(name="Alice", email="alice@example.com")
session.add(user)
session.commit()

# Query
users = session.query(User).filter_by(name="Alice").all()
print(users[0].email)
⚠️ Common Mistakes
❌
Not using parameterized queries.
✔ Never use string formatting for SQL queries. Use parameterized queries (?) to prevent SQL injection attacks.
❌
Forgetting to commit transactions.
✔ Changes are not saved until you call conn.commit(). Remember to commit after INSERT, UPDATE, DELETE.
❌
Not closing connections.
✔ Always close connections when done. Use context managers (with statement) for automatic cleanup.
🎯 Interview Questions
Q
"What is an ORM and why would you use one?"
"ORM (Object-Relational Mapping) is a technique that maps database tables to Python classes and rows to objects. Benefits: write Python code instead of SQL, automatic relationship management, database portability, and reduced boilerplate. SQLAlchemy is the most popular Python ORM."
Q
"What is SQL injection and how do you prevent it?"
"SQL injection is a security vulnerability where malicious SQL code is inserted into queries. Prevent it by using parameterized queries instead of string formatting. Example: cursor.execute('SELECT * FROM users WHERE id = ?', (user_id,)) - the ? placeholder ensures proper escaping."
