📖 The Story — Library Books
Return Books

A library lends books, tracks borrowers, and re-shelves returned books. Python's garbage collector works like a librarian, reclaiming memory from unused objects.

Imagine a library where books are borrowed and returned. When someone loses interest in a book and returns it, the librarian puts it back on the shelf for others to use. Without this system, the library would run out of space. Python's Garbage Collector works the same way. When objects are no longer needed, it automatically frees their memory so it can be reused.

🔧 Reference Counting Example
Understanding reference counting:

import sys

# Create object
x = [1, 2, 3]
print(sys.getrefcount(x)) # 2 (x + getrefcount)

# Add reference
y = x
print(sys.getrefcount(x)) # 3

# Remove reference
y = None
print(sys.getrefcount(x)) # 2

# When count reaches 0, object is deleted
x = None
# Object is now eligible for GC
🔧 Circular Reference Example
Problem of circular references:

class Node:
  def __init__(self, name):
    self.name = name
    self.ref = None

# Create circular reference
a = Node("A")
b = Node("B")
a.ref = b
b.ref = a # Circular!

# Remove external references
a = None
b = None

# Objects still exist due to circular ref
# Garbage Collector will clean them up
🔧 Using gc Module
Controlling garbage collection:

import gc

# Check if GC is enabled
print(gc.isenabled()) # True

# Disable GC
gc.disable()

# Enable GC
gc.enable()

# Manually trigger GC
collected = gc.collect()
print(f"Collected {collected} objects")

# Get GC stats
print(gc.get_stats())
⚠️ Common Mistakes
❌
Thinking GC collects everything immediately.
✔ Reference counting deletes most objects immediately. GC only handles circular references periodically.
❌
Creating unnecessary circular references.
✔ Be careful with mutual references. Use weakref when appropriate.
❌
Calling gc.collect() too frequently.
✔ Let Python manage GC automatically. Manual collection is rarely needed.
❌
Confusing del with immediate deletion.
✔ del removes a reference, not necessarily the object. Object is deleted only when reference count reaches 0.
🎯 Interview Questions
Q
"How does Python manage memory?"
"Python uses reference counting as the primary mechanism. Each object has a count of references to it. When the count reaches zero, the object is immediately deleted. For circular references, Python has a cyclic garbage collector that runs periodically. The gc module allows control over this process."
Q
"What are circular references and how does Python handle them?"
"Circular references occur when two or more objects reference each other, creating a cycle. Reference counting alone can't delete them because their counts never reach zero. Python's cyclic garbage collector identifies and removes these unreachable cycles. You can also use weak references to avoid circular references."
