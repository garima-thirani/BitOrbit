📖 The Story — Restaurant Token
Promise of Future Work

You order food and get a token. The token isn't the food - it's a promise that food will be ready later. A Future object works the same way.

Imagine ordering food at a restaurant. The waiter gives you a token with a number. This token represents a promise: "Your food will be ready soon." You don't wait at the counter - you can sit and chat while waiting. When the food is ready, you exchange the token for your order. Futures work exactly like this token. They represent a result that will be available in the future, allowing your program to continue working while waiting.

🔧 ThreadPoolExecutor Example
Using ThreadPoolExecutor for IO-bound tasks:

from concurrent.futures import ThreadPoolExecutor, as_completed
import time

def download_file(url):
  time.sleep(1) # Simulate IO
  return f"Downloaded {url}"

urls = ["url1", "url2", "url3", "url4"]

# ThreadPoolExecutor for IO-bound work
with ThreadPoolExecutor(max_workers=3) as executor:
  # Submit all tasks
  futures = [executor.submit(download_file, url) for url in urls]

  # Get results as they complete
  for future in as_completed(futures):
    print(future.result())
🔧 ProcessPoolExecutor Example
Using ProcessPoolExecutor for CPU-bound tasks:

from concurrent.futures import ProcessPoolExecutor

def cpu_intensive_task(n):
  return sum(i*i for i in range(n))

numbers = [1000000, 2000000, 3000000, 4000000]

# ProcessPoolExecutor for CPU-bound work
with ProcessPoolExecutor(max_workers=4) as executor:
  # Map function to data
  results = executor.map(cpu_intensive_task, numbers)

  for result in results:
    print(result)
🔧 submit() vs map()
Understanding the differences:

from concurrent.futures import ThreadPoolExecutor

def process(x):
  return x * 2

with ThreadPoolExecutor() as executor:

  # submit() - individual tasks
  future1 = executor.submit(process, 5)
  future2 = executor.submit(process, 10)
  print(future1.result()) # 10
  print(future2.result()) # 20

  # map() - same function on iterable
  results = executor.map(process, [5, 10, 15])
  print(list(results)) # [10, 20, 30]
⚠️ Common Mistakes
❌
Calling future.result() immediately after submit().
✔ This blocks the current thread. Only call result() when you're ready to wait for the result.
❌
Using ThreadPoolExecutor for CPU-intensive tasks.
✔ Use ProcessPoolExecutor for CPU-bound work to bypass the GIL.
❌
Not handling exceptions from futures.
✔ Wrap future.result() in try-except to catch exceptions from worker threads/processes.
❌
Creating too many workers.
✔ Use max_workers parameter. For IO-bound: 2-5x CPU cores. For CPU-bound: number of CPU cores.
🎯 Interview Questions
Q
"What is a Future object?"
"A Future represents the result of an asynchronous computation that may not have completed yet. It's a placeholder for a value that will be available in the future. You can check if it's done, add callbacks, or retrieve the result (blocking if not ready)."
Q
"When should you use ThreadPoolExecutor vs ProcessPoolExecutor?"
"Use ThreadPoolExecutor for IO-bound tasks (file operations, network requests, database queries) where threads spend time waiting. Use ProcessPoolExecutor for CPU-bound tasks (computations, data processing) where you need true parallelism and want to bypass the GIL."
