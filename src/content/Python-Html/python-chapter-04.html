📖 The Story — Building a House
Quality Matters

Writing code is like building a house. Both houses work, but which one will be easier to repair ten years later?

Imagine two construction teams. The first team builds a house quickly. The second team spends extra time labeling every wire, organizing every pipe, drawing proper blueprints, and keeping everything clean. Both houses work. But ten years later, which house will be easier to repair? Obviously, the second one. Programming is exactly the same. Writing code is easy. Maintaining it for years is difficult. Professional developers spend 80% of their time reading code and only 20% writing it.

🥇 The Golden Rule
Code is written once but read hundreds of times. Always optimize your code for readability. Your future teammates—and your future self—will thank you.

📋 PEP 8 — Python Style Guide
PEP 8 (Python Enhancement Proposal 8) is the official coding style guide for Python. It defines standards for naming, indentation, spacing, imports, blank lines, comments, and line length. Following PEP 8 makes code consistent and easier to maintain.

Key Rules:
• Use 4 spaces for indentation (not tabs)
• Keep lines under 79 characters
• Use spaces around operators: total = price + tax
• Separate logical sections with blank lines
• Place imports at the top of the file
• Use snake_case for variables and functions
• Use PascalCase for classes

💬 Comments vs Docstrings
Comments explain why something is done, not what the code already says. Use # for single-line comments.

Docstrings document functions, classes, or modules and can be accessed programmatically using help(). Use """triple quotes""".

Example:
# Retry after temporary network failure (comment — explains why)
def add(a, b): """Returns the sum of two numbers.""" (docstring)
⚠️ Common Beginner Mistakes
❌
Meaningless variable names.
✔ Use descriptive names: age = 10 instead of x = 10. Good names make code self-documenting.
❌
Ignoring indentation.
✔ Python depends on indentation to define blocks. Always use 4 spaces consistently.
❌
Using camelCase for variables.
✔ Python uses snake_case for variables and functions: student_name not studentName.
❌
Writing comments for obvious code.
✔ Avoid # Add one above x += 1. Explain why, not what the code already shows.
🎯 Interview Questions
Q
"What is PEP 8 and why is it important?"
"PEP 8 (Python Enhancement Proposal 8) is the official coding style guide for Python. It provides conventions for naming, indentation, spacing, imports, comments, and line length. Following PEP 8 makes code consistent, readable, and easier to maintain across different developers and projects. Tools like Flake8 and Black help enforce PEP 8 automatically."
Q
"What is Pythonic code?"
"Pythonic code uses Python's features to write code that is simple, readable, and expressive. Instead of writing code like other languages, it embraces Python's strengths. Examples include using a, b = b, a for swapping instead of a temporary variable, using enumerate() instead of range(len()), and using if not items: instead of if len(items) == 0:."
Q
"What is the difference between comments and docstrings?"
"Comments explain parts of the code to developers and are ignored by Python. They use # and should explain why something is done. Docstrings document functions, classes, or modules using """triple quotes""" and can be accessed programmatically with help(). Docstrings become part of your project's documentation."
Q
"Why should variable names be meaningful?"
"Meaningful variable names make code self-documenting. Readers can understand the program without relying heavily on comments. For example, monthly_salary = 500 is immediately clear, while x = 500 requires the reader to guess or search for context. Good names reduce cognitive load and simplify maintenance."
