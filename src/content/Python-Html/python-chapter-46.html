📖 The Story — Factory Quality Control
Quality Check

A factory tests every product before shipping. Software should be tested too - every function, every edge case, every scenario.

Imagine a factory manufacturing light bulbs. Each bulb undergoes rigorous testing: does it turn on? Does it last 1000 hours? Does it handle voltage fluctuations? Only after passing all tests does it reach customers. Software development works the same way. Testing verifies that your code works correctly, catches bugs early, and ensures changes don't break existing functionality.

🔧 unittest Example
Testing with unittest:

import unittest

def add(a, b):
  return a + b

class TestMath(unittest.TestCase):

  def test_add(self):
    self.assertEqual(add(2, 3), 5)
    self.assertEqual(add(-1, 1), 0)
    self.assertEqual(add(0, 0), 0)

  def test_negative(self):
    self.assertEqual(add(-5, -3), -8)

if __name__ == '__main__':
  unittest.main()
🔧 pytest Example
Testing with pytest (simpler):

def add(a, b):
  return a + b

# Simple test function
def test_add():
  assert add(2, 3) == 5
  assert add(-1, 1) == 0
  assert add(0, 0) == 0

# Parametrized test
@pytest.mark.parametrize("a,b,expected", [
  (2, 3, 5),
  (-1, 1, 0),
  (0, 0, 0)
])
def test_add_parametrized(a, b, expected):
  assert add(a, b) == expected
🔧 Test Fixtures Example
Using fixtures for setup/teardown:

import pytest

# Fixture runs before each test
@pytest.fixture
def sample_data():
  data = [1, 2, 3, 4, 5]
  print("\nSetup: Creating test data")
  yield data # Provide data to test
  print("\nTeardown: Cleaning up")

def test_sum(sample_data):
  assert sum(sample_data) == 15

def test_length(sample_data):
  assert len(sample_data) == 5
⚠️ Common Mistakes
❌
Testing only the happy path.
✔ Test edge cases, invalid inputs, and error conditions too.
❌
Writing tests that depend on each other.
✔ Each test should be independent and run in any order.
❌
Not running tests automatically.
✔ Integrate testing into your development workflow and CI/CD pipeline.
❌
Ignoring test failures.
✔ Fix failing tests immediately. Don't let them accumulate.
🎯 Interview Questions
Q
"What is unit testing and why is it important?"
"Unit testing verifies individual functions or methods work correctly in isolation. It's important because it catches bugs early, enables confident refactoring, serves as documentation, and prevents regressions. Good unit tests are fast, isolated, repeatable, and cover both normal cases and edge cases."
Q
"What's the difference between unittest and pytest?"
"unittest is Python's built-in testing framework with class-based tests and more boilerplate. pytest is a third-party framework with simpler function-based tests, automatic test discovery, better fixtures, and powerful features like parametrization. pytest is generally preferred for new projects due to its simplicity and features."
