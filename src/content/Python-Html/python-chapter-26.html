📖 The Story — Safety Inspector
Quality Assurance

A safety inspector checks every part of a bridge before it opens. Testing checks every part of your code before it ships.

Imagine a bridge being built. Before it opens to the public, safety inspectors check every bolt, weld, and support structure. They find problems before they become disasters. Software testing works the same way. Instead of waiting for users to find bugs, you write tests that automatically check your code. Unit tests check individual components. Integration tests check how components work together. pytest is your inspection toolkit.

🔧 pytest Example
Writing tests with pytest:

# test_calculator.py
def add(a, b):
  return a + b

def test_add():
  assert add(2, 3) == 5
  assert add(-1, 1) == 0
  assert add(0, 0) == 0

def test_add_negative():
  assert add(-5, -3) == -8

# Run with: pytest test_calculator.py

⚠️ Common Mistakes
❌
Not testing edge cases.
✔ Test boundary conditions, empty inputs, None values, and error cases, not just happy paths.
❌
Writing tests that are too coupled to implementation.
✔ Test behavior, not implementation. Tests should survive refactoring.
❌
Ignoring test failures.
✔ Fix failing tests immediately. They indicate real problems.
🎯 Interview Questions
Q
"What is unit testing?"
"Unit testing is the practice of testing individual functions or methods in isolation to ensure they work correctly. Each test verifies a specific behavior. Unit tests are fast, automated, and help catch bugs early. They serve as documentation and enable confident refactoring."
Q
"What is Test-Driven Development (TDD)?"
"TDD is a development approach where you write tests before writing code. The cycle: 1) Write a failing test (Red), 2) Write minimal code to pass (Green), 3) Refactor while keeping tests passing (Refactor). TDD leads to better design, higher test coverage, and more maintainable code."
