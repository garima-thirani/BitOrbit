🔧 Common Pitfalls & Solutions
Mutable default arguments:

# WRONG - mutable default
def add_item(item, list=[]):
  list.append(item)
  return list

# CORRECT - None default
def add_item(item, list=None):
  if list is None:
    list = []
  list.append(item)
  return list
🔧 Pythonic Code Examples
Writing Pythonic code:

# Unpacking
first, *middle, last = [1, 2, 3, 4, 5]

# Zip for parallel iteration
for name, age in zip(names, ages):
  print(f"{name}: {age}")

# Enumerate for index + value
for i, item in enumerate(items):
  print(f"{i}: {item}")

# Dictionary comprehension
squares = {x: x**2 for x in range(10)}

# Context manager
with open('file.txt') as f:
  data = f.read()
⚠️ Common Mistakes to Avoid
❌
Using mutable default arguments.
✔ Always use None as default for mutable arguments. Initialize inside function.
❌
Not using list comprehensions.
✔ List comprehensions are more Pythonic and often faster than map/filter.
❌
Ignoring PEP 8.
✔ Follow PEP 8 for consistent, readable code. Use tools like black, flake8.
❌
Overcomplicating code.
✔ Simple is better than complex. Readability counts. Don't use advanced features when simple ones work.
🎯 Final Interview Questions
Q
"What makes Python code 'Pythonic'?"
"Pythonic code follows Python's philosophy: simple, readable, explicit. Key principles: use list comprehensions instead of map/filter, use with statements for resources, embrace duck typing, follow PEP 8, use context managers, prefer built-in functions, write clear variable names. Pythonic code reads like pseudocode and is intuitive to other Python developers."
Q
"What's the most common Python mistake you've made?"
"Common mistakes include: mutable default arguments, not closing resources, mixing tabs and spaces, not using virtual environments, ignoring exceptions. The key is learning to use linters, write tests, and follow best practices. I always use 'with' for file handling, never use mutable defaults, and follow PEP 8 consistently."
