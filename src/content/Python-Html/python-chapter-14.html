📖 The Story — Phone Contacts
Names & Numbers

Your phone contacts are like a dictionary: names (keys) map to phone numbers (values). No duplicate names allowed.

Imagine your phone's contact list. Each contact has a unique name (the key) and a phone number (the value). You can quickly look up anyone by name. If you try to add the same name twice, the phone replaces the old number. Python dictionaries work exactly like this. They store data as key-value pairs and provide lightning-fast lookups.

🔧 Dictionary Methods
Common dictionary operations:

# Create
user = {"name": "Alice", "age": 22}

# Access
user["name"] # "Alice"
user.get("email", "N/A") # "N/A" (safe)

# Modify
user["age"] = 23 # Update
user["email"] = "a@b.com" # Add
del user["age"] # Remove

# Iterate
for key, value in user.items():
  print(key, value)
⚠️ Common Mistakes
❌
Using a list as a dictionary key.
✔ Keys must be immutable (strings, numbers, tuples). Lists cannot be keys because they can change.
❌
Accessing a key that doesn't exist without using .get().
✔ user["email"] raises KeyError if "email" doesn't exist. Use user.get("email", "N/A") for safe access.
❌
Confusing sets with lists.
✔ Sets are unordered and unique. Lists are ordered and allow duplicates. Use sets for membership testing and removing duplicates.
🎯 Interview Questions
Q
"What is the difference between a set and a list?"
"Sets are unordered collections of unique elements. Lists are ordered sequences that allow duplicates. Sets are faster for membership testing (O(1)) but don't maintain order. Use sets when you need uniqueness or fast lookups."
Q
"When would you use a dictionary?"
"Dictionaries are ideal when you need to map keys to values. They provide O(1) lookup time. Common uses: caching, counting frequencies, storing object properties, and any scenario where you need fast lookups by a unique identifier."
