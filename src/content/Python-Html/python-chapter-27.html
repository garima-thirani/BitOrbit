📖 The Story — Restaurant Kitchen
Multiple Tasks

A restaurant handles multiple orders simultaneously. Different tasks require different approaches.

Imagine a busy restaurant kitchen. The chef can cook multiple dishes at once by switching between tasks (concurrency). But for truly simultaneous cooking, you need multiple chefs (parallelism). Some tasks like waiting for water to boil (I/O-bound) can be interleaved efficiently. Other tasks like chopping vegetables (CPU-bound) need actual parallel processing. Python offers three approaches: threading (lightweight, shared memory), multiprocessing (separate memory, true parallelism), and asyncio (single-threaded event loop).

🔧 Threading Example
Using threading for I/O-bound tasks:

import threading
import time

def download_file(filename):
  print(f"Downloading {filename}...")
  time.sleep(2) # Simulate I/O
  print(f"Downloaded {filename}")

# Create threads
t1 = threading.Thread(target=download_file, args=("file1.txt",))
t2 = threading.Thread(target=download_file, args=("file2.txt",))

# Start threads
t1.start()
t2.start()

# Wait for completion
t1.join()
t2.join()
print("All downloads complete!")
🔧 AsyncIO Example
Using async/await:

import asyncio

async def download_file(filename):
  print(f"Downloading {filename}...")
  await asyncio.sleep(2) # Non-blocking sleep
  print(f"Downloaded {filename}")
  return f"{filename} complete"

async def main():
  # Run concurrently
  results = await asyncio.gather(
    download_file("file1.txt"),
    download_file("file2.txt")
  )
  print(results)

# Run
asyncio.run(main())
⚠️ Common Mistakes
❌
Using threading for CPU-bound tasks.
✔ Due to GIL, threading doesn't help CPU-bound tasks. Use multiprocessing instead.
❌
Not handling race conditions in threads.
✔ Use locks (threading.Lock) when multiple threads access shared data.
❌
Mixing async and blocking code.
✔ Don't call blocking functions in async functions. Use asyncio.run_in_executor() for blocking operations.
🎯 Interview Questions
Q
"What is the GIL and how does it affect threading?"
"The Global Interpreter Lock (GIL) is a mutex that allows only one thread to execute Python bytecode at a time. This means threading in CPython doesn't provide true parallelism for CPU-bound tasks. For I/O-bound tasks, the GIL is released during I/O operations, so threading still helps. For CPU-bound tasks, use multiprocessing."
Q
"When would you use threading vs multiprocessing vs asyncio?"
"Threading: I/O-bound tasks with shared state (e.g., web scraping, file I/O). Multiprocessing: CPU-bound tasks needing true parallelism (e.g., data processing, calculations). AsyncIO: High-concurrency I/O operations (e.g., web servers, APIs, many simultaneous connections)."
