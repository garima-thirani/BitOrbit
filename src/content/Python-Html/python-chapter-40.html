📖 The Story — Bakery
Parallel Work

One chef making bread, cake, cookies, and pizza is slow. Four chefs working simultaneously finish much faster. This is multiprocessing.

Imagine a bakery where one chef must make bread, cake, cookies, and pizza. Even with multiple hands, one chef can only work so fast. Now imagine hiring four chefs, each making one item simultaneously. The bakery finishes much faster. Multiprocessing works the same way. Instead of using multiple threads inside one process, Python creates multiple independent processes, each with its own Python interpreter and memory space.

🔧 Creating Process Example
Basic multiprocessing example:

from multiprocessing import Process
import time

def task(name):
  print(f"{name} started")
  time.sleep(2)
  print(f"{name} finished")

# Create processes
p1 = Process(target=task, args=("Process-1",))
p2 = Process(target=task, args=("Process-2",))

# Start processes
p1.start()
p2.start()

# Wait for completion
p1.join()
p2.join()
print("All processes completed")
🔧 Process Pool Example
Using ProcessPool for efficient task distribution:

from multiprocessing import Pool
import math

def square(x):
  return x * x

# Create pool with 4 worker processes
with Pool(4) as pool:
  # Map function to data
  results = pool.map(square, [1, 2, 3, 4, 5])

print(results)
# Output: [1, 4, 9, 16, 25]
🔧 Queue for IPC Example
Inter-process communication with Queue:

from multiprocessing import Process, Queue

def producer(q):
  q.put("Hello from producer")

def consumer(q):
  message = q.get()
  print(f"Received: {message}")

# Create queue
q = Queue()

# Create processes
p1 = Process(target=producer, args=(q,))
p2 = Process(target=consumer, args=(q,))

p1.start()
p2.start()
p1.join()
p2.join()
⚠️ Common Mistakes
❌
Using threads for CPU-intensive tasks.
✔ Due to GIL, use multiprocessing for CPU-bound work to achieve true parallelism.
❌
Forgetting if __name__ == "__main__" guard.
✔ On Windows, multiprocessing requires this guard to prevent infinite process creation.
❌
Creating too many processes.
✔ Use Pool() to reuse worker processes instead of creating new ones for each task.
❌
Assuming processes share variables.
✔ Each process has separate memory. Use Queue, Pipe, or Shared Memory for communication.
🎯 Interview Questions
Q
"What is multiprocessing and when should you use it?"
"Multiprocessing creates multiple independent processes, each with its own Python interpreter and memory space. Use it for CPU-intensive tasks like image processing, machine learning, or scientific computing. It bypasses the GIL, allowing true parallel execution on multiple CPU cores."
Q
"What is the difference between threading and multiprocessing?"
"Threading creates lightweight threads within a process that share memory, but is limited by the GIL for CPU-bound tasks. Multiprocessing creates separate processes with independent memory, bypassing the GIL for true parallelism. Threads are better for IO-bound tasks, processes for CPU-bound tasks."
