📖 The Story — Hotel Reception
Name Tags

A hotel receptionist doesn't store guests - they only track room numbers. Python variables work the same way - they store references, not the actual objects.

Imagine a hotel. The receptionist doesn't store people in drawers. Instead, they keep a registry: "Alice → Room 101, Bob → Room 102." The receptionist only knows where guests are, not the guests themselves. Python variables work exactly like this. When you write x = 100, the variable x doesn't contain the number 100. It only stores a reference (like a room number) pointing to where the actual object lives in memory.

🔧 References Example
Understanding Python references:

# Variables store references, not values
x = 100
y = x # y references same object as x

print(id(x)) # Memory address
print(id(y)) # Same address!
print(x is y) # True - same object

# Changing assignment
x = 200
print(id(x)) # Different address
print(id(y)) # Still points to 100
🔧 Mutable vs Immutable
Understanding mutability:

# Immutable: int, float, str, tuple
x = 10
y = x
x = 20 # Creates NEW object
print(y) # Still 10

# Mutable: list, dict, set
list1 = [1, 2, 3]
list2 = list1 # Same reference!
list1.append(4)
print(list2) # [1, 2, 3, 4] - changed!
🔧 is vs ==
Identity vs Equality:

a = [1, 2, 3]
b = [1, 2, 3]
c = a

# == checks VALUES
print(a == b) # True (same values)
print(a == c) # True (same values)

# is checks IDENTITY
print(a is b) # False (different objects)
print(a is c) # True (same object)
⚠️ Common Mistakes
❌
Thinking variables store values directly.
✔ Variables store references to objects. The objects live in heap memory.
❌
Using is when you mean ==.
✔ Use == to compare values. Use is only for comparing with None or checking identity.
❌
Not understanding mutable object sharing.
✔ When you assign a list to another variable, both point to the same object. Use copy() if you need independence.
❌
Confusing stack and heap.
✔ Stack: references and function calls. Heap: actual objects. Variables live in stack, objects in heap.
🎯 Interview Questions
Q
"What is the difference between stack and heap memory?"
"Stack stores function calls and local references. It's fast but limited in size. Heap stores actual Python objects (lists, dicts, instances) and is much larger. Variables in the stack hold references to objects in the heap. When you assign a = b, you're copying the reference, not the object."
Q
"What is the difference between 'is' and '=='?"
"== compares values (equality), while 'is' compares identity (whether two variables reference the exact same object in memory). Use == for value comparison. Use 'is' mainly for comparing with None or when you specifically need to check if two variables point to the same object."
