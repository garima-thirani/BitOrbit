📖 The Story — Text Messages
Words & Characters

Text messages are made of characters. You can read, modify (in a new message), and format them in many ways.

Imagine sending text messages. Each message is made of characters (letters, numbers, symbols). You can make text uppercase, lowercase, split it into words, replace words, or combine multiple messages. Python strings work exactly like this. They are immutable sequences of characters with powerful built-in methods for manipulation.

🔧 String Formatting
f-strings (Python 3.6+) — Recommended:
name = "Alice"
age = 22
msg = f"{name} is {age} years old"

With expressions:
f"2 + 2 = {2 + 2}" → "2 + 2 = 4"

Old style (%):
"%s is %d years old" % (name, age)

.format() method:
"{} is {} years old".format(name, age)
⚠️ Common Mistakes
❌
Trying to modify a string directly.
✔ Strings are immutable. s[0] = "H" raises TypeError. Use s = "H" + s[1:] to create a new string.
❌
Forgetting that strings are indexed from 0.
✔ s[0] is the first character, not s[1]. Negative indices count from the end: s[-1] is the last character.
❌
Using + to join many strings in a loop.
✔ Strings are immutable, so + creates new strings each time. Use "".join() for better performance.
🎯 Interview Questions
Q
"Are strings mutable or immutable in Python?"
"Strings are immutable in Python. Once created, you cannot change them. Any operation that appears to modify a string actually creates a new string. This makes strings thread-safe and allows Python to optimize memory usage."
Q
"What is string slicing?"
"String slicing extracts a portion of a string using the syntax string[start:stop:step]. The start index is inclusive, stop is exclusive, and step determines the interval. Examples: s[0:5] gets first 5 characters, s[::-1] reverses the string."
Q
"What are f-strings and why are they preferred?"
"f-strings (formatted string literals) are a Python 3.6+ feature for string formatting. They're prefixed with 'f' and allow expressions in curly braces: f'Hello {name}'. They're faster, more readable, and less error-prone than % formatting or .format()."
