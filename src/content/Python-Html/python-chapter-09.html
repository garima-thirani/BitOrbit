📖 The Story — Online Food Ordering
Defaults and Options

You order a pizza. You must specify the size, but cheese and toppings are optional with defaults.

Imagine ordering food online. The app asks for: Pizza Size (required), Cheese (default: Yes), Extra Sauce (default: No), Toppings (optional). You don't have to provide every detail—the system uses defaults for anything you don't specify. Python functions support the same flexibility through default parameters, making them easier to use in most cases while still allowing customization when needed.

⚠️ Common Mistakes
❌
Placing default parameters before required parameters.
✔ def greet(age, name="Guest"): — defaults must come after required parameters.
❌
Using mutable objects as default parameters.
✔ Defaults are evaluated once. Use None and create a new object inside the function: def add(item, items=None):
❌
Mixing positional and keyword arguments incorrectly.
✔ All positional arguments must come before keyword arguments: func("Alice", age=22) ✅ not func(age=22, "Alice") ❌
🎯 Interview Questions
Q
"What is the difference between *args and **kwargs?"
"*args collects extra positional arguments into a tuple. **kwargs collects extra keyword arguments into a dictionary. *args is used when you don't know how many positional arguments will be passed, while **kwargs is used for named arguments."
Q
"Why should mutable objects not be used as default parameters?"
"Default parameter values are evaluated only once when the function is defined. If a mutable object (like a list) is modified, changes persist across future function calls. Use None and create a new object inside the function instead."
