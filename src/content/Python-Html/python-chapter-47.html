📖 The Story — Detective
Investigation

A detective investigates a crime scene by collecting clues, analyzing evidence, and identifying the culprit. Debugging works the same way - systematically investigating bugs.

Imagine a detective solving a mystery. They don't immediately know who committed the crime. Instead, they collect clues, interview witnesses, analyze evidence, and piece together what happened. Debugging works exactly the same way. When your program behaves unexpectedly, you systematically investigate: read error messages, examine variable values, trace execution flow, and identify the root cause.

🔧 Print Debugging Example
Simple debugging with print:

def calculate_average(numbers):
  print(f"Input: {numbers}") # Debug
  total = sum(numbers)
  print(f"Total: {total}") # Debug
  count = len(numbers)
  print(f"Count: {count}") # Debug
  average = total / count
  print(f"Average: {average}") # Debug
  return average

# Simple but effective for quick debugging
🔧 pdb Debugger Example
Interactive debugging with pdb:

import pdb

def buggy_function(x, y):
  pdb.set_trace() # Breakpoint
  result = x + y
  pdb.set_trace() # Another breakpoint
  return result * 2

# When execution stops at breakpoint:
# (pdb) p x # Print variable x
# (pdb) p y # Print variable y
# (pdb) n # Next line
# (pdb) c # Continue
# (pdb) q # Quit
🔧 Logging Example
Professional logging:

import logging

# Configure logging
logging.basicConfig(
  level=logging.INFO,
  format='%(asctime)s - %(levelname)s - %(message)s',
  filename='app.log'
)

def process_data(data):
  logging.info(f"Processing {len(data)} items")
  try:
    result = sum(data) / len(data)
    logging.info(f"Result: {result}")
    return result
  except Exception as e:
    logging.error(f"Error: {e}")
    raise
🔧 Assertions Example
Using assertions for validation:

def divide(a, b):
  # Validate inputs
  assert isinstance(a, (int, float)), "a must be numeric"
  assert isinstance(b, (int, float)), "b must be numeric"
  assert b != 0, "Cannot divide by zero"
  
  return a / b

# Assertions catch programming errors early
# They can be disabled with python -O
⚠️ Common Mistakes
❌
Using print() for everything.
✔ Use logging for production code. Print is fine for quick debugging but lacks levels, timestamps, and file output.
❌
Not reading tracebacks carefully.
✔ Read the last line first - it tells you the error. Then trace up to find where it happened.
❌
Using assertions for user input validation.
✔ Assertions are for catching programmer errors, not validating user input. Use proper error handling for user input.
❌
Debugging in production.
✔ Use logging, not pdb, in production. pdb halts execution and shouldn't be left in code.
🎯 Interview Questions
Q
"How do you debug a Python program?"
"I follow a systematic approach: 1) Read the error message and traceback carefully. 2) Use print statements or logging to inspect variable values. 3) Use pdb for interactive debugging - set breakpoints, step through code, inspect state. 4) Check recent changes. 5) Write a minimal reproduction. 6) Fix and verify. For production, I use structured logging with different severity levels."
Q
"What's the difference between logging and print?"
"Print is simple output to stdout. Logging provides: severity levels (DEBUG, INFO, WARNING, ERROR), timestamps, formatting, output to files, configurable verbosity, and better performance. Logging is production-ready. Print is for quick debugging. Professional applications always use logging."
