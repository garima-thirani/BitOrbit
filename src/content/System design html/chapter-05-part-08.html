📋 Quick Revision Notes

Cache Fundamentals

Caches store frequently accessed data in fast memory (RAM) to avoid slower database queries. Benefits: Lower latency, reduced database load, better user experience. Key metrics: Cache hit rate, cache miss rate. Cache = Copy, Not Truth.

Caching Patterns

Cache-Aside: App manages cache (most common). Read-Through: Cache loads missing data. Write-Through: Update cache + DB together. Write-Behind: Cache now, DB later (async). Choose based on consistency needs and write patterns.

Cache Eviction Policies

LRU: Remove least recently used (general purpose). LFU: Remove least frequently used (popularity-based). FIFO: Remove oldest (simple). TTL: Time-based expiry. Right policy improves hit rates without increasing cache size.

Cache Stampede Prevention

When popular cache entries expire simultaneously, thousands of requests can overwhelm the database. Prevention: Locking (only one rebuilds), Jitter (randomize TTL), Never Expire (background refresh), Probabilistic Early Expiration (refresh popular items proactively).

Cache Invalidation

TTL-Based: Automatic expiry (simple, eventual consistency). Event-Based: Invalidate on data change (strong consistency). Write-Through: Update cache + DB together. Write-Behind: Async DB update. Choose based on freshness requirements.

When NOT to Cache

Avoid caching: Frequently changing data (stock prices), Highly sensitive data (passwords), Rarely accessed data (yearly reports), Data requiring strong consistency (banking), Cheap-to-compute data (simple lookups). Don't cache: Sensitive, volatile, rare, or cheap-to-compute data.

💡 Flashcards
Q: What is a cache hit?
A: Requested data is found in cache, avoiding a database query
Cache hits are fast. Cache misses require fetching from the slower database.
Q: Which caching pattern is most common?
A: Cache-Aside — application manages the cache
Cache-Aside is simple and gives the application full control over caching logic.
Q: What is a cache stampede?
A: Many simultaneous requests miss an expired cache entry and overwhelm the database
Prevent with locking, jitter, or never-expire strategies.

🧪 Final Quiz
1. Which caching pattern provides the highest write throughput with eventual consistency?
A) Cache-Aside
B) Write-Through
C) Read-Through
D) Write-Behind — writes go to cache first, async flush to DB
Write-Behind provides the highest write throughput by buffering writes in cache and flushing asynchronously to the database.
2. A product page cached for 1 hour expires. 50,000 users request it simultaneously. What's the best prevention strategy?
A) Increase the TTL
B) Use locking — only one request rebuilds the cache, others wait
C) Add more database servers
D) Disable caching
Locking ensures only one request hits the database to rebuild the cache. All other requests use the rebuilt cache.
