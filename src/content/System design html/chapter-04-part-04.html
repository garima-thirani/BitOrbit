📖 The Story — The Popular Library
Why Read Replicas Exist

Create multiple copies so many readers can read simultaneously.

Imagine a library with a single copy of a bestselling book. Thousands of readers want to borrow it. Only one person can read it at a time. The solution? Create multiple copies of the same book. Now many readers can read simultaneously while the original master copy remains safe. Read replicas work exactly the same way.

📐 What is a Read Replica?
Read Replica: A copy of the primary database that continuously receives updates from the primary but serves only read requests. Applications never write directly to replicas.
🔄 Read Routing

Applications determine where queries should go:

SELECT → Replica INSERT → Primary UPDATE → Primary DELETE → Primary

This routing can happen in: Application code, Database proxy, Service mesh, ORM configuration.

⚖ Replica Load Balancing
Read Router distributes read traffic across replicas using Round Robin, Least Connections, or Weighted Routing.
⏱ Read-After-Write Consistency
The Stale Read Problem

User updates profile, then immediately sees old value.

Consider this sequence: 1) User updates profile. 2) Update reaches Primary. 3) User refreshes page. 4) Request goes to Replica. 5) Replica has not caught up. The user sees stale data. This is a common production issue.

🔄 Strategies to Handle Stale Reads
📖 Read from Primary Temporarily
After a write, route next few reads to primary. Useful for profile updates, settings, payment confirmation.
📌 Sticky Reads
Temporarily pin user's reads to primary until replication catches up.
⏱ Accept Eventual Consistency
For non-critical data: like counts, product views, analytics. Small delays acceptable.
📊 Reporting Databases

Large reporting queries should not impact production traffic. Instead: Primary → Replica → Analytics Queries. Examples: Daily sales reports, Dashboard generation, BI tools. Production latency remains low.

📈 Scaling Example

Without replicas: 20,000 Reads → Primary. With four replicas: 20,000 Reads → Read Router → 5,000 per Replica. The primary focuses on writes.

🏭 Production Example
Real World

Streaming Platform Architecture

A streaming platform stores user accounts, watch history, and preferences. Writes: viewing progress, new subscriptions. Reads: homepage, recommendations, search results. Homepage requests are served from replicas while subscription updates go to the primary.

🎯 Interview Callout
Q
"Can read replicas increase write capacity?"
"No. Replicas only help distribute read traffic. All writes still go through the primary unless another replication strategy such as multi-leader replication is used."
