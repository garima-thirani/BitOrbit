📖 The Story — Adding One More Server
The Rebalancing Problem

Your database uses 4 servers with hash(userId) % 4. Traffic doubles. You add one more server. Now every piece of data must be redistributed. Millions of records move across the network. One server caused an entire cluster to rebalance.

This is the problem with traditional modulo hashing. Consistent Hashing was invented to solve this exact problem. When servers change, only a small amount of data moves. The rest remains untouched. This makes cloud-native scaling possible.

🎯 What is Consistent Hashing?
Consistent Hashing: A technique where both servers and keys are placed on a circular hash ring. Keys are assigned to the next server clockwise. When a server joins or leaves, only nearby keys move. Everything else stays unchanged.

✅ Virtual Nodes (vNodes)
Virtual Nodes: Instead of one position per server, each server appears multiple times on the ring. This improves load balancing, reduces hotspots, and makes rebalancing smaller. Modern systems use dozens or hundreds of vNodes per physical server.
🔄 How Data Movement Works
Example: Server D is added between Server B and Server C. Only keys between B and D move to D. All other keys stay with their current servers. Instead of moving 80% of data (modulo hashing), only ~20% moves (consistent hashing).
🏭 Production Examples
Real World

Cassandra, DynamoDB & Redis Cluster

Apache Cassandra: Uses consistent hashing with virtual nodes. Each physical node has multiple vNodes for better load distribution. Automatic scaling with minimal data movement.

Amazon DynamoDB: Uses consistent hashing to partition data across storage nodes. Adding nodes triggers minimal data movement.

Redis Cluster: Uses hash slots (similar concept) to distribute keys across nodes.

🎯 Interview Callout
Q
"Why is consistent hashing better than modulo hashing?"
"Consistent hashing minimizes data movement when the cluster changes. With modulo hashing, adding one server requires redistributing almost all keys. With consistent hashing, only keys near the new/removed server move. This makes cloud-native scaling feasible."
🧠 Memory Trick
Ring → Servers → Keys → Clockwise → Virtual Nodes → Minimal Movement. Consistent hashing enables elastic scaling.
