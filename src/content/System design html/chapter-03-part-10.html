📋 Quick Revision Notes

RDBMS vs NoSQL

RDBMS

Structured schema, SQL, ACID transactions, Strong consistency. Best for financial and transactional systems.

NoSQL

Flexible schema, Horizontal scalability, High write throughput, Often follows BASE principles. Best for large-scale distributed workloads.

ACID Properties

Atomicity
All or Nothing — transaction completes fully or rolls back completely
Consistency
Valid State — database moves from one valid state to another
Isolation
No Interference — concurrent transactions don't interfere
Durability
Survives Crash — committed data persists even after failure

BASE Model

Basically Available — system continues serving during failures. Soft State — data may differ between replicas temporarily. Eventual Consistency — all replicas converge over time. Used when availability and scalability are more important than immediate consistency.

CAP Theorem

During a network partition, choose between Consistency and Availability. Partition Tolerance is assumed in distributed systems. The real choice is CP vs AP.

PACELC Theorem

If Partition: Choose Availability or Consistency. Else: Choose Latency or Consistency. PACELC extends CAP by explaining trade-offs during normal operation.

Database Indexing

B-Tree
General purpose — range queries, sorting, equality
Hash
Equality lookups only — fast but no ordering
Composite
Multi-column — leftmost prefix rule applies
Indexes improve reads. Indexes slow writes.

💡 Flashcards
Q: Difference between sharding and replication?
A: Sharding distributes data. Replication copies data.
Replication keeps copies for redundancy. Sharding splits data for horizontal scaling.
Q: When should you choose an RDBMS?
A: When strong consistency, transactions, and relationships are important.
RDBMS excels at ACID transactions and complex relationships via JOINs.
Q: What causes the N+1 query problem?
A: One parent query followed by one query for every child record.
Solution: Use JOINs or batch loading via DataLoader pattern.

🚨 Common Mistakes
❌ Choosing DB Based on Popularity
Choose based on requirements, not trends
❌ Ignoring Access Patterns
Your queries determine the optimal schema and indexes
❌ Indexing Every Column
Indexes slow writes — be selective
❌ Confusing ACID Consistency with CAP Consistency
They are different concepts entirely
❌ Optimizing Before Measuring
Always measure first — the bottleneck may surprise you
🧪 Final Quiz
1. A social media app needs user profiles (structured), posts (flexible schema), and friend relationships (graph). What database strategy?
A) Use PostgreSQL for everything
B) Polyglot persistence — RDBMS for profiles, document DB for posts, graph DB for relationships
C) Use MongoDB for everything
D) Use only NoSQL databases
Different data models benefit from different database types. Polyglot persistence chooses the best tool for each job.
2. Your e-commerce site is slow during checkout. CPU (35%), Memory (healthy), Disk (low). Thousands of transactions wait on the same inventory row. What's the bottleneck?
A) Missing indexes
B) Lock contention — many transactions waiting on the same row
C) Need more RAM
D) Network bandwidth
When CPU, memory, and disk are healthy but transactions are slow, lock contention is a likely cause — especially during flash sales.
