📖 The Story — The Single Library
Why Clustering Exists

One librarian can only handle so many books.

Imagine a library with one librarian who knows where every book is. As the collection grows to millions of books, one person cannot manage it all. The solution? Split the library into sections, each managed by a different librarian. Now they can handle more books and serve more readers simultaneously. Redis Cluster works the same way.

🎯 Why Redis Cluster?

A single Redis instance is limited by: Memory (cannot exceed RAM), Throughput (single CPU core), Network (single NIC). Redis Cluster solves this by: Distributing data across multiple nodes, Enabling horizontal scaling, Providing high availability through replication.

Key Insight: Redis Cluster allows you to scale Redis like a distributed system, not just a single server.
📐 What is Redis Cluster?
Redis Cluster: A distributed implementation of Redis that automatically shards data across multiple nodes. Each node manages a subset of the data. The cluster appears as a single Redis instance to clients.
🏛 Cluster Architecture
Redis Cluster: Masters handle writes, replicas provide high availability and read scaling.
🔑 Key Concepts
🎯 Master Node
Handles reads and writes for its shard
📖 Replica Node
Read-only copy of master. Promotes to master if master fails
🗺 Hash Slots
16,384 slots distributed across masters. Keys map to slots
🔀 Sharding
Data automatically distributed based on key hash
📊 Redis Data Structures

Redis is not just a key-value store. It supports rich data structures:

📝 String
Basic key-value. Max 512MB. Use for: caching, counters
📋 Hash
Field-value pairs. Use for: user profiles, objects
📑 List
Ordered collection. Use for: queues, timelines
📚 Set
Unordered unique values. Use for: tags, relationships
⭐ Sorted Set
Scored elements. Use for: leaderboards, rankings
🧮 Bitmap
Bit-level operations. Use for: flags, analytics
⚡ When to Use Each Structure
