📖 The Story — The Missing Money
Bank Account Mystery

Balance shows ₹42,000. Where did ₹8,000 go?

Customer calls bank support: "Yesterday my account had ₹50,000. Today it has ₹42,000. Where did my money go?" You open the database. It shows only: Balance = ₹42,000. No explanation. No history. No timeline. The current state exists, but the journey is lost. Now imagine Event Sourcing. Instead of storing balance, you store: Account Created, Salary Credited ₹50,000, Electricity Bill ₹2,000, ATM Withdrawal ₹5,000, Online Purchase ₹1,000. Now anyone can answer how the balance became ₹42,000. The history itself becomes the database.

🎯 What is Event Sourcing?
Event Sourcing: Store every state change as an immutable event. Current state is computed by replaying events. Complete audit trail built-in.

🔄 Event Store Architecture
Traditional: UPDATE accounts SET balance = 42000 Event Sourcing: APPEND: Account Created APPEND: Salary Credited 50000 APPEND: Electricity Bill -2000 APPEND: ATM Withdrawal -5000 APPEND: Online Purchase -1000 Current Balance = Sum of all events
📦 Event Store Schema
Event: { "eventId": "evt_123", "aggregateId": "account_456", "eventType": "MoneyDeposited", "timestamp": "2026-07-01T12:00:00Z", "version": 1, "payload": { "amount": 5000, "currency": "INR" } }
🔄 Rebuilding State (Replay)
Event Store ↓ Replay All Events ↓ Current State Computed Example: Start: 0 + Deposit 5000 = 5000 - Withdraw 2000 = 3000 + Deposit 4600 = 7600 = Current Balance: ₹7,600
📸 Snapshots
Snapshot: Periodic checkpoint of current state to avoid replaying thousands of events. Recovery starts from latest snapshot + remaining events.
Without Snapshot: Replay 1,000,000 events → Slow! With Snapshot: Start at Snapshot (event 1000) Replay remaining 900,000 events → Much faster!

🎯 Interview Callout
Q
"What's the difference between Event Sourcing and Kafka?"
"Kafka is designed for event streaming and message distribution with temporary retention. Event Sourcing uses an Event Store as the authoritative source of business history with permanent retention, aggregate streams, optimistic concurrency, and built-in replay for state reconstruction. Many systems use both: Event Store for source of truth, Kafka for distribution."
🧠 Memory Trick
Command → Event → Append → Event Store → Replay → Current State. History creates state, not the other way around.
