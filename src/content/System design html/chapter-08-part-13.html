📋 Master Cheat Sheet - Core Concepts

🎯 Event Types

  • Domain Event: Internal, free to evolve
  • Integration Event: Public, stable contract
  • Event: Something that happened
  • Command: User intent

🔄 Event Flow

  • Event Storming: Business discovery
  • Broker: Decouples producers/consumers
  • Bus: Communication pattern
  • Mesh: Global multi-region

📊 Schema Evolution

  • Backward: New consumer reads old
  • Forward: Old consumer reads new
  • Full: Both directions work
  • Registry: Schema governance

⏱️ Ordering

  • Lamport: Logical time, causal order
  • Vector: Detects concurrency
  • Partition Key: Business ID for ordering
  • Kafka: Guarantees per-partition

📐 Architecture Patterns

  • CQRS: Separate reads/writes
  • Event Sourcing: Store history
  • Projection: Event → Read Model
  • Replay: Rebuild from events

🏭 Production

  • DLQ: Failed events
  • Lag: Consumer backlog
  • Tracing: Correlation ID
  • Monitoring: Metrics + Alerts

🎯 Top Interview Questions

Q1: Domain vs Integration Events?

Domain events are internal, free to evolve. Integration events are public contracts, must remain stable. Use Translation Layer between them.

Q2: Why Event Storming first?

Identifies business workflows and boundaries before implementation. Prevents designing microservices around technical layers instead of business capabilities.

Q3: Schema evolution with 200 consumers?

Add optional fields with defaults. Register new schema version. Deploy consumers first, then producers. Monitor validation errors before deprecating old versions.

Q4: Kafka ordering guarantee?

Guaranteed only within single partition. Use business identifiers (Order ID, Conversation ID) as partition keys to maintain ordering for related events.

Q5: CQRS vs Event Sourcing?

CQRS separates reads from writes. Event Sourcing stores history instead of state. They complement each other: Event Sourcing provides the event log, CQRS builds optimized read models.

Q6: Analytics database deleted?

Redeploy projection service with replay mode. Replay historical events from Event Store/Kafka. Rebuild analytics database. Validate correctness. Return to normal operation.

Q7: Poison message blocking queue?

Implement DLQ after max retries. Use exponential backoff + jitter. Monitor DLQ size. Operations team investigates. Replay valid events after resolution.
