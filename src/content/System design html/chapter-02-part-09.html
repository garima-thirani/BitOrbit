Designing Dropbox

Cloud File Storage HLD

Design a cloud storage system similar to Dropbox where users can upload files, download files, synchronize files across devices, and share files using links. The service should support millions of users and large files.

Requirements

✅ Functional

User authentication, File upload/download, File synchronization, Folder management, Shareable links, File version history (optional).

📊 Non-Functional

High availability, Durable storage, Low download latency, Horizontal scalability, Secure file access.

Capacity Estimation

Assumptions: 20 million DAU, average file uploaded/day = 50 MB, total uploads/day ≈ 1 PB. Read traffic is much higher than write traffic. Key insight: Storage dominates infrastructure cost. Metadata is much smaller than file content.

High-Level Architecture
Dropbox HLD: API servers handle metadata, upload service streams to object storage, queue handles background processing.
Key Architectural Decisions
🧱 Block-Level Sync
Files are split into 4MB blocks. Only changed blocks are uploaded — not entire files. Massive bandwidth savings.
🔍 Content Hashing
Each block is identified by its SHA-256 hash. Identical blocks across users are stored only once (deduplication).
💻 LAN Sync
When multiple devices are on the same network, files sync locally instead of through the cloud. Much faster.
📦 Compression
Blocks are compressed before transfer. Reduces storage and bandwidth by up to 50%.
Memory Trick
Metadata is small. Files are huge. Treat them differently. Never store large binary files inside the relational database.
