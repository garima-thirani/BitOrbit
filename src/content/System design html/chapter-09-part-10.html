📖 The Story — The Internal API Attack
Front Door Locked, Rooms Open

Company secures API Gateway perfectly. Internet → Gateway → Microservices. Everything looks safe. But attacker gains access to one compromised container. From inside the cluster, they can call Payment Service, Inventory Service, Customer Service freely. Internal communication was never secured. Company protected front door but left every room inside unlocked.

Monolith has very few communication paths: Application → Database. Microservices have hundreds of APIs and thousands of network calls. Every connection must be trusted. Security becomes much harder. This is why modern microservices use Zero Trust: verify every request, every service, every hop.

🎯 Authentication vs Authorization
Authentication (Who are you?): Verifies identity. Example: User logs in with password, system verifies it's Alice.

Authorization (What can you do?): Verifies permissions. Example: Alice can view orders but cannot refund orders.

Authentication happens first, then authorization. Both are mandatory in every microservice.

📊 JWT (JSON Web Token)

How JWT Works

User logs in ↓ Server validates credentials ↓ Creates JWT (3 parts): 1. Header (algorithm) 2. Payload (user info, expiry) 3. Signature (verification) ↓ Client stores JWT ↓ Every request includes JWT ↓ Server verifies signature Stateless. No session storage needed.

JWT Payload Example

{ "sub":"12345", // User ID "name":"Alice", "role":"customer", "exp":1712345678 // Expiry } Never store passwords in JWT!
🔄 OAuth2 & OpenID Connect
OAuth2: Authorization framework allowing apps to access resources on behalf of users. Example: "Login with Google" - password never reaches your app. Google provides access token.

OpenID Connect (OIDC): Adds authentication to OAuth2. Provides identity information (name, email) in ID Token. OAuth2 = authorization, OIDC = authentication + authorization.
✅ mTLS (Mutual TLS)
mTLS: Normal TLS secures server only. mTLS secures both sides. Both client and server present certificates. Example: Orders Service calls Payments Service. Both verify each other's certificates. Prevents unauthorized services from impersonating trusted services. Essential for service-to-service communication in Zero Trust architecture.
🔄 Zero Trust Architecture
Zero Trust: Old assumption: "Inside network = trusted". Modern assumption: "Trust nothing, verify everything". Every user, service, and request must authenticate and authorize itself, regardless of location. Every network hop performs verification. No implicit trust. This philosophy prevents lateral movement attacks.

🏭 Production Example
Real World

Amazon Security Stack

Customer logs in with OAuth2 + OIDC → receives short-lived JWT → API Gateway validates JWT → Internal services communicate with mTLS → Every service has unique identity → Secrets stored in Vault with automatic rotation → RBAC governs permissions → All traffic encrypted in transit and at rest → Every request logged and audited. Zero Trust everywhere.

🎯 Interview Callout
Q
"How do you secure microservices?"
"Use OAuth2 + OIDC for user authentication with short-lived JWTs. Validate tokens at API Gateway. Use mTLS for service-to-service authentication. Store secrets in Vault with automatic rotation. Apply RBAC for authorization. Encrypt all data in transit and at rest. Follow Zero Trust: verify every request, every service, every hop. Never trust internal traffic."

Users → OAuth2/JWT → Gateway → mTLS → Services → Vault → Zero Trust. Security at every layer, every hop, every request.
