📖 The Story — Amazon's Order Service
When Internal Events Leak

Exposing implementation details breaks everything.

A customer places an order. Order Service performs dozens of internal operations: Validate Coupon, Calculate Tax, Reserve Order Number, Update Inventory Cache, Persist Database, Generate Audit Log, Create Shipment, Notify Analytics. Question: Should every internal step become a Kafka event? Absolutely not. Imagine exposing CouponValidated, InventoryCacheUpdated, TemporaryDiscountApplied, OrderChecksumGenerated. Six months later, the Order team changes an internal algorithm. Suddenly Analytics breaks. Fraud breaks. Recommendations breaks. Shipping breaks. They accidentally exposed their internal implementation. This is why we distinguish between Domain Events and Integration Events.

🏭 Production Examples
Real World

Amazon, Uber, Netflix

Amazon: Internal events like TaxCalculated, CouponApplied never exposed. Only OrderCreated, PaymentCompleted, ShipmentDelivered are public.

Uber: Internal events like DriverMatched, RouteCalculated, PricingComputed stay private. Only RideStarted, RideCompleted are public.

Netflix: Internal events like BufferFilled, DecoderReady, ManifestLoaded never published. Only PlaybackStarted, PlaybackEnded are public.

🎯 Interview Callout
Q
"Why shouldn't every Domain Event be published?"
"Publishing every Domain Event exposes internal implementation details and creates tight coupling. Other services may depend on events never intended as public contracts, making future refactoring difficult. Only publish stable Integration Events that represent meaningful business milestones."
🧠 Memory Trick
Inside Service → Domain Event → Translate → Integration Event → Outside World. Keep internals private.
