📖 Problem Statement
Design Challenge

Design the backend database for a local delivery platform.

Design the backend database for a local delivery platform where users can: Browse restaurants and stores, Search for food or products, Place orders, Track delivery partners, Make payments, View order history. The platform should support millions of users and thousands of concurrent orders.

📋 Requirements

✅ Functional

Customer registration, Restaurant onboarding, Menu management, Product search, Cart management, Order placement, Payment processing, Delivery partner assignment, Live order tracking, Ratings & reviews

📊 Non-Functional

Highly available, Fault tolerant, Horizontally scalable, Low latency, Durable, Secure, Able to process large traffic spikes during meal times

🗄 Core Entities
Customer, Restaurant, Menu Item, Cart, Order, Payment, Delivery Partner, Location, Review
📐 Relational Schema
Customers(customer_id PK, name, phone, email) Restaurants(restaurant_id PK, name, address, rating) Menu_Items(item_id PK, restaurant_id FK, name, price, category) Orders(order_id PK, customer_id FK, restaurant_id FK, status, total_price, created_at) Order_Items(order_item_id PK, order_id FK, item_id FK, quantity) Payments(payment_id PK, order_id FK, status, amount) Delivery_Partners(partner_id PK, name, vehicle, status) Reviews(review_id PK, customer_id FK, restaurant_id FK, rating, comment)
🔷 Why SQL for Core Data?
Core transactional data requires ACID guarantees, foreign keys, referential integrity, and complex joins. Orders, Payments, Customers, and Restaurants are best served by a relational database like PostgreSQL.
⚡ Where NoSQL Fits

📍 Live Driver Locations

Frequent location updates are better suited to a distributed NoSQL store or an in-memory data store like Redis.

🔍 Search

Restaurant and menu search is often powered by a dedicated search engine (Elasticsearch/OpenSearch) rather than the primary database.

🎯 Interview Walkthrough

A strong interview answer:

1️⃣ Clarify requirements
Understand the business problem
2️⃣ Identify entities
List core objects and their relationships
3️⃣ Design schema
Create tables with proper keys
4️⃣ Define relationships
Foreign keys, one-to-many, many-to-many
5️⃣ Explain indexes
Match indexes to access patterns
6️⃣ SQL vs NoSQL
Choose the right tool for each workload
7️⃣ Add caching
Redis for frequently accessed data
8️⃣ Discuss scaling
Replicas, sharding, partitioning
9️⃣ Identify bottlenecks
Hot restaurants, payment spikes
🔟 Explain trade-offs
Why this design? What did we sacrifice?
