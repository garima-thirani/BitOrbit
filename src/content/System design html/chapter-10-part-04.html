📖 The Story — The Datacenter Fire
Why Replication Matters

Amazon stores all orders in one database server in Virginia. One day, the entire datacenter loses power. Millions of customers cannot place orders. Years of business stop instantly.

Amazon's solution is not a bigger server. It is Replication. By maintaining multiple copies of data across different servers and regions, Amazon ensures that if one datacenter fails, others continue serving traffic. Replication provides high availability, fault tolerance, disaster recovery, and faster reads for geographically distributed users.

🎯 What is Replication?
Replication: Maintaining multiple copies of the same data across different servers or locations. Instead of one database, we have many: Primary, Replica 1, Replica 2, Replica 3. If one fails, others continue.

🔄 Synchronous vs Asynchronous Replication
Synchronous: Leader waits for followers to confirm before returning success. Strong consistency, higher latency. Asynchronous: Leader returns success immediately, followers replicate later. Lower latency, possible data loss. Semi-Synchronous: Leader waits for at least one follower. Best of both worlds.
✅ Read Replicas & Replica Lag
Read Replicas: Followers that handle read traffic, reducing load on the leader. Replica Lag: Delay between leader update and follower update. During this time, followers contain stale data. Monitor replica lag continuously.
🏭 Production Examples
Real World

MySQL & PostgreSQL

MySQL: Uses Leader-Follower replication. Primary handles writes, read replicas handle queries. Asynchronous replication by default, semi-synchronous available.

PostgreSQL: Streaming replication with automatic failover. Standby servers can be promoted to primary if the leader fails.

🎯 Interview Callout
Q
"What's the difference between synchronous and asynchronous replication?"
"Synchronous replication waits for replicas to acknowledge before returning success, providing stronger consistency at the cost of higher latency. Asynchronous replication returns success immediately after the leader commits, offering better performance but allowing temporary replica lag and possible data loss during failures."
🧠 Memory Trick
Leader writes, followers replicate. Sync = wait, Async = fast. Read replicas scale reads, not writes. Monitor replica lag.
