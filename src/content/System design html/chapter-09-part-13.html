🎯 Top 20 Interview Questions

Fundamentals

Q1: Why microservices over monolith?
Team scaling, independent deployment, fault isolation, technology diversity.

Q2: What is Conway's Law?
Architecture mirrors organization structure. Independent teams build independent services.

Q3: How to identify service boundaries?
Business capabilities, DDD bounded contexts, independent scaling, separate teams.

Q4: Database per Service - why?
Independent schema evolution, deployment, scaling. No hidden coupling.

Q5: Shared database anti-pattern?
Tight coupling, schema conflicts, coordinated deployments, hidden dependencies.

Communication & Data

Q6: REST vs gRPC vs Kafka?
REST (public APIs, simple), gRPC (internal, fast), Kafka (events, async).

Q7: Synchronous vs Asynchronous?
Sync: user waits (payment). Async: user doesn't wait (analytics).

Q8: What is Saga pattern?
Local transactions with compensating actions. Replaces 2PC in microservices.

Q9: Eventual consistency?
Data becomes consistent eventually. Acceptable for distributed systems.

Q10: CQRS?
Separate read and write models. Optimize each independently.

Resilience & Operations

<Q11: Circuit Breaker?
Stop calling failing service. States: Closed → Open → Half-Open.

Q12: Why retries need backoff?
Prevent retry storms. Exponential backoff + jitter spreads traffic.

Q13: Service Discovery?
Dynamic service location. No hardcoded IPs. Registry-based.

Q14: API Gateway purpose?
Single entry point, auth, rate limiting, request aggregation.

Q15: Three observability pillars?
Logs (what), Metrics (where), Traces (why).

Security & Deployment

Q16: OAuth2 vs JWT?
OAuth2 (authorization framework), JWT (stateless token format).

Q17: mTLS?
Mutual TLS. Both client and server verify certificates.

Q18: Zero Trust?
Verify every request, every service, every hop. No implicit trust.

Q19: Docker vs Kubernetes?
Docker (containers), Kubernetes (orchestrates containers at scale).

Q20: Rolling update vs Canary?
Rolling (gradual replacement), Canary (test on small % first).

📊 Decision Trees

When to Use Microservices?

Small Team (< 10)? ↓ YES → Monolith NO → Independent Teams? ↓ YES → Different Scaling Needs? ↓ YES → Microservices NO → Modular Monolith

Communication Choice

User needs immediate response? ↓ YES → Public API? → REST NO → Internal API? → gRPC NO → Events/Async? → Kafka

Database Choice

Need ACID? → PostgreSQL Need Search? → Elasticsearch Need Cache? → Redis Need Analytics? → ClickHouse Need Massive Writes? → Cassandra

Deployment Strategy

Need zero downtime? ↓ YES → Rolling Update Need fast rollback? → Blue-Green Need progressive testing? → Canary
✅ Golden Rules
1. Design around business capabilities, not technical layers 2. Every service owns its data - never share databases 3. Keep services independently deployable 4. Prefer async communication where possible 5. Every external call needs timeout 6. Retries require backoff + jitter + circuit breaker 7. Every request needs Trace ID 8. Secure every service-to-service call 9. Automate everything (CI/CD) 10. Design for failure from day one 11. Make everything observable (Logs, Metrics, Traces) 12. Scale horizontally whenever possible 13. Measure before optimizing 14. Accept eventual consistency where appropriate 15. Build systems that evolve without stopping business
