📊 Decision Tree — Vertical vs Horizontal Scaling
Need More Capacity? → Fits On One Machine? → YES → Vertical Scaling. NO → Horizontal Scaling. Vertical: Bigger machine, simple, hardware limit. Horizontal: More machines, complex, nearly unlimited.
📊 Decision Tree — CP vs AP
Network Partition? → Need Correct Data? → YES → CP (Banking, Payments). Need Always Available? → YES → AP (Social Media, Analytics). Partition tolerance is mandatory in distributed systems.
📊 Decision Tree — Replication Strategy
Mostly Reads? → Leader-Follower. Global Writes? → Multi-Leader. Highest Availability? → Leaderless. Each strategy has different trade-offs for consistency, latency, and complexity.
📊 Decision Tree — Sharding Strategy
Need Range Queries? → Range Sharding. Need Even Distribution? → Hash Sharding. Need Flexible Placement? → Directory Sharding. Choose shard key carefully - changing it later is very expensive.
📊 Decision Tree — Consistency Model
Financial Data? → Strong. Messaging? → Causal. User Profile? → Read-after-Write. Social Feed? → Eventual. Use the weakest model that satisfies business requirements.
📊 Decision Tree — Deployment
Single Region Enough? → Multi-AZ. Global Users? → Multi-Region. Need Lowest Latency? → Active-Active. Disaster Recovery Only? → Active-Passive.

📋 Top 10 Engineering Principles
  1. Scale horizontally before vertically whenever possible.
  2. Replication improves availability; sharding improves capacity.
  3. Every distributed system must handle partitions.
  4. Use the weakest consistency model that satisfies business requirements.
  5. Consensus is for correctness, not speed.
  6. Keep data close to users.
  7. Cache aggressively, invalidate carefully.
  8. Test failures before they happen.
  9. Measure everything.
  10. Every architectural decision is a trade-off.
🎯 Interview Callout
Q
"Design a global distributed system from scratch."
"Start with requirements and traffic estimates. Choose horizontal scaling. Select CAP trade-off based on business needs. Design replication strategy (Leader-Follower for reads, Multi-Leader for global writes). Implement sharding with hash-based distribution. Use consistent hashing for dynamic scaling. Add Raft-based consensus for leader election. Deploy multi-region with Active-Active architecture. Implement disaster recovery with defined RPO/RTO. Add monitoring, caching, and autoscaling. Always discuss trade-offs."
