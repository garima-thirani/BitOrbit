📖 The Story — The Analytics Disaster
Netflix Saves the Day with Replay

12 hours of analytics lost. Replay restores everything in minutes.

Monday morning at Netflix. Developer deploys a bug. Instead of counting PlaybackStarted events correctly, analytics service ignores 12 hours of events. Executives see "0 Views" for half the day. Panic. Should engineers manually reconstruct everything? Fortunately, Netflix stores every event. They simply replay PlaybackStarted, PlaybackPaused, PlaybackCompleted into a corrected analytics service. Within minutes, every dashboard is restored. No users notice. This is the power of Event Replay.

🎯 What is Event Replay?
Event Replay: Process historical events again to rebuild projections, recover systems, populate new read models, or recompute analytics. Works because complete event history is preserved.

🔄 Replay Strategies

Strategy 1: Full Replay

Replay all events from beginning. Simple but slow for large datasets.

Strategy 2: From Snapshot

Start from latest snapshot + replay remaining events. Much faster.

Strategy 3: By Time Range

Replay only specific period (e.g., yesterday). Useful after small bugs.

Strategy 4: By Aggregate

Replay single entity (e.g., Order 1001). Only affected records.

⚠️ Replay Safety
Critical Rule: Replay should rebuild data, NOT repeat business actions. Disable emails, SMS, payments, and third-party APIs during replay.
✅ Safe Replay: Replay → Projection → Database ❌ Dangerous Replay: Replay → Email → SMS → Payment (Users get duplicate notifications!)
🏭 Production Examples
Real World

Amazon, Netflix, Uber

Amazon: Recommendation algorithm bug? Replay OrderCreated events → Recommendation Projection → Recommendations fixed.

Netflix: Trending algorithm updated? Replay Playback events → Trending Projection → Updated rankings.

Uber: Pricing bug fixed? Replay Ride events → Analytics → Historical reports updated.

🎯 Interview Callout
Q
"Your analytics database was accidentally deleted. How do you recover?"
"Redeploy the analytics projection service, enable replay mode to suppress side effects, replay historical events from the Event Store or Kafka, rebuild the analytics database, validate correctness, then return to normal operation. Use snapshots or parallel replay if the event history is very large."
🧠 Memory Trick
History → Replay → Projection → Rebuild → Recovery. Events are forever. Mistakes are reversible.
