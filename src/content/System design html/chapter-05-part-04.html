Preventing Cascading Failures

📖 The Story — The Concert Ticket Rush
Why Cache Stampedes Happen

Thousands of people hitting refresh simultaneously.

Imagine a popular concert where tickets go on sale at 10:00 AM. At exactly 10:00 AM, 100,000 people simultaneously click "Buy Tickets." If the ticket inventory is cached and expires at 10:00 AM, all 100,000 requests miss the cache and hit the database simultaneously. The database cannot handle the sudden spike. This is a cache stampede.

🎯 What is a Cache Stampede?
Cache Stampede: A situation where a popular cache entry expires, and a large number of simultaneous requests miss the cache and flood the database. Also called: Thundering Herd, Dogpile, Cache Avalanche.
⚠ The Problem

Example: A product page cached for 1 hour. At 11:00 AM, 50,000 users request the page simultaneously. The cache entry expires. All 50,000 requests miss the cache and query the database. The database receives 50,000 identical queries at once.

10:00 AM → Cache Hit → 50,000 Fast Responses 11:00 AM → Cache Expired → 50,000 Database Queries → Database Overwhelmed
🛠 Prevention Strategies

1. Locking (Mutex)

Only one request rebuilds the cache. Others wait.

Request 1 → Acquire Lock → Rebuild Cache → Release Lock Request 2 → Wait for Lock → Use Rebuilt Cache Request 3 → Wait for Lock → Use Rebuilt Cache
✅ Advantage
Only one database query per expiration
❌ Disadvantage
Added complexity, potential deadlocks

2. Jitter (Randomized TTL)

Add randomness to expiration times so entries don't expire simultaneously.

Entry A: TTL = 1 hour + random(0-10 minutes) Entry B: TTL = 1 hour + random(0-10 minutes) Entry C: TTL = 1 hour + random(0-10 minutes)
✅ Advantage
Simple, prevents synchronized expirations
❌ Disadvantage
Doesn't help if a single entry is extremely popular

3. Never Expire (Background Refresh)

Keep serving stale data while a background job refreshes the cache.

Cache Entry Expires? ├── Yes → Continue Serving Stale Data │ └── Background Job Refreshes Cache └── No → Serve Fresh Data
✅ Advantage
Zero user-facing latency spikes
❌ Disadvantage
Users may see slightly stale data

4. Probabilistic Early Expiration

Start refreshing popular entries before they expire based on access patterns.

If an entry is accessed frequently: └── Refresh it proactively before expiration
✅ Advantage
Prevents stampedes for popular items
❌ Disadvantage
More database queries for popular items

🏭 Production Example
Real World

E-commerce Flash Sale

A popular e-commerce site runs a flash sale. Product pages are cached with TTL = 5 minutes. To prevent stampedes: 1) Jitter: Add random(0-30s) to TTL. 2) Locking: Only one request rebuilds the cache. 3) Monitoring: Alert if cache miss rate spikes. Result: Database remains stable even with 100,000 concurrent users.
