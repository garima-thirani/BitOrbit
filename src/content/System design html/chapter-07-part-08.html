📖 The Story — LinkedIn's Data Problem
Why Kafka Was Created

The library that never throws away books.

Imagine a national library where every book is placed on a shelf and never removed. Readers remember their page number and return anytime. This is Kafka. Unlike RabbitMQ which delivers and deletes messages, Kafka stores every event forever. LinkedIn needed this because different teams needed to replay historical data: Search, Recommendations, Ads, Analytics, ML. Traditional brokers couldn't do this. Kafka was born in 2010 at LinkedIn to solve exactly this problem.

🎯 What is Kafka?
Apache Kafka: A distributed event streaming platform designed for high-throughput, fault-tolerant, scalable event storage and processing. It's not a message queue - it's an append-only distributed log.

📁 What is a Topic?
Topic: A logical category of events. Examples: "orders", "payments", "page_views", "notifications". Topics organize related events together.
Topics organize events: topic: orders topic: payments topic: page_views topic: notifications Each topic is independent.
📄 What is a Partition?
Partition: Topics are divided into partitions for parallelism. Each partition is an ordered, immutable log of events stored on disk.

Why partitions? One topic might receive 2M events/second. One server can't handle that. Partitions distribute data across multiple brokers.

Topic: orders ├── Partition 0 (Broker 1) ├── Partition 1 (Broker 2) ├── Partition 2 (Broker 3) └── Partition 3 (Broker 4) Parallel processing across brokers
⚠️ Important
Kafka guarantees ordering ONLY within a partition, not across partitions
🔢 What is an Offset?
Offset: A unique sequential number assigned to each event within a partition. Like page numbers in a book. Consumers track their position using offsets.
Partition 0: Offset 0: OrderCreated Offset 1: OrderPaid Offset 2: OrderShipped Offset 3: OrderDelivered Consumer remembers last offset read
👥 What is a Consumer Group?
Consumer Group: A group of consumers that work together to consume a topic. Each partition is assigned to only one consumer in the group.
Topic: orders (4 partitions) Consumer Group: Analytics ├── Consumer A → Partition 0 ├── Consumer B → Partition 1 ├── Consumer C → Partition 2 └── Consumer D → Partition 3 Load balanced automatically
💡 Key Insight
Different teams can have different Consumer Groups reading the same topic independently
🔄 Leader & Followers

Each partition has one Leader and multiple Followers (replicas).

Partition 0: ├── Leader (Broker 1) - handles reads/writes ├── Follower (Broker 2) - replicates └── Follower (Broker 3) - replicates If Leader crashes → Follower becomes Leader
✅ In-Sync Replicas (ISR)
ISR: Replicas that are fully synchronized with the Leader. Only ISR members can become Leader during failover.
⚡ Why Kafka is Fast
📝 Sequential Writes
Append-only log = sequential disk writes (very fast)
📦 Batching
Sends events in batches, not one-by-one
🗜 Compression
Compresses batches for less network overhead
💨 Zero Copy
Minimizes data copying between kernel and app

🏭 Production Examples
Real World

Netflix, Uber, LinkedIn

Netflix: Every playback event → Kafka → Recommendations, Billing, Analytics, ML. Each has own Consumer Group.

Uber: RideCompleted → Kafka → Pricing, Receipts, Fraud, ML, Heat Maps. Independent processing.

LinkedIn: Profile views, searches, messages → Kafka → Search Ranking, Ads, Feed, Recommendations. Original Kafka use case.

🎯 Interview Callout
Q
"Why are partitions important in Kafka?"
"Partitions enable parallel processing across multiple brokers. They improve throughput and scalability. However, ordering is only guaranteed within a partition, so partition strategy matters for ordered data."
🧠 Memory Trick
Topic = Category, Partition = Parallelism, Offset = Position, Consumer Group = Load Balance. Kafka stores events forever.
🧪 Test Your Knowledge
1. What does a Consumer Group do?
A) All consumers process all messages
B) Consumers compete for messages
C) Consumers share workload - each partition assigned to one consumer
D) Consumers process messages randomly
Consumer Groups enable load balancing. Each partition is assigned to one consumer, enabling parallel processing.
2. Where does Kafka guarantee ordering?
A) Across all partitions
B) Across all topics
C) Within a single partition only
D) Kafka doesn't guarantee ordering
Kafka guarantees ordering only within a partition. Events in different partitions can arrive in any order.
