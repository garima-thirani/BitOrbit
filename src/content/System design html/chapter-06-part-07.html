Facebook News Feed Case Study
Designing a High-Performance Feed System

Facebook's news feed serves billions of users with personalized content. This case study applies multi-tier caching, fanout strategies, and real-time updates to build a scalable feed system.

📖 Problem Statement
Design Challenge

Design a news feed system like Facebook or Twitter.

Design a news feed system where users can: Post updates, photos, videos, Follow other users, View personalized feed, Like and comment, Share content. The system must serve millions of users with low latency while handling millions of posts per day.

📋 Requirements

✅ Functional

User posts, Follow/unollow, News feed generation, Likes, comments, shares, Notifications, Media uploads, Search

📊 Non-Functional

Low latency feed loading (< 200ms), High availability, Real-time updates, Personalized content, Handle 1B+ users, Support viral content

⚠️ Key Challenges
📰 Feed Generation
Millions of users, each with unique feeds
⚡ Low Latency
Feed must load in < 200ms
🔥 Viral Content
Popular posts can overwhelm systems
💾 Storage Scale
Billions of posts, photos, videos
🏛 High-Level Architecture
News Feed Architecture: Users → API → Feed Cache → Fanout → Database/CDN
⚡ Multi-Tier Caching Strategy

Feed systems rely heavily on caching:

L1: Browser Cache
Cache static assets, profile pictures
L2: CDN
Cache images, videos, popular posts
L3: Redis
Cache generated feeds, user data, post metadata
L4: Database
Source of truth for all data
🔄 Fanout Strategies

How to deliver posts to followers:

📤 Push Fanout
When user posts, write to all followers' feeds. Fast reads, slower writes.
📥 Pull Fanout
When user loads feed, fetch from all followed users. Slower reads, faster writes.
🔄 Hybrid
Push for normal users, pull for celebrities with millions of followers.
📊 Feed Generation Flow
User Requests Feed ↓ Check Redis (Cached Feed?) ├── Yes → Return Cached Feed (Fast!) └── No │ Fetch from Database │ Rank Posts (Algorithm) │ Cache in Redis (TTL = 5 min) │ Return Feed
🎯 Ranking Algorithm

Feed ranking considers multiple signals:

⏰ Recency
Newer posts rank higher
❤️ Engagement
Likes, comments, shares
👥 Relationship
Close friends rank higher
📊 User Behavior
What the user typically engages with
⚡ Handling Viral Content

When a post goes viral:

📋 Separate Cache
Store viral posts in dedicated cache
⏱ TTL Extension
Keep viral posts cached longer
📊 Rate Limiting
Prevent abuse and spam
🔄 CDN Offload
Serve viral content from CDN

🧠 Memory Trick
Feed = Cache + Fanout + Rank. Push for normal users, pull for celebrities.
🧪 Test Your Knowledge
1. Why use push fanout for normal users and pull fanout for celebrities?
A) Celebrities don't post often
B) Celebrities have millions of followers — pushing to all would be expensive
C) Normal users don't care about latency
D) Pull is always better
A celebrity with 10M followers would require 10M writes per post. Pull fanout is more efficient — fetch posts when followers request their feed.
