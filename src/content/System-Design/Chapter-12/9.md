# Engineering Notes

## Large Companies Never Depend on One Cache Layer

Production systems

rarely rely

on

a single cache.

Instead,

they combine

browser caches,

CDNs,

reverse proxies,

local application caches,

distributed caches,

and databases.

Each layer

reduces

the load

on the next.

---

## Different Data Lives in Different Caches

Static assets,

dynamic metadata,

user sessions,

and analytics

have

different access patterns.

Successful systems

store

each type

of data

in the cache

best suited

to its workload,

rather than forcing

everything

into Redis.

# FAANG Interview Questions

## Question 1

### Question

Why do companies use multiple cache layers?

### Ideal Answer

Each cache layer serves a different purpose. Browser caches eliminate client requests, CDNs reduce global latency, reverse proxies offload application servers, Redis caches dynamic data, and databases remain the source of truth. Together they maximize performance and scalability.

---

## Question 2

### Question

Why isn't Redis used to cache everything?

### Ideal Answer

Redis is best suited for frequently accessed, dynamic data. Static assets are more efficiently served from browser caches and CDNs, while highly volatile or sensitive data may require direct database access to maintain correctness.

---

## Question 3

### Question

How do companies prevent cache stampedes?

### Ideal Answer

They use distributed mutex locks, request coalescing, refresh-ahead, randomized TTLs, cache warming, and multi-layer caching to prevent many requests from rebuilding the same cache entry simultaneously.

---

## Question 4

### Question

How do global systems reduce latency?

### Ideal Answer

By deploying edge caches and CDNs across multiple geographic regions, serving content from the location closest to the user, and using regional Redis clusters for dynamic data.

---

## Question 5 (FAANG)

### Question

Design the caching architecture for a global e-commerce platform serving hundreds of millions of users.

### Ideal Answer

Use browser caching for static assets, a CDN for images and downloadable content, reverse proxy caching for HTML pages, Redis Cluster for dynamic product metadata and sessions, local in-memory caches for configuration, Cache-Aside with event-driven invalidation, randomized TTLs and refresh-ahead for popular products, Bloom Filters to prevent cache penetration, distributed locks to prevent cache stampedes, and multi-region deployments with replication for high availability and low latency.
