# Engineering Notes

## Eviction Policy Directly Affects Database Load

An ineffective

eviction strategy

causes

data

to leave the cache.

This lowers

the cache hit ratio,

forcing

more requests

to the database

and increasing

overall latency.

Choosing

the correct

eviction policy

is often

as important

as choosing

the cache itself.

---

## TTL is a Consistency Mechanism, Not Just a Cleanup Mechanism

Many engineers

view TTL

only as

memory cleanup.

In reality,

TTL also controls

how stale

cached data

can become.

Selecting

the correct TTL

requires

balancing

freshness,

latency,

and

database load.

# Interview Questions & Solutions

## Question 1

### Question

Why does a cache need an eviction policy?

### Ideal Answer

Cache memory is limited. When the cache becomes full, an eviction policy determines which items should be removed to make space for new data while maximizing future cache hits and minimizing database load.

---

## Question 2

### Question

What is the difference between LRU and LFU?

### Ideal Answer

LRU removes the item that has not been accessed recently, assuming recent access predicts future access. LFU removes the item accessed least frequently, assuming frequently requested objects are more valuable over time.

---

## Question 3

### Question

What is TTL and why is it important?

### Ideal Answer

TTL (Time-To-Live) specifies how long an item remains in the cache before expiring. It helps prevent stale data, controls memory usage, and balances cache freshness against database load.

---

## Question 4

### Question

When would you choose LFU instead of LRU?

### Ideal Answer

LFU is preferable when a small set of objects remains consistently popular for long periods, such as trending videos or homepage content. LRU performs better when recent access is the strongest predictor of future access.

---

## Question 5 (FAANG)

### Question

Design the eviction strategy for a global e-commerce platform.

### Ideal Answer

Use Redis with the `allkeys-lru` policy for general product caching because user access exhibits strong temporal locality. Apply TTL values based on business requirements, invalidate cache entries immediately after product updates, monitor hit ratio, eviction rate, and memory utilization, and use LFU selectively for long-lived popular content such as trending products or best-seller rankings.

# Revision Notes

- Cache eviction is necessary because memory is finite.
- TTL controls both cache freshness and memory cleanup.
- LRU is the most widely used eviction policy due to temporal locality.
- LFU is ideal for workloads with long-lived popular objects.
- ARC and TinyLFU improve upon traditional algorithms by combining recency and frequency.
- Redis provides multiple eviction policies for different workloads.
- Monitoring hit ratio, eviction rate, and memory usage is essential for maintaining cache performance.
