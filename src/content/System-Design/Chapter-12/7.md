# Memcached vs Redis

| Feature | Redis | Memcached |
|----------|--------|-----------|
| Persistence | Yes | No |
| Replication | Yes | No |
| Data Structures | Many | String Only |
| Pub/Sub | Yes | No |
| Streams | Yes | No |
| Cluster | Native | Client-side |
| Memory Efficiency | High | Very High |
| Complexity | Higher | Lower |

# Interview Questions & Solutions

## Question 1

### Question

When would you choose Memcached over Redis?

### Ideal Answer

Choose Memcached when you need a simple, high-performance in-memory cache without persistence, replication, or advanced data structures. It is ideal for temporary cache entries in read-heavy workloads where operational simplicity is important.

---

## Question 2

### Question

What is the purpose of a CDN?

### Ideal Answer

A CDN stores cached copies of static and cacheable content on geographically distributed edge servers. Users receive content from the nearest edge location, reducing latency, lowering origin server load, and improving availability.

---

## Question 3

### Question

What is the difference between Browser Cache and Redis?

### Ideal Answer

Browser cache stores content locally on the user's device, eliminating requests entirely. Redis is a server-side cache shared by multiple users and applications, reducing backend database access.

---

## Question 4

### Question

What is an ETag?

### Ideal Answer

An ETag is a unique identifier representing a specific version of a resource. Browsers send the ETag back to the server to determine whether the cached copy is still valid, allowing efficient `304 Not Modified` responses.

---

## Question 5 (FAANG)

### Question

Design the caching architecture for a global video streaming platform.

### Ideal Answer

Implement a multi-layer cache consisting of browser caching for static assets, CDN edge caching for videos and images, reverse proxy caching for HTML responses, Redis clusters for metadata and user sessions, and the primary database as the source of truth. Configure Cache-Control headers and ETags for browser validation, invalidate CDN objects after content updates, monitor cache hit ratio across all layers, and replicate Redis clusters across regions for low-latency access and high availability.

# Revision Notes

- Large-scale systems use multiple cache layers to reduce latency and backend load.
- Memcached is a lightweight in-memory cache, while Redis provides richer functionality and persistence.
- Browser caching eliminates requests before they reach the server.
- HTTP caching relies on Cache-Control headers, ETags, and Last-Modified timestamps.
- CDNs cache content at edge locations close to users, improving global performance.
- Reverse proxies such as Nginx and Varnish cache backend responses.
- Effective caching combines browser, CDN, reverse proxy, and server-side caches into a unified architecture.
