# Engineering Notes

## Caches Improve Performance by Avoiding Work

Caching

does not

make

databases faster.

Instead,

it avoids

executing

expensive operations

repeatedly.

The biggest gain

comes

from

eliminating unnecessary work.

## Cache Effectiveness Depends on Access Patterns

A cache

is valuable

only when

the same data

is requested

multiple times.

Applications

with highly random,

never-repeated requests

gain little benefit

from caching.

Understanding

access patterns

is as important

as choosing

the caching technology.

# Interview Questions & Solutions

## Question 1

### Question

Why do distributed systems use caching?

### Ideal Answer

Caching reduces latency, decreases database load, increases throughput, improves scalability, and lowers infrastructure costs by serving frequently requested data directly from memory instead of repeatedly querying slower backend systems.

---

## Question 2

### Question

What is the difference between a cache hit and a cache miss?

### Ideal Answer

A cache hit occurs when the requested data is already available in the cache and can be returned immediately. A cache miss occurs when the data is absent, requiring a database lookup before optionally storing the result in the cache.

---

## Question 3

### Question

Why is RAM used for caching?

### Ideal Answer

RAM provides nanosecond-level access times, making it orders of magnitude faster than SSDs, HDDs, or remote databases. This enables low-latency responses for frequently accessed data.

---

## Question 4

### Question

What kinds of data should be cached?

### Ideal Answer

Frequently read, infrequently updated data such as product catalogs, user profiles, configuration values, search results, and API responses are ideal candidates. Highly volatile or security-sensitive data requires careful consideration.

---

## Question 5 (FAANG)

### Question

Design the caching layer for an e-commerce platform handling 100 million daily users.

### Ideal Answer

Deploy a distributed cache such as Redis in front of the primary database. Cache frequently accessed product details, category pages, pricing metadata, and recommendation results. Monitor cache hit ratio, preload popular products during startup, define expiration policies, and implement cache invalidation whenever product information changes. Use local in-memory caches for ultra-low-latency application configuration and distributed caches for shared business data.

# Revision Notes

- Caching stores frequently accessed data in memory to reduce latency.
- Cache hits avoid database queries, while cache misses load data from the database.
- High cache hit ratios significantly reduce backend load.
- Local caches are fastest but isolated; distributed caches are shared across services.
- Cache warming improves startup performance by preloading popular data.
- Cache invalidation is critical for maintaining consistency.
- Effective caching depends on workload characteristics and access patterns.
