# Engineering Notes

## Consistent Hashing Makes Scaling Practical

Without

consistent hashing,

adding

or removing

a cache node

would relocate

almost every key,

causing

a massive

drop

in cache hit ratio.

Consistent hashing

limits

key movement

to

only the affected

portion

of the hash ring,

making

elastic scaling

possible.

---

## Hot Keys Are More Dangerous Than Big Data

Many systems

fail

not because

they store

too much data,

but because

one cache key

receives

millions

of requests.

Detecting

and mitigating

hot keys

through

replication,

local caching,

or request distribution

is critical

for production systems.

# Interview Questions & Solutions

## Question 1

### Question

Why is consistent hashing preferred over modulo hashing?

### Ideal Answer

Modulo hashing remaps almost every key whenever the number of servers changes, causing massive cache misses. Consistent hashing moves only a small subset of keys when nodes are added or removed, making it ideal for distributed caches.

---

## Question 2

### Question

What are virtual nodes?

### Ideal Answer

Virtual nodes represent multiple logical positions for a physical server on the hash ring. They improve load balancing, reduce data skew, and make scaling and failover more uniform.

---

## Question 3

### Question

How does Redis Cluster distribute data?

### Ideal Answer

Redis Cluster divides the keyspace into 16,384 hash slots. Each node owns a subset of these slots, and keys are assigned to slots using a hash function, allowing efficient partitioning and rebalancing.

---

## Question 4

### Question

What is a hot key and why is it a problem?

### Ideal Answer

A hot key is a cache entry that receives a disproportionately high number of requests, potentially overloading a single cache node. Solutions include local caching, replication, request throttling, and distributing read traffic.

---

## Question 5 (FAANG)

### Question

Design the distributed caching layer for a global e-commerce platform.

### Ideal Answer

Deploy Redis Cluster across multiple regions with hash-slot partitioning and replicas for high availability. Use consistent hashing to minimize key movement during scaling, virtual nodes for balanced distribution, regional caches to reduce latency, event-driven invalidation to synchronize updates, and monitoring for hot keys, hit ratio, replication lag, and memory utilization. Cache frequently accessed product metadata while using local in-memory caches for configuration and feature flags.

# Revision Notes

- Distributed caches overcome the memory and throughput limitations of a single cache server.
- Sharding partitions data across multiple cache nodes.
- Consistent hashing minimizes key movement when scaling the cluster.
- Virtual nodes improve load balancing and fault tolerance.
- Redis Cluster uses 16,384 hash slots for automatic partitioning.
- Replication provides high availability, while regional caches reduce latency.
- Hot keys require special handling to prevent individual nodes from becoming bottlenecks.
