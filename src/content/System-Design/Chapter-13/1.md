# Engineering Notes

## Indexes Optimize Search, Not Storage

Indexes

of data

Instead,

they provide

to locate

specific rows,

much like

a book's index

---

## Every Index Has a Cost

Many engineers

focus only

on

faster reads.

However,

every index

must also

be updated

during writes.

Large production systems

carefully choose

indexes

that provide

the greatest benefit

while minimizing

write overhead

and storage costs.

# Interview Questions & Solutions

## Question 1

### Question

Why do databases use indexes?

### Ideal Answer

Indexes allow databases to locate rows efficiently without scanning the entire table. They significantly improve read performance by organizing searchable values into optimized data structures.

---

## Question 2

### Question

What is a Full Table Scan?

### Ideal Answer

A Full Table Scan occurs when the database examines every row in a table to find matching data. It has O(n) complexity and is often used when no suitable index exists or when scanning is cheaper than using an index.

---

## Question 3

### Question

Why aren't all columns indexed?

### Ideal Answer

Indexes consume storage and slow down INSERT, UPDATE, and DELETE operations because they must be maintained. Columns with low selectivity or rarely queried values often provide little benefit from indexing.

---

## Question 4

### Question

What is index selectivity?

### Ideal Answer

Selectivity measures how effectively an index narrows down search results. Highly selective columns, such as email addresses or unique IDs, make indexes much more efficient than columns with only a few distinct values.

---

## Question 5 (FAANG)

### Question

Design the indexing strategy for a global e-commerce customer database.

### Ideal Answer

Index the primary key (CustomerID), unique columns such as Email and Username, and foreign keys used in joins. Avoid indexing low-selectivity columns like Gender or Status unless justified by specific query patterns. Continuously monitor query execution plans, balance read performance against write overhead, and periodically review unused indexes to minimize storage and maintenance costs.

# Revision Notes

- Indexes accelerate row lookups by storing searchable keys and row references.
- Full Table Scans examine every row and become expensive on large tables.
- Primary keys are typically indexed automatically.
- Secondary indexes support additional search paths.
- High-selectivity columns benefit most from indexing.
- Indexes improve read performance but increase write costs and storage usage.
- Effective indexing requires balancing query speed against maintenance overhead.
