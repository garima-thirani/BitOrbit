# Interview Questions & Solutions

## Question 1

### Question

Why can a table have only one clustered index?

### Ideal Answer

A clustered index determines the physical order of rows on disk. Since rows can only be stored in one physical order, a table can have only one clustered index.

---

## Question 2

### Question

What is the difference between clustered and non-clustered indexes?

### Ideal Answer

A clustered index stores table rows in index order, making the leaf nodes the actual data pages. A non-clustered index is a separate B+ Tree containing indexed keys and pointers to the underlying table rows.

---

## Question 3

### Question

What is a covering index?

### Ideal Answer

A covering index contains all columns required by a query, allowing the database to satisfy the request entirely from the index without accessing the base table, reducing disk I/O.

---

## Question 4

### Question

Why are sequential keys preferred for clustered indexes?

### Ideal Answer

Sequential keys minimize page splits and fragmentation because new rows are appended near the end of the index rather than inserted randomly throughout the tree.

---

## Question 5 (FAANG)

### Question

Design the indexing strategy for a global order database containing billions of records.

### Ideal Answer

Use a clustered B+ Tree index on the sequential OrderID to optimize primary lookups and minimize fragmentation. Create non-clustered indexes on frequently searched fields such as CustomerID, Email, and OrderStatus. Build covering indexes for high-frequency reporting queries, monitor fragmentation, periodically rebuild indexes when necessary, and avoid clustering on random UUIDs to reduce page splits.

# Revision Notes

- A clustered index determines the physical storage order of table rows.
- A table can have only one clustered index but many non-clustered indexes.
- Non-clustered indexes store keys and pointers to table rows.
- Covering indexes satisfy queries without accessing the base table.
- Sequential clustered keys reduce page splits and fragmentation.
- Random clustered keys such as UUIDs increase maintenance costs.
- Index Seek is the most efficient access path, while Table Scan is generally the most expensive.
