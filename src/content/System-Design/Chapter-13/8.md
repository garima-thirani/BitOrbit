# Interview Questions & Solutions

## Question 1

### Question

Why are database statistics important?

### Ideal Answer

Database statistics provide the optimizer with information about row counts, value distribution, and selectivity. This allows it to estimate query costs accurately and choose efficient execution plans.

---

## Question 2

### Question

What is index fragmentation?

### Ideal Answer

Index fragmentation occurs when logical index order no longer matches physical storage order due to inserts, updates, deletes, and page splits. It increases disk I/O and reduces query performance.

---

## Question 3

### Question

What is the difference between rebuilding and reorganizing an index?

### Ideal Answer

Rebuilding recreates the entire index, removing fragmentation completely but requiring more resources. Reorganizing incrementally defragments the index with less disruption but may not achieve the same level of optimization.

---

## Question 4

### Question

Why is VACUUM necessary in PostgreSQL?

### Ideal Answer

PostgreSQL uses MVCC, leaving obsolete row versions (dead tuples) after updates and deletes. VACUUM reclaims this space, improves storage efficiency, and maintains query performance.

---

## Question 5 (FAANG)

### Question

A production database suddenly becomes slow after a large data import. How would you investigate?

### Ideal Answer

First review execution plans using EXPLAIN ANALYZE to identify plan changes. Verify that database statistics are current, refresh them if necessary, inspect cardinality estimates, review index fragmentation, analyze slow query logs, monitor resource utilization, and check whether new data distributions require different indexing strategies.

# Revision Notes

- Database statistics guide the Cost-Based Optimizer in choosing execution plans.
- Histograms improve row count estimation for unevenly distributed data.
- Accurate cardinality estimates are essential for efficient joins and index selection.
- VACUUM reclaims storage and removes dead tuples in MVCC databases.
- Index fragmentation increases disk I/O and should be monitored.
- Index rebuilds and reorganizations restore index efficiency.
- Slow query logs and execution plans are essential tools for production performance tuning.
