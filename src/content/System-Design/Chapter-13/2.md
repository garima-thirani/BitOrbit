# Interview Questions & Solutions

## Question 1

### Question

Why do databases use B+ Trees instead of Binary Search Trees?

### Ideal Answer

Binary Search Trees have high tree depth and require many disk accesses for large datasets. B+ Trees have high fan-out, much smaller height, and therefore require far fewer disk reads, making them ideal for database storage.

---

## Question 2

### Question

What is the difference between a B-Tree and a B+ Tree?

### Ideal Answer

A B-Tree stores data in both internal and leaf nodes. A B+ Tree stores actual row pointers only in leaf nodes, while internal nodes contain keys for navigation. B+ Trees also link leaf nodes, enabling efficient range scans.

---

## Question 3

### Question

Why are linked leaf nodes important?

### Ideal Answer

Linked leaf nodes allow efficient sequential traversal without repeatedly navigating the tree. This makes B+ Trees particularly effective for range queries, sorting, and pagination.

---

## Question 4

### Question

What is fan-out?

### Ideal Answer

Fan-out is the number of child pointers a tree node can have. Higher fan-out reduces tree height, resulting in fewer disk page reads and faster searches.

---

## Question 5 (FAANG)

### Question

Design the indexing structure for a database storing one billion customer records.

### Ideal Answer

Use B+ Tree indexes for primary keys and frequently queried secondary attributes. Configure page sizes to maximize fan-out, minimizing tree height and disk I/O. Store row pointers in linked leaf nodes for efficient exact lookups, range scans, sorting, and pagination. Monitor index fragmentation and rebuild indexes periodically when necessary.

# Revision Notes

- B+ Trees are the standard index structure used by modern relational databases.
- High fan-out dramatically reduces tree height and disk accesses.
- Internal nodes store only keys, while leaf nodes store row pointers.
- Linked leaf nodes make range queries and ordered scans highly efficient.
- Search, insert, and delete operations all have O(log n) complexity.
- B+ Trees are optimized for disk-based storage rather than CPU-only performance.
- Most SQL databases, including MySQL, PostgreSQL, Oracle, and SQL Server, use B+ Trees for their primary indexing structures.
