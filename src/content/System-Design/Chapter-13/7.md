# Interview Questions & Solutions

## Question 1

### Question

What is a SARGable query?

### Ideal Answer

A SARGable query allows the database optimizer to efficiently use indexes by avoiding functions, calculations, or transformations on indexed columns. It enables fast index seeks instead of table scans.

---

## Question 2

### Question

Why is keyset pagination preferred over OFFSET pagination?

### Ideal Answer

OFFSET pagination requires the database to skip all preceding rows, making it increasingly expensive as offsets grow. Keyset pagination uses the last retrieved key to continue scanning efficiently, providing consistent performance on very large datasets.

---

## Question 3

### Question

When should you use EXISTS instead of IN?

### Ideal Answer

EXISTS is generally more efficient for large subqueries because it stops searching after finding the first matching row. IN is suitable for smaller lists of values and simpler queries.

---

## Question 4

### Question

What is the N+1 query problem?

### Ideal Answer

The N+1 query problem occurs when an application executes one query to retrieve a list of records and then issues an additional query for each record, resulting in excessive database round trips. It is typically solved using joins, eager loading, or batch fetching.

---

## Question 5 (FAANG)

### Question

Your dashboard query has become slow as the Orders table grows to billions of rows. How would you optimize it?

### Ideal Answer

Start by analyzing the execution plan with EXPLAIN ANALYZE. Rewrite the query to be SARGable, ensure appropriate composite and covering indexes exist, replace OFFSET pagination with keyset pagination, avoid SELECT *, eliminate unnecessary DISTINCT and OR conditions where possible, use EXISTS for large existence checks, move expensive reporting queries to materialized views or read replicas, and continuously monitor execution statistics and index usage.

# Revision Notes

- SARGable queries maximize index utilization.
- Avoid functions on indexed columns whenever possible.
- EXISTS is generally preferred for large existence checks.
- Keyset pagination scales much better than OFFSET pagination.
- Covering indexes and query rewriting reduce disk I/O.
- Materialized views accelerate complex reporting workloads.
- Reading execution plans is essential for diagnosing SQL performance problems.
- Efficient SQL often provides greater performance gains than additional hardware.
