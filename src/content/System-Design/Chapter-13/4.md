# Interview Questions & Solutions

## Question 1

### Question

What is a composite index?

### Ideal Answer

A composite index is an index built on multiple columns. It allows the database to efficiently process queries that filter or sort using those columns in the defined order.

---

## Question 2

### Question

Explain the Leftmost Prefix Rule.

### Ideal Answer

A composite index can only be efficiently used starting from its leftmost indexed column. For an index on (A, B, C), queries filtering on A, A+B, or A+B+C can use the index efficiently, while queries filtering only on B or C generally cannot.

---

## Question 3

### Question

What is a covering index?

### Ideal Answer

A covering index contains every column required by a query, allowing the database to return results directly from the index without accessing the underlying table, reducing disk I/O.

---

## Question 4

### Question

Why should highly selective columns appear early in an index?

### Ideal Answer

Highly selective columns eliminate more rows early in the search process, making the index more efficient by reducing the amount of data that must be scanned.

---

## Question 5 (FAANG)

### Question

Design the indexing strategy for an Orders table frequently queried by CustomerID, Status, and OrderDate.

### Ideal Answer

Create a composite index beginning with the most selective and frequently filtered columns, such as (CustomerID, Status, OrderDate). If reporting queries also retrieve Amount and PaymentMethod, include them as covered or included columns to avoid table lookups. Ensure the index also supports common ORDER BY clauses, monitor execution plans, and remove redundant indexes that overlap with the composite index.

# Revision Notes

- Composite indexes store multiple columns in a single index.
- The Leftmost Prefix Rule determines when composite indexes can be used efficiently.
- High-cardinality and high-selectivity columns are generally better index candidates.
- Covering indexes eliminate expensive table lookups by containing all required query columns.
- Included columns allow indexes to cover queries without affecting search order.
- SARGable queries maximize index usage by avoiding functions on indexed columns.
- Good index design is driven by real query patterns rather than table structure alone.
