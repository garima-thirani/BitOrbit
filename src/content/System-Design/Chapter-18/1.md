# Engineering Notes

## Replication Improves Availability, Not Infinite Performance

Replication

creates

multiple copies

of data,

allowing

to survive failures

and distribute

read traffic.

However,

every write

must still

be replicated,

alone

does not

write bottlenecks.

---

## Distribution Introduces Coordination Costs

A single database

does not

need

to coordinate

with other servers.

Distributed databases

must synchronize

updates,

detect failures,

elect leaders,

and resolve conflicts.

Scalability

comes

at the cost

of additional complexity.

# Interview Questions & Solutions

## Question 1

### Question

Why do distributed databases exist?

### Ideal Answer

Distributed databases overcome the limitations of a single machine by distributing data across multiple servers. They improve scalability, availability, fault tolerance, geographic reach, and read performance while presenting a single logical database to applications.

---

## Question 2

### Question

Why doesn't replication automatically improve write throughput?

### Ideal Answer

Each write must still be applied to the primary and propagated to replicas. Replication primarily improves availability and read scalability. Increasing write throughput typically requires partitioning or sharding.

---

## Question 3

### Question

What is the difference between replication and backup?

### Ideal Answer

Replication creates continuously synchronized copies of live data for availability and fault tolerance, whereas backups are point-in-time snapshots intended for recovery after accidental deletion, corruption, or disaster.

---

## Question 4

### Question

Why are read replicas useful?

### Ideal Answer

Most applications perform many more reads than writes. Read replicas distribute read traffic across multiple servers, reducing load on the primary database and improving overall query performance.

---

## Question 5 (FAANG)

### Question

Design the database architecture for a rapidly growing social media platform.

### Ideal Answer

Begin with a primary database and multiple read replicas for high availability and read scaling. Deploy replicas across multiple availability zones or regions for disaster recovery and lower latency. Monitor replication lag and automate failover. As write traffic grows, introduce sharding to distribute writes across multiple database partitions.

# Revision Notes

- Distributed databases distribute data across multiple physical servers while presenting a single logical database.
- Vertical scaling increases server resources, while horizontal scaling adds more servers.
- Replication improves availability, fault tolerance, disaster recovery, and read scalability.
- Read replicas reduce load on the primary database but do not significantly improve write throughput.
- Geographic replication reduces latency for global users and protects against regional failures.
- Replication is different from backups because it maintains live synchronized copies.
- Monitoring replication lag and replica health is essential for reliable production systems.
