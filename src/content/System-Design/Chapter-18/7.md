---

✔ SQL

✔ ACID Transactions

✔ Global Availability

✔ Low Latency

```text

↓

↓

Paxos Group

↓

↓

Storage
```

---

---

---

---

replicate.

---

## Transaction Flow

```text

↓

↓

↓

Paxos

↓

↓

Client
```

# Top 80 FAANG Revision Facts

### Replication

1. Replication improves availability.
2. Replication improves read scaling.
3. Replication does not solve write scaling.
4. Replication requires synchronization.
5. Replication introduces lag.
6. Read replicas may return stale data.
7. Synchronous replication prioritizes consistency.
8. Asynchronous replication prioritizes latency.
9. Semi-synchronous balances both.
10. Failover promotes replicas.

### Sharding

11. Sharding improves write scalability.
12. Horizontal partitioning splits rows.
13. Vertical partitioning splits tables.
14. Shard keys determine scalability.
15. Bad shard keys create hotspots.
16. Range sharding favors range queries.
17. Hash sharding balances load.
18. Directory sharding adds flexibility.
19. Composite sharding combines techniques.
20. Online rebalancing avoids downtime.

### Consistent Hashing

21. Hash rings minimize key movement.
22. Virtual nodes improve balance.
23. Only nearby keys move after scaling.
24. Cassandra uses virtual nodes.
25. Dynamo popularized consistent hashing.

### Leaderless Systems

26. Dynamo is leaderless.
27. Cassandra is leaderless.
28. Every node can coordinate.
29. RF determines replica count.
30. Quorums control consistency.
31. Read repair fixes stale replicas.
32. Anti-entropy synchronizes replicas.
33. Hinted handoff preserves writes.
34. Vector clocks detect conflicts.
35. Eventual consistency is expected.

### Storage Engines

36. Cassandra uses LSM Trees.
37. MySQL uses B+ Trees.
38. MemTables buffer writes.
39. Commit Logs ensure durability.
40. SSTables are immutable.
41. Bloom Filters reduce disk reads.
42. Compaction merges SSTables.
43. Tombstones mark deletes.
44. RocksDB uses LSM Trees.
45. Pebble powers CockroachDB.

### Global Databases

46. Spanner uses Paxos.
47. Spanner uses TrueTime.
48. CockroachDB uses Raft.
49. DynamoDB Global Tables use active-active replication.
50. Geo-partitioning improves latency.
51. Data locality matters.
52. Routing layers hide partitions.
53. Metadata services locate shards.
54. Scatter-gather queries are expensive.
55. Cross-shard joins should be minimized.

### Production Systems

56. Netflix uses Cassandra.
57. Uber uses Cassandra and Kafka.
58. Google built Bigtable.
59. Bigtable inspired HBase.
60. Vitess powers YouTube sharding.
61. MongoDB uses Config Servers.
62. Replica Sets provide HA.
63. Kubernetes stores metadata in etcd.
64. Kafka stores logs sequentially.
65. SSDs favor sequential writes.

### Design Principles

66. Reads scale with replication.
67. Writes scale with sharding.
68. Strong consistency costs latency.
69. Eventual consistency improves availability.
70. Every distributed system assumes failures.
71. Data movement is expensive.
72. Online migrations are preferred.
73. Monitor hotspots continuously.
74. Choose shard keys carefully.
75. Use replication for resilience.
76. Use partitioning for scale.
77. Minimize distributed transactions.
78. Prefer local operations.
79. Observe before optimizing.
80. Simplicity usually scales better than unnecessary complexity.
