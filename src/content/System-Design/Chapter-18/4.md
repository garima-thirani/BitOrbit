# Interview Questions & Solutions

## Question 1

### Question

Why is replication alone insufficient for large-scale databases?

### Ideal Answer

Replication creates multiple copies of the same data and primarily improves availability and read scalability. It does not significantly increase write throughput because every write still targets the same logical dataset. Sharding distributes writes across multiple databases, allowing the system to scale horizontally.

---

## Question 2

### Question

What makes a good shard key?

### Ideal Answer

A good shard key has high cardinality, distributes data evenly, remains stable over time, and aligns with common access patterns. User IDs and Order IDs are common examples because they avoid hotspots and evenly spread traffic.

---

## Question 3

### Question

Why is Consistent Hashing better than modulo hashing?

### Ideal Answer

Modulo hashing causes most keys to move whenever the number of shards changes. Consistent hashing limits data movement to the partitions affected by the added or removed node, significantly reducing rebalancing costs and improving scalability.

---

## Question 4

### Question

What are virtual nodes?

### Ideal Answer

Virtual nodes divide a physical server into multiple logical positions on the hash ring. This improves load balancing, simplifies scaling, and prevents uneven key distribution caused by physical node placement.

---

## Question 5 (FAANG)

### Question

Design the database architecture for a platform expected to grow from 10 million to 2 billion users.

### Ideal Answer

Begin with Leader–Follower replication for high availability and read scaling. As write traffic increases, horizontally shard data using a high-cardinality shard key such as User ID. Use consistent hashing with virtual nodes to distribute traffic evenly and simplify scaling. Monitor hotspots, rebalance shards online, avoid cross-shard joins where possible, and replicate each shard independently for fault tolerance.

# Revision Notes

- Sharding distributes data across multiple databases to improve write scalability and storage capacity.
- Horizontal partitioning divides rows, while vertical partitioning divides tables or services.
- The shard key is the most critical design decision because it determines data distribution and long-term scalability.
- Range sharding is simple but can create hotspots, while hash sharding distributes load more evenly.
- Consistent hashing minimizes data movement when servers are added or removed.
- Virtual nodes improve load balancing and are widely used in modern distributed databases.
- Cross-shard queries and transactions introduce complexity and should be minimized through careful data modeling.
