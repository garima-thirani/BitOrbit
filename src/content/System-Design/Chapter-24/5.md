# Performance Optimization Checklist

Whenever a system becomes slow, investigate these layers.

```text
Client
   │
Network
   │
Load Balancer
   │
Application
   │
Cache
   │
Database
   │
Storage
```

Typical optimizations include:

- Add caching.
- Optimize database indexes.
- Reduce network latency.
- Introduce asynchronous processing.
- Scale horizontally.
- Offload static content to a CDN.

---

# Scalability Checklist

Before declaring a design complete, verify:

- Horizontal Scaling
- Load Balancing
- Stateless Services
- Auto Scaling
- Read Replicas
- Sharding
- CDN
- Multi-Region Deployment

---

# Reliability Checklist

Ask yourself:

- What happens if a server fails?
- What happens if a database fails?
- What happens if Redis is unavailable?
- What happens if Kafka is unavailable?
- Can requests be retried safely?
- Is there replication?
- Is there failover?
- Is disaster recovery planned?

---

# Production Readiness Checklist

Before launching any system, ask:

- Does it scale?
- Is it fault tolerant?
- Is data backed up?
- Are APIs secured?
- Are logs and metrics available?
- Is deployment automated?
- Are alerts configured?
- Can the system recover from failures?
- Have bottlenecks been identified?

# Final Words

Technology changes rapidly, but engineering principles remain consistent.

Always:

- Start with requirements.
- Keep the design as simple as possible.
- Scale only when necessary.
- Measure before optimizing.
- Explain your trade-offs.
- Design for failures, not just success.

These principles apply whether you're building a URL shortener, a payment gateway, an AI assistant, or the next large-scale internet platform.
