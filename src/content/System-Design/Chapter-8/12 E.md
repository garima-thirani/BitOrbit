# Universal Design Principles

Every production architecture follows these principles.

---

## Principle 1

Business Events

Not Technical Events

Good

```
OrderCreated
```

Bad

```
DatabaseUpdated
```

---

## Principle 2

Immutable Events

Events are never modified.

Instead

Create

New Events.

---

## Principle 3

Loose Coupling

Producer

Never knows

Consumers.

---

## Principle 4

Replay Everything

Historical events

must always

be replayable.

---

## Principle 5

Consumers are Idempotent

Processing

```
PaymentCompleted
```

twice

must not duplicate money.

---

## Principle 6

Own Your Data

Every service

owns

its database.

Never share databases.

---

## Principle 7

Partition by Business Entity

Good

```
Order ID

Ride ID

Conversation ID

Account ID
```

Bad

Random keys.

---

## Principle 8

Everything Observable

Every event should be traceable.

Every consumer measurable.

Every failure recoverable.

## Kafka vs RabbitMQ

| Kafka | RabbitMQ |
|--------|-----------|
| Event Streaming | Work Queues |
| Replay | Immediate Processing |
| Analytics | Task Execution |
| High Throughput | Low Latency Commands |
| Event History | Request Processing |

# Key Takeaways

- Design around business events, not technical actions.
- Publish immutable events.
- Keep producers independent of consumers.
- Use Kafka for durable event streaming.
- Scale consumers independently.
- Build specialized read models with CQRS.
- Use Event Sourcing only where historical reconstruction matters.
- Ensure replay safety through idempotency and replay mode.
- Treat schemas as contracts.
- Invest in observability from day one.
