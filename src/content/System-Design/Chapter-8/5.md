# What is an Event Broker?

An Event Broker is infrastructure responsible for receiving, storing, routing, and delivering events between producers and consumers.

Instead of

```text
Order Service

↓

Inventory

↓

Shipping

↓

Analytics
```

We have

```text
Order Service

↓

Broker

↓

Inventory

Shipping

Analytics

Fraud

ML
```

The producer communicates with only one component.

---

# Why Brokers Exist

Imagine an airport.

Passengers don't fly directly between every pair of cities.

Instead

Flights go through hubs.

```text
Passenger

↓

Airport Hub

↓

Destination
```

Kafka, RabbitMQ, Pulsar, and NATS are all event hubs.

---

# Responsibilities of an Event Broker

A broker is responsible for:

- Receiving events
- Persisting events
- Routing events
- Delivering events
- Load balancing
- Retry handling
- Failure recovery
- Scaling consumers

It is not responsible for business logic.

# Event Broker vs Event Bus

People often confuse these.

Think of it this way.

```
Event Bus

↓

Communication Pattern

------------------

Event Broker

↓

Software Implementation
```

Kafka implements an Event Bus.

RabbitMQ can implement an Event Bus.

Azure Event Grid implements an Event Bus.

# Interview Questions & Solutions

---

## Question 1

### Question

Why introduce an Event Broker instead of direct service communication?

### What Interviewer Tests

Understanding of loose coupling and scalability.

### Ideal Answer

An Event Broker decouples producers from consumers. Producers publish events without needing to know which services consume them. This improves scalability, fault isolation, independent deployments, and allows new consumers to be added without modifying existing services.

---

## Question 2

### Question

What is the difference between an Event Bus and an Event Broker?

### Ideal Answer

An Event Bus is an architectural communication pattern where producers publish events and consumers subscribe to them. An Event Broker is the software that implements this pattern, such as Kafka, RabbitMQ, Apache Pulsar, or Azure Event Grid.

---

## Question 3

### Question

What is an Event Mesh?

### Ideal Answer

An Event Mesh is a distributed network of interconnected event brokers spanning multiple regions or environments. It enables events to flow automatically between brokers, reducing latency, improving fault tolerance, and supporting geographically distributed applications.

---

## Question 4

### Question

Why do global companies use broker federation?

### Ideal Answer

Federation allows each region to operate its own broker cluster while selectively replicating events across regions. This reduces latency, improves resilience, supports regional autonomy, and avoids routing all traffic through a single global cluster.

---

## Question 5 (FAANG)

### Question

Design the event infrastructure for a global e-commerce platform operating across North America, Europe, and Asia.

### Ideal Answer

Deploy regional Kafka clusters connected through broker federation or an event mesh. Producers publish to local clusters to minimize latency. Important business events are replicated to other regions where analytics, reporting, and global services consume them. RabbitMQ is used for local operational messaging such as email generation and invoice processing. Monitor replication lag, consumer lag, broker health, and cross-region bandwidth.

# Production Engineering Notes

## Capacity Planning

Before selecting a broker, estimate:

- Events per second
- Average event size
- Peak traffic multiplier
- Retention period
- Number of consumer groups
- Replication factor

These determine storage, network bandwidth, and broker count.

---

## Monitoring Metrics

Critical broker metrics include:

- Producer throughput
- Consumer lag
- Replication lag
- Queue depth
- Topic growth
- Partition imbalance
- Disk utilization
- Network throughput
- Broker CPU and memory
- Failed publishes

These metrics are often more valuable than simple CPU utilization.

---

## Failure Scenarios

### Broker Failure

If a Kafka broker fails:

```text
Leader

↓

Follower promoted

↓

Clients reconnect

↓

Traffic resumes
```

Minimal downtime if replication is configured correctly.

---

### Consumer Failure

If a consumer crashes:

```text
Broker

↓

Consumer Timeout

↓

Consumer Group Rebalance

↓

Another Consumer Continues
```

Processing resumes automatically.

---

### Regional Failure

If an entire region becomes unavailable:

```text
US Region

❌

↓

Traffic Routed

↓

EU Region

↓

Asia Region
```

The Event Mesh helps continue operations.

# Revision Notes

- Event Brokers decouple producers from consumers.
- Event Bus is a communication pattern; Event Broker is its implementation.
- Event Mesh connects brokers across regions.
- Federation enables selective broker-to-broker replication.
- Kafka commonly serves as an organization's event backbone.
- RabbitMQ excels at operational messaging; Kafka excels at event streaming.
- Multi-region deployments require careful routing, replication, and monitoring.
