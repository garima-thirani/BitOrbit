# What is Event Replay?

Replay means

**processing historical events again.**

Instead of waiting for new events,

the system reads previously stored events and processes them as if they had just occurred.

---

# Replay Architecture

```text
Event Store

↓

Replay Engine

↓

Projection

↓

Read Model
```

Events are processed again.

Nothing changes in history.

Only downstream systems change.

Before replaying events:

✓ Disable emails

✓ Disable push notifications

✓ Disable payment processing

✓ Disable third-party integrations

✓ Enable replay metrics

✓ Validate projection correctness

Replay should rebuild data—not repeat business actions.

# Interview Questions & Solutions

## Question 1

### Question

What is Event Replay?

### What Interviewer Tests

Understanding of recovery mechanisms.

### Ideal Answer

Event Replay is the process of reprocessing historical events to rebuild projections, recover systems, populate new read models, or recompute analytics. It works because the complete event history is preserved.

---

## Question 2

### Question

Why is replay safer than restoring a database backup?

### Ideal Answer

Database backups capture only snapshots in time and may lose recent changes. Replay reconstructs the latest state by processing every historical event, ensuring no committed business events are lost.

---

## Question 3

### Question

Why should replay avoid sending emails?

### Ideal Answer

Replay is intended to rebuild internal state, not repeat external business actions. Side effects like emails, payments, and notifications must be disabled during replay to avoid duplicate user-visible actions.

---

## Question 4

### Question

How can replay performance be improved?

### Ideal Answer

Use snapshots, replay by partition, parallelize projections, replay only affected aggregates or time ranges, and monitor throughput and lag throughout the replay process.

---

## Question 5 (FAANG)

### Question

Your recommendation database has been accidentally deleted. How would you recover it?

### Ideal Answer

Redeploy the recommendation projection service, enable replay mode to suppress side effects, replay historical events from the Event Store or Kafka, rebuild the recommendation database, validate correctness, and then return the service to normal operation. Use snapshots or parallel replay if the event history is very large.
