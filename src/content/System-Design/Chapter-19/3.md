# Introduction

In the previous part, we learned how search engines organize documents using **Inverted Indexes**.

However, there is an important question we have not answered yet.

> **What exactly gets stored inside the Inverted Index?**

Is the entire document stored?

Do we store complete sentences?

Do we store paragraphs?

The answer is **No**.

Before any document can be indexed, it passes through a **Text Processing Pipeline**.

The purpose of this pipeline is to convert raw human language into a standardized collection of searchable terms.

Without this preprocessing stage,

- search quality would decrease,
- indexes would become unnecessarily large,
- queries would become slower,
- typo tolerance would be impossible,
- and relevance ranking would be far less accurate.

Every modern search engine—including **Lucene, Elasticsearch, OpenSearch, Solr, and Google Search**—uses some variation of this pipeline.

---

# Why Text Processing is Necessary

Consider the following document.

```text
The Distributed Systems Handbook is one of the best books on scalable software architecture.
```

Now suppose a user searches for

```text
distributed system
```

Notice the differences.

The document contains

- Distributed
- Systems

The query contains

- distributed
- system

Although they mean the same thing,

they are not identical strings.

Without preprocessing,

the search engine may fail to retrieve the document.

Text Processing solves exactly this problem.

---

# The Text Processing Pipeline

Every document follows a sequence of transformations before being indexed.

```text
Raw Document
      │
      ▼
Tokenization
      │
      ▼
Stop Word Removal
      │
      ▼
Normalization
      │
      ▼
Stemming / Lemmatization
      │
      ▼
Synonym Expansion
      │
      ▼
N-Gram Generation (Optional)
      │
      ▼
Index Construction
```

Each stage improves either

- storage efficiency,
- search quality,
- or query performance.

---

# Tokenization

The first step is **Tokenization**.

Tokenization breaks raw text into individual searchable units called **tokens**.

Consider the sentence

```text
Distributed systems power modern applications.
```

After tokenization,

it becomes

```text
Distributed

Systems

Power

Modern

Applications
```

Each token can now be inserted into the search index.

---

## Why Tokenization Matters

Without tokenization,

the search engine would treat the entire sentence as a single string.

Searching for

```text
systems
```

would fail because

```text
Distributed systems power modern applications.
```

would be stored as one large block of text.

Tokenization makes every word individually searchable.

---

## Types of Tokenization

Different languages require different tokenization strategies.

### Whitespace Tokenization

The simplest approach.

```text
Distributed Systems Handbook
```

↓

```text
Distributed

Systems

Handbook
```

---

### Rule-Based Tokenization

Considers punctuation.

```text
Hello, World!
```

↓

```text
Hello

World
```

---

### Language-Aware Tokenization

Languages like Chinese and Japanese do not separate words using spaces.

Specialized tokenizers analyze grammar to identify word boundaries.

---

# Stop Words

Not every word contributes meaningful information.

Consider the sentence

```text
The distributed system is built on the cloud.
```

Words like

- the
- is
- on

appear in almost every document.

These words are called **Stop Words**.

After removing them,

the sentence becomes

```text
distributed

system

built

cloud
```

---

## Why Remove Stop Words?

Removing Stop Words provides several advantages.

- Smaller indexes
- Faster searches
- Better ranking
- Less memory usage

Imagine Google indexing the word

```text
the
```

It would appear in nearly every document ever created.

Maintaining such a Posting List would be wasteful.

---

## Are Stop Words Always Removed?

Not necessarily.

Consider the search

```text
The Who
```

"The Who" is the name of a famous rock band.

Removing

```text
The
```

would change the meaning.

Modern search engines selectively retain or remove Stop Words depending on context.

---

# Text Normalization

People write the same word in different ways.

For example,

```text
Docker

docker

DOCKER

DoCkEr
```

All represent the same concept.

A search engine should treat them identically.

This process is called **Normalization**.

---

## Common Normalization Techniques

### Lowercasing

```text
Docker
```

↓

```text
docker
```

---

### Removing Punctuation

```text
Hello!
```

↓

```text
hello
```

---

### Removing Special Characters

```text
C++
```

may become

```text
c++
```

or

```text
cpp
```

depending on the tokenizer.

---

### Unicode Normalization

Different Unicode representations of the same character are standardized into a consistent format.

---

# Stemming

Humans naturally understand that

- connect
- connected
- connecting
- connection

all refer to a similar concept.

Computers do not.

Stemming attempts to reduce related words to a common root.

Example

```text
Running

Runner

Runs

Run
```

↓

```text
Run
```

The resulting root may not always be a valid English word.

Its purpose is efficiency rather than linguistic correctness.

---

## Advantages of Stemming

Searching

```text
running
```

can also retrieve documents containing

```text
run
```

This significantly improves recall.

---

# Lemmatization

Unlike stemming,

**Lemmatization** considers grammar and vocabulary.

Example

```text
Better
```

↓

```text
Good
```

Another example

```text
Children
```

↓

```text
Child
```

Unlike stemming,

the resulting word is always a valid dictionary word.

---

# Stemming vs Lemmatization

| Stemming | Lemmatization |
|-----------|---------------|
| Faster | Slower |
| Rule-based | Dictionary-based |
| May produce invalid words | Produces valid words |
| Less accurate | More accurate |

Search engines choose between these techniques based on speed, accuracy, and language support.

---

# Synonyms

Users often search using different words for the same concept.

Consider

```text
car
```

Another user searches

```text
automobile
```

Another searches

```text
vehicle
```

Although the words differ,

their meanings are closely related.

Search engines maintain **Synonym Dictionaries**.

Example

```text
Car

↓

Automobile

Vehicle

Sedan
```

Searching for one term can automatically retrieve documents containing its synonyms.

---

## Real-World Example

Searching Amazon for

```text
television
```

may also return products labeled

```text
TV
```

This improves search quality without requiring exact wording.

---

# N-Grams

Sometimes users type only part of a word.

Example

```text
Elas
```

The search engine should suggest

```text
Elasticsearch
```

This is made possible using **N-Grams**.

---

## What is an N-Gram?

An N-Gram is a sequence of **N consecutive characters or words**.

Consider the word

```text
Search
```

### 2-Grams

```text
Se

ea

ar

rc

ch
```

---

### 3-Grams

```text
Sea

ear

arc

rch
```

---

## Why N-Grams Matter

N-Grams power features like

- Autocomplete
- Prefix Search
- Spell Checking
- Partial Matching

Many search systems generate N-Grams during indexing so they can quickly answer incomplete queries.

---

# Autocomplete Basics

Suppose a user types

```text
kub
```

The search engine should suggest

- Kubernetes
- Kubectl
- Kubeflow

instead of returning

"No Results Found."

This improves user experience dramatically.

Autocomplete systems rely heavily on

- N-Grams
- Prefix Trees (Tries)
- Popular Query Statistics

# Real-World Example

Consider GitHub Code Search.

Suppose a repository contains

```text
DistributedSystemsTutorial.java
```

A developer searches

```text
distributed system tutorial
```

Even though the exact phrase does not exist,

the tokenizer,

normalizer,

and stemming pipeline enable GitHub to retrieve the correct file almost instantly.

This preprocessing stage is one of the reasons modern search engines feel intelligent rather than relying on simple string matching.

# Key Takeaways

- Raw documents are never indexed directly.
- Every document passes through a Text Processing Pipeline before indexing.
- Tokenization converts text into searchable tokens.
- Stop Words remove extremely common terms that add little search value.
- Normalization standardizes different textual representations into a consistent format.
- Stemming reduces words to their root forms, while Lemmatization produces grammatically correct base words.
- Synonym expansion improves recall by recognizing related words.
- N-Grams enable autocomplete, prefix matching, and partial searches.
- These preprocessing techniques significantly improve search quality, reduce index size, and make large-scale search systems efficient.
