
Tomorrow

```

```


| Performance | Scalability |
|--------------|-------------|

| Local optimization | Architectural optimization |

# Little's Law

One of the most useful

```
L = λ × W
```

- L = Average requests in system
- λ = Arrival rate
- W = Average response time

# Interview Questions & Solutions

## Question 1

### Question

What is the difference between performance and scalability?

### Ideal Answer

Performance measures how fast a system operates under its current workload. Scalability measures whether the system can continue to perform well as workload increases. A high-performance system may not necessarily scale.

---

## Question 2

### Question

When should you choose vertical scaling over horizontal scaling?

### Ideal Answer

Vertical scaling is appropriate when application changes are undesirable, workloads fit on a single machine, or certain databases benefit from larger hardware. Horizontal scaling is preferred for cloud-native applications requiring high availability and long-term growth.

---

## Question 3

### Question

Explain the difference between latency and throughput.

### Ideal Answer

Latency is the time required to complete a single request, while throughput is the number of requests or operations completed per unit of time. Optimizing one does not always optimize the other.

---

## Question 4

### Question

Why is identifying bottlenecks important before scaling?

### Ideal Answer

Scaling components that are not the bottleneck provides little or no improvement. Engineers should measure CPU, memory, database performance, network latency, and application traces to locate the true limiting resource before investing in additional infrastructure.

---

## Question 5 (FAANG)

### Question

Your e-commerce platform currently handles 10,000 requests per second. Management expects traffic to increase to 100,000 requests per second within one year. How would you prepare?

### Ideal Answer

First, benchmark the current system to identify bottlenecks. Design stateless services to enable horizontal scaling behind load balancers. Introduce caching for read-heavy workloads, autoscaling for compute resources, connection pooling for databases, asynchronous processing for background tasks, and capacity planning based on projected growth. Monitor latency, throughput, error rates, and infrastructure utilization continuously to validate scaling assumptions.

# Revision Notes

- Scalability is about sustaining performance as demand grows.
- Performance measures current efficiency; scalability measures future growth.
- Vertical scaling upgrades a single machine but has hardware limits.
- Horizontal scaling distributes work across many machines and improves availability.
- Throughput measures work completed; latency measures response time.
- Capacity planning anticipates future infrastructure needs.
- Always identify and optimize the true bottleneck before scaling.
- Balance performance improvements against operational cost.
