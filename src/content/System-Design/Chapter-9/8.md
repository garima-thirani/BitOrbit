# Interview Questions & Solutions

## Question 1

### Question

Why isn't monitoring enough?

### Ideal Answer

Monitoring indicates that something is wrong, but it rarely explains why. Observability combines logs, metrics, and traces to identify the root cause of failures across distributed systems.

---

## Question 2

### Question

What are the three pillars of observability?

### Ideal Answer

Logs record discrete events, metrics measure system health over time, and distributed traces show how a request flows across services. Together they provide complete visibility into system behavior.

---

## Question 3

### Question

What is the purpose of a Trace ID?

### Ideal Answer

A Trace ID uniquely identifies an entire request as it travels through multiple services. It enables engineers to reconstruct the complete request path during debugging.

---

## Question 4

### Question

What is OpenTelemetry?

### Ideal Answer

OpenTelemetry is an open standard for collecting logs, metrics, and distributed traces. It provides vendor-neutral instrumentation that integrates with tools such as Prometheus, Grafana, and Jaeger.

---

## Question 5 (FAANG)

### Question

Design the observability platform for a large e-commerce application.

### Ideal Answer

Instrument all services using OpenTelemetry. Export metrics to Prometheus and visualize them in Grafana. Collect structured JSON logs into Elasticsearch and analyze them with Kibana. Store distributed traces in Jaeger, propagating Trace IDs and Correlation IDs across all synchronous and asynchronous communication. Monitor SLIs such as latency, error rate, and availability, define SLOs with appropriate error budgets, and integrate Alertmanager with an on-call system such as PagerDuty.

# Revision Notes

- Monitoring shows symptoms; observability reveals causes.
- Logs, metrics, and traces complement each other.
- Every request should carry a Trace ID and Correlation ID.
- Use structured logging for machine-readable analysis.
- Prometheus and Grafana form the standard metrics stack.
- Jaeger visualizes distributed request flows.
- OpenTelemetry standardizes instrumentation.
- SLOs and Error Budgets guide reliability engineering.
- Postmortems should focus on learning, not blame.
