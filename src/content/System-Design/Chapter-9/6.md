# Engineering Notes

## API Gateway Should Not Become a Monolith

A common mistake is putting business logic inside the API Gateway.

Good Gateway

- Authentication
- Routing
- Rate limiting
- Request transformation

Bad Gateway

- Payment processing
- Inventory validation
- Business rules

Business logic belongs inside services.

---

## Service Mesh Is Not Mandatory

Many startups deploy hundreds of successful services without Istio.

Introduce a Service Mesh only when operational networking becomes difficult to manage consistently.

# Interview Questions & Solutions

## Question 1

### Question

Why is Service Discovery required in Microservices?

### Ideal Answer

Because service instances are frequently created, destroyed, and rescheduled in cloud environments. Hardcoded IP addresses quickly become invalid. Service Discovery allows services to locate each other dynamically.

---

## Question 2

### Question

What is the difference between Client-Side and Server-Side Discovery?

### Ideal Answer

In Client-Side Discovery, the client queries the registry and selects an instance itself. In Server-Side Discovery, the client sends requests to a load balancer or proxy, which performs discovery and routing on behalf of the client.

---

## Question 3

### Question

What responsibilities belong to an API Gateway?

### Ideal Answer

Routing, authentication, authorization, SSL termination, rate limiting, logging, monitoring, and request aggregation. Business logic should remain inside the Microservices.

---

## Question 4

### Question

Why use a Service Mesh?

### Ideal Answer

A Service Mesh centralizes networking concerns such as retries, mTLS, traffic routing, observability, and circuit breaking into sidecar proxies, reducing duplication across services.

---

## Question 5 (FAANG)

### Question

Design the networking architecture for a Microservices-based e-commerce platform.

### Ideal Answer

Expose a single API Gateway for external clients. Use Kubernetes Services and DNS for service discovery inside the cluster. Register services automatically, perform readiness and liveness checks, apply rate limiting and JWT authentication at the gateway, and introduce a Service Mesh such as Istio only when advanced traffic management, observability, or mTLS becomes operationally necessary.

# Revision Notes

- Service Discovery removes hardcoded addresses.
- Service Registries maintain the list of healthy service instances.
- API Gateways provide a single secure entry point.
- Server-side discovery simplifies clients.
- Kubernetes offers built-in service discovery through DNS.
- Service Mesh moves networking concerns out of application code.
- Keep business logic out of the API Gateway.
- Adopt Service Mesh when operational complexity justifies it.
