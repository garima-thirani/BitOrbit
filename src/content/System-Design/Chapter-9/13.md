# Architecture Selection Guide

## Should I use Events?

YES if

- Multiple systems react independently
- Background processing
- Analytics
- Notifications
- Fraud Detection
- Recommendations

NO if

- Immediate synchronous response
- Simple CRUD
- Single application

---

## Should I use Kafka?

YES

- High throughput
- Event streaming
- Replay
- Analytics

NO

- Simple task queues
- RPC
- Request-response APIs

---

## Should I use RabbitMQ?

YES

- Background jobs
- Task execution
- Work queues
- Email processing

NO

- Event replay
- Analytics
- Streaming pipelines

---

## Should I use CQRS?

YES

- Read-heavy systems
- Dashboards
- Search
- Large-scale applications

NO

- Small CRUD systems
- Simple admin panels

---

## Should I use Event Sourcing?

YES

- Banking
- Finance
- Audit
- Healthcare
- Compliance

NO

- Blogs
- Internal tools
- CRUD applications

# Final Engineering Principles

1. Design around business events.
2. Keep events immutable.
3. Producers should never know consumers.
4. Consumers must be idempotent.
5. Every event should be replayable.
6. Every service owns its own data.
7. Partition using business identifiers.
8. Monitor everything.
9. Prefer asynchronous workflows where appropriate.
10. Optimize for recoverability, not just correctness.
