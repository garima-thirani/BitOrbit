# Interview Questions & Solutions

## Question 1

### Question

What is database sharding?

### Ideal Answer

Database sharding is the process of partitioning one logical database into multiple physical databases, where each shard stores a subset of the data. This allows systems to scale horizontally by distributing storage and query load across multiple servers.

---

## Question 2

### Question

What is the difference between vertical and horizontal scaling?

### Ideal Answer

Vertical scaling increases the resources of a single machine by adding CPU, memory, or storage. Horizontal scaling adds more machines and distributes data or workload among them, enabling much larger scalability.

---

## Question 3

### Question

When should a database be sharded?

### Ideal Answer

Sharding becomes appropriate when vertical scaling is no longer sufficient, write throughput is saturated, storage limits are reached, or the database has grown so large that a single server cannot handle the workload efficiently.

---

## Question 4

### Question

Why can't read replicas solve every scaling problem?

### Ideal Answer

Read replicas improve read throughput but do not increase write capacity because writes still go to the primary database. Sharding distributes both reads and writes across multiple databases.

---

## Question 5 (FAANG)

### Question

A social media platform grows from one million users to one billion users. How would you scale its database?

### Ideal Answer

Initially scale vertically while introducing caching and read replicas. As write throughput and storage exceed the limits of a single database, partition the data using sharding. Route requests through a shard router, distribute users across shards using an appropriate sharding strategy, deploy read replicas per shard, monitor hotspots, and plan for future rebalancing and fault tolerance.

# Revision Notes

- Vertical scaling upgrades a single server, while horizontal scaling adds more servers.
- Sharding distributes data across multiple physical databases.
- Read replicas improve read scalability but not write scalability.
- Sharding addresses storage, write throughput, and overall scalability.
- Horizontal scaling introduces additional operational complexity.
- Internet-scale systems rely on sharding after exhausting vertical scaling.
- Database scaling decisions should be based on workload, growth projections, and operational requirements.
