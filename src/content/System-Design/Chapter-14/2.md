# Interview Questions & Solutions

## Question 1

### Question

What is a shard key?

### Ideal Answer

A shard key is the attribute used to determine which shard stores a particular record. A good shard key distributes data evenly, remains stable over time, and aligns with common query patterns.

---

## Question 2

### Question

What are the advantages of hash-based sharding?

### Ideal Answer

Hash-based sharding distributes data uniformly across shards, reducing hotspots and balancing storage and write traffic. However, it makes range queries more difficult because adjacent keys may reside on different shards.

---

## Question 3

### Question

Why is range-based sharding prone to hotspots?

### Ideal Answer

When new records are continuously inserted into the latest range, one shard receives a disproportionate share of write traffic while older shards remain underutilized.

---

## Question 4

### Question

When is tenant-based sharding a good choice?

### Ideal Answer

Tenant-based sharding is ideal for SaaS platforms where each customer or organization can be isolated within its own shard, simplifying backup, migration, compliance, and performance isolation.

---

## Question 5 (FAANG)

### Question

Design the sharding strategy for a global social media platform.

### Ideal Answer

Use UserID as the primary shard key with hash-based sharding to achieve even distribution. Co-locate user profiles, posts, and relationships on the same shard when possible. Use geographic routing to direct users to nearby regions, deploy read replicas per shard, monitor hotspots, introduce virtual shards for rebalancing, and employ consistent hashing to minimize data movement as the cluster expands.

# Revision Notes

- A shard key determines where data is stored.
- Range sharding supports efficient range queries but can create hotspots.
- Hash sharding distributes data evenly but complicates range scans.
- Directory sharding offers flexible routing at the cost of maintaining a lookup service.
- Geographic sharding reduces latency and supports regional compliance.
- Tenant and user sharding keep related data together for efficient access.
- Choosing the correct shard key is one of the most important architectural decisions in distributed database design.
