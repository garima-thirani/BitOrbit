# Story – Adding One More Server

Suppose

your system

has

```
4 Database Shards
```

Routing rule

is

```text
Hash(UserID)

MOD 4
```

Everything

works perfectly.

---

Traffic grows.

Need

one more server.

Now

you have

```
5 Shards
```

Routing becomes

```text

MOD 5
```

Suddenly

moves

to

a different shard.

Millions

of records

must migrate.

Production

becomes unstable.

The problem

**Modulo Hashing.**


```
↓

Shard 1

```

```
=

↓

Shard 2
```

The record

# Massive Data Movement

# What is Consistent Hashing?

Instead

to

servers directly,

both

servers

---

```text

↓

90°

↓

180°

↓

270°

↓

360°
```

Circular,

```text

↓

DB2
```

---

# Routing Rule

# Engineering Notes

## Consistent Hashing Optimizes Cluster Growth

Traditional

hashing

optimizes

lookup speed.

Consistent hashing

optimizes

cluster evolution,

making it practical

## Virtual Nodes Solve Real Production Problems

Production servers

Virtual nodes

# Interview Questions & Solutions

## Question 1

### Question

Why does modulo hashing perform poorly when adding new servers?

### Ideal Answer

Modulo hashing depends directly on the number of shards. When the shard count changes, the modulo result changes for most keys, causing widespread data movement and expensive rebalancing.

---

## Question 2

### Question

What problem does consistent hashing solve?

### Ideal Answer

Consistent hashing minimizes data movement when servers are added or removed. Only the keys belonging to neighboring partitions are reassigned, making cluster expansion and failure recovery efficient.

---

## Question 3

### Question

Why are virtual nodes used?

### Ideal Answer

Virtual nodes distribute data more evenly across physical servers, reduce hotspots, simplify rebalancing, and allow stronger servers to own proportionally more data.

---

## Question 4

### Question

How does consistent hashing handle server failures?

### Ideal Answer

When a server fails, only the keys assigned to that server are reassigned to the next server on the hash ring or to replicas. The rest of the cluster remains unaffected.

---

## Question 5 (FAANG)

### Question

Design a database cluster that can scale from 10 servers to 500 servers with minimal downtime.

### Ideal Answer

Use consistent hashing with virtual nodes to distribute data evenly. Store multiple replicas of each partition for fault tolerance, monitor load continuously, and rebalance by transferring virtual nodes rather than entire databases. Use weighted virtual nodes to account for hardware differences and automate failover to replicas during node failures.

# Revision Notes

- Modulo hashing causes widespread data movement when shard counts change.
- Consistent hashing minimizes data migration by using a hash ring.
- Keys are assigned to the next server in the clockwise direction.
- Virtual nodes improve load balancing and simplify cluster expansion.
- Weighted virtual nodes support heterogeneous hardware.
- Replication provides fault tolerance alongside consistent hashing.
- Consistent hashing is widely used in distributed databases and storage systems.
