# Introduction

In the previous part, we learned how RAG retrieves relevant information before sending it to an LLM.

But another important question naturally follows.

> **Once the prompt reaches the AI model, how is the response actually generated?**

Suppose ChatGPT receives

```
Explain Kubernetes in simple terms.
```

What happens next?

Does the model start training again?

Does it search the Internet?

Does it rebuild its neural network?

None of these.

Instead,

the model performs **Inference**.

Inference is the process of using an already-trained model to generate predictions or responses.

For production AI systems,

inference—not training—is where most engineering effort is spent.

---

# AI Training vs AI Inference

One of the biggest misconceptions about AI systems is confusing training with inference.

Although they use the same model,

their goals are completely different.

---

# What is Training?

Training is the process of teaching an AI model by exposing it to massive amounts of data.

During training,

the model continuously adjusts its parameters until it learns patterns.

Training typically happens only occasionally.

---

# Real-Life Analogy

Imagine becoming a doctor.

Medical school,

internships,

and years of practice

represent **training**.

Once qualified,

treating patients

represents **inference**.

The doctor doesn't relearn medicine every time a patient arrives.

---

# Training Pipeline

```text
Training Data

↓

Neural Network

↓

Gradient Calculation

↓

Parameter Updates

↓

Repeat Millions of Times

↓

Trained Model
```

Training is computationally expensive.

Large models may require

- Thousands of GPUs
- Weeks of computation
- Petabytes of data

---

# What is Inference?

Inference is the process of using a trained model to generate outputs.

The model's parameters remain fixed.

No learning occurs.

---

# Example

User Prompt

```
Explain Redis.
```

↓

LLM

↓

Generated Response

The model simply applies

what it has already learned.

---

# Training vs Inference

| Training | Inference |
|------------|------------|
| Learns | Uses Learned Knowledge |
| Updates Parameters | Parameters Fixed |
| Very Expensive | Optimized for Speed |
| Happens Occasionally | Happens Continuously |
| Research Phase | Production Phase |

Most AI engineers work on

Inference Systems,

not model training.

---

# Why Inference Matters

Imagine ChatGPT serving

```
100 Million Users
```

Every prompt

requires inference.

The infrastructure must

- Respond quickly
- Scale automatically
- Minimize cost
- Maximize GPU utilization

This makes inference one of the most important engineering problems in AI.

---

# Online Inference

Most AI assistants perform

**Online Inference.**

---

# What is Online Inference?

Online Inference generates predictions

immediately

after receiving a request.

The user waits for the response.

---

# Examples

- ChatGPT
- Claude
- Gemini
- GitHub Copilot
- Cursor

Every interaction requires real-time inference.

---

# Real-Life Analogy

Imagine ordering food at a restaurant.

You place an order.

The kitchen immediately starts cooking.

You wait.

That is Online Inference.

---

# Batch Inference

Not every AI workload is interactive.

Some predictions are generated

in bulk.

This is called

**Batch Inference.**

---

# Example

Netflix may recompute

movie recommendations

for

250 million users

overnight.

Users don't wait for this process.

It runs in the background.

---

# Real-Life Analogy

Imagine a bakery.

Instead of baking one loaf every minute,

the bakery prepares

10,000 loaves

overnight.

This is Batch Processing.

---

# Online vs Batch Inference

| Online | Batch |
|----------|---------|
| Immediate Response | Scheduled Processing |
| Low Latency | High Throughput |
| User Waiting | Offline Processing |
| ChatGPT | Recommendation Updates |

Most production AI platforms use both.

---

# CPU vs GPU

Traditional applications

primarily run on CPUs.

AI models typically run on GPUs.

Why?

---

# CPU

A CPU contains

a relatively small number

of powerful cores.

It excels at

- General Computing
- Operating Systems
- Databases
- Web Servers

---

# GPU

A GPU contains

thousands of smaller cores

capable of performing

many mathematical operations simultaneously.

Deep learning relies heavily on

matrix multiplication.

GPUs perform these operations extremely efficiently.

---

# Real-Life Analogy

Imagine moving

10,000 boxes.

One very strong worker

(CPU)

moves them

one after another.

A thousand workers

(GPU)

move many boxes simultaneously.

For parallel tasks,

the GPU wins.

---

# CPU vs GPU

| CPU | GPU |
|------|------|
| Few Powerful Cores | Thousands of Small Cores |
| General Purpose | Massive Parallelism |
| Databases | AI Models |
| Web Servers | Neural Networks |

---

# Why GPUs Are Essential

Transformer models perform billions of mathematical operations

for every request.

Without GPUs,

response times would become impractically slow.

This is why companies invest heavily in GPU clusters.

---

# Model Serving

A trained model is not useful

until applications can access it.

The infrastructure responsible for exposing models

is called

**Model Serving.**

---

# What is Model Serving?

Model Serving makes trained AI models available through APIs.

Instead of interacting directly with neural networks,

applications send requests to a serving layer.

---

# Architecture

```text
Application

↓

Inference API

↓

Model Server

↓

GPU

↓

Response
```

The model server manages

- Request Queues
- Batching
- GPU Scheduling
- Response Generation

---

# Real-Life Analogy

Imagine a restaurant.

Customers never enter the kitchen.

They interact with waiters.

The waiter delivers orders to the kitchen.

Model Serving behaves similarly.

Applications communicate

with the serving layer,

not directly with GPUs.

---

# TensorRT

Serving large models efficiently

requires optimization.

One popular optimization framework is

**TensorRT.**

---

# What is TensorRT?

TensorRT

developed by NVIDIA,

optimizes neural networks

for faster inference.

It reduces

- Latency
- Memory Usage
- GPU Computation

without significantly reducing accuracy.

---

# Real-Life Analogy

Imagine translating a book

into a shorter,

clearer version

without changing its meaning.

TensorRT optimizes models similarly.

---

# ONNX

Different AI frameworks

store models differently.

TensorFlow,

PyTorch,

MXNet

all use different formats.

This creates interoperability problems.

---

# What is ONNX?

ONNX

(Open Neural Network Exchange)

is a standard model format

allowing models

to move between frameworks.

---

# Real-Life Analogy

Imagine PDF files.

Regardless of which software created them,

any PDF reader can open them.

ONNX serves the same purpose for AI models.

---

# vLLM

Modern LLMs are extremely memory intensive.

Serving thousands of requests efficiently

requires specialized optimizations.

One popular solution is

**vLLM.**

---

# What is vLLM?

vLLM

is an optimized LLM inference engine

designed for high throughput.

Its key innovation is

**PagedAttention**,

which dramatically improves GPU memory utilization.

---

# Why vLLM?

Without optimization,

many GPU resources remain unused.

vLLM allows

more requests

to share GPU memory efficiently.

This increases

throughput

while reducing costs.

---

# Triton Inference Server

Production AI platforms

often serve

Managing this manually becomes difficult.

---

# What is Triton?

NVIDIA Triton Inference Server

for deploying AI models at scale.

It supports

- TensorFlow

- ONNX
- TensorRT
- Python Models

through a unified serving interface.

---

# Triton Architecture

```text
Clients

↓

Load Balancer

↓

Triton Server

↓

GPU Cluster

↓

Responses
```

- Scheduling
- Dynamic Batching
- Multiple Models
- GPU Allocation

automatically.

# Real-World Example

Imagine ChatGPT during a major product launch.

Millions of users submit prompts simultaneously.

The workflow looks like this.

1. A user's prompt reaches the API Gateway.
2. The Load Balancer selects an available inference server.
3. The inference server receives the request.
4. vLLM batches multiple compatible requests together.
5. TensorRT executes optimized inference on NVIDIA GPUs.
6. Generated tokens are streamed back to the user in real time.
7. Autoscaling launches additional inference servers if GPU utilization becomes too high.

Although the user simply sees text appearing on the screen,

an enormous distributed inference platform is working behind the scenes.

---

# Key Takeaways

- **Training** teaches AI models by updating parameters, while **Inference** uses trained models to generate predictions.
- Most production AI engineering focuses on optimizing **Inference**, not training.
- **Online Inference** serves real-time user requests, whereas **Batch Inference** processes large datasets offline.
- GPUs outperform CPUs for neural network workloads because they excel at parallel matrix computations.
- **Model Serving** exposes AI models through scalable APIs, managing requests, batching, and GPU scheduling.
- **TensorRT** optimizes NVIDIA models for faster and more efficient inference.
- **ONNX** provides a standardized model format that enables interoperability across AI frameworks.
- **vLLM** improves LLM serving efficiency using techniques like PagedAttention to maximize GPU utilization.
- **Triton Inference Server** is a production platform for serving multiple AI models across GPU clusters.
- AI systems rely on **Load Balancing** and **Autoscaling** to handle millions of concurrent requests while maintaining low latency.
