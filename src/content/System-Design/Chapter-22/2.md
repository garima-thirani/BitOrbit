# What is a Large Language Model?

A Large Language Model is a deep learning model trained on enormous amounts of text to understand and generate human language.

Instead of storing predefined answers,

an LLM learns statistical relationships between words, phrases, and concepts.

Its primary task is surprisingly simple.

> **Predict the next most likely token given all previous tokens.**

Everything from writing essays to generating code emerges from this single objective.

---

# Real-Life Analogy

Imagine reading a sentence.

```
The sun rises in the _____
```

Almost everyone predicts

```
east
```

without consciously thinking.

Your brain has learned language patterns from experience.

An LLM works similarly,

except it has learned from billions or even trillions of tokens.

---

# Why are they called "Large"?

The word **Large** refers to multiple aspects.

Large Models have

- Massive datasets
- Billions of parameters
- Huge computational requirements
- Large context windows

Examples

| Model | Approximate Parameters |
|---------|-----------------------|
| GPT-2 | 1.5 Billion |
| LLaMA 2 70B | 70 Billion |
| GPT-4 | Not Public |
| Claude | Not Public |
| Gemini | Not Public |

As models become larger,

they generally learn more complex language patterns.

# How LLMs Differ from Traditional Machine Learning

Traditional Machine Learning learns to predict labels.

Example

```
Email

↓

Spam?
```

Output

```
Yes
```

An LLM instead predicts language.

Example

```
Write a summary of this article.
```

Output

```
A newly generated summary.
```

The output isn't selected from predefined labels.

It is generated token by token.

---

# Traditional ML vs LLMs

| Traditional ML | Large Language Models |
|----------------|------------------------|
| Classification | Text Generation |
| Fixed Output | Dynamic Output |
| Structured Features | Natural Language |
| Labels | Tokens |
| Prediction | Generation |

# Transformer Architecture (High Level)

Modern LLMs are based on a neural network architecture called the **Transformer.**

The Transformer was introduced in the famous research paper

> **"Attention Is All You Need" (2017)**

Nearly every modern LLM,

including

- GPT
- Claude
- Gemini
- LLaMA
- Mistral

is built upon this architecture.

---

# Why Transformers?

Before Transformers,

language models processed words sequentially.

Imagine reading a book one word at a time without remembering the entire sentence.

Long-distance relationships between words were difficult to capture.

Transformers solved this problem using **Attention.**

---

# Real-Life Analogy

Imagine reading this sentence.

```
John gave his book to David because he had already finished reading it.
```

Who does **he** refer to?

Your brain looks at the entire sentence,

not just the previous word.

Transformers behave similarly.

They examine relationships between all words simultaneously.

---

# High-Level Transformer Architecture

```text
            Input Text
                 │
                 ▼
          Tokenization
                 │
                 ▼
        Token Embeddings
                 │
                 ▼
     Positional Encoding
                 │
                 ▼
   Multi-Head Self Attention
                 │
                 ▼
     Feed Forward Networks
                 │
                 ▼
     Multiple Transformer Layers
                 │
                 ▼
         Next Token Prediction
```

Don't worry about the mathematical details.

For system design,

understanding the data flow is sufficient.

---

# Self-Attention

The most important innovation in Transformers is

**Self-Attention.**

Attention allows every word to examine every other word in the sentence.

Instead of processing words independently,

the model learns

which words are important

for understanding meaning.

---

# Example

Consider

```
Apple released a new phone.
```

Here,

"Apple"

refers to the company.

Now consider

```
Apple is my favorite fruit.
```

The same word has a completely different meaning.

Attention helps the model determine the correct interpretation using surrounding context.

---

# Tokens

Humans think in words.

Computers do not.

Before text enters an LLM,

it must first be converted into **Tokens.**

---

# What is a Token?

A token is the smallest unit of text processed by an LLM.

Tokens may represent

- Entire words
- Partial words
- Characters
- Punctuation

---

# Example

Sentence

```
System Design is fun!
```

Possible Tokens

```text
System

Design

is

fun

!
```

Another tokenizer might split

```
Designing
```

into

```text
Design

ing
```

Different models use different tokenizers.

---

# Why Tokenization?

Neural networks operate on numbers,

not words.

Tokenization converts text into discrete units,

which are then mapped to numerical representations.

---

# Context Window

An LLM cannot remember an unlimited amount of information.

Every model has a **Context Window.**

---

# What is a Context Window?

A Context Window defines

the maximum number of tokens

an LLM can process at one time.

Everything outside this window

is forgotten.

---

# Real-Life Analogy

Imagine writing on a whiteboard.

Once the board is full,

you must erase old information

to continue writing.

The whiteboard represents the model's context window.

---

# Example

Suppose a model supports

```
8,000 Tokens
```

If a conversation exceeds this limit,

older messages may be removed

to make room for newer ones.

---

# Why Context Windows Matter

Larger context windows allow models to

- Analyze long documents
- Read entire codebases
- Summarize books
- Maintain long conversations

However,

larger context windows also require

more memory

and

more computation.

---

# Embeddings

Earlier,

we learned about Tokens.

However,

tokens are still text.

Neural networks require numbers.

This conversion happens through **Embeddings.**

---

# What are Embeddings?

Embeddings convert tokens into high-dimensional vectors.

These vectors capture semantic meaning.

Words with similar meanings

produce similar vectors.

---

# Real-Life Analogy

Imagine plotting cities on a map.

Cities that are geographically close

appear near each other.

Embeddings create a similar map,

except instead of geography,

they organize concepts by meaning.

---

# Example

Words like

```
Dog

Puppy

Canine
```

produce vectors close together.

Whereas

```
Dog

Database
```

produce vectors that are much farther apart.

This enables semantic understanding.

---

# Prompt Engineering

LLMs respond based on prompts.

The quality of the prompt

greatly influences the quality of the response.

This practice is called **Prompt Engineering.**

---

# What is Prompt Engineering?

Prompt Engineering is the process of designing effective prompts that guide the model toward better outputs.

---

# Example

Poor Prompt

```
Explain Kubernetes.
```

Better Prompt

```
Explain Kubernetes to a backend engineer with knowledge of Docker.
Include architecture diagrams and real-world examples.
```

The second prompt provides

clearer context,

resulting in a better response.

---

# Real-Life Analogy

Imagine asking a taxi driver

```
Take me somewhere nice.
```

versus

```
Take me to the nearest Italian restaurant within 10 minutes.
```

More context leads to better results.

---

# Model Parameters

Every LLM contains

millions or billions

of **Parameters.**

---

# What are Parameters?

Parameters are the learned numerical values

inside the neural network.

During training,

these values are continuously adjusted

until the model learns language patterns.

They represent the model's knowledge.

---

# Real-Life Analogy

Imagine learning to play the piano.

Years of practice modify your muscle memory.

Parameters represent the accumulated knowledge acquired during training.

---

# More Parameters ≠ Always Better

Larger models generally perform better,

but they also require

- More Memory
- More GPUs
- Higher Costs
- Longer Inference Time

Model size always involves trade-offs.

---

# Fine-Tuning vs Prompting

There are two primary ways to customize an LLM.

---

# Prompting

Prompting changes

only the input.

The model itself remains unchanged.

Example

```
Act as a senior software architect.
```

No retraining occurs.

---

# Fine-Tuning

Fine-Tuning updates

the model's parameters

using additional training data.

This permanently changes the model's behavior.

---

# Real-Life Analogy

Imagine hiring a chef.

Prompting is giving the chef new instructions for today's meal.

Fine-Tuning is sending the chef to culinary school for six months.

One changes instructions.

The other changes expertise.

---

# Prompting vs Fine-Tuning

| Prompting | Fine-Tuning |
|------------|-------------|
| Fast | Slow |
| Cheap | Expensive |
| Temporary | Permanent |
| No Retraining | Requires Training |
| Easy to Experiment | Specialized Models |

Today,

many production systems prefer

Prompting + RAG

instead of expensive Fine-Tuning.

# The LLM Inference Pipeline

Everything we've learned now comes together.

When a user submits a prompt,

the model performs a sequence of operations.

```text
User Prompt
      │
      ▼
Tokenization
      │
      ▼
Token IDs
      │
      ▼
Embeddings
      │
      ▼
Transformer Layers
(Self-Attention + Feed Forward)
      │
      ▼
Probability Distribution
      │
      ▼
Next Token Selection
      │
      ▼
Generated Token
      │
      ▼
Repeat Until Completion
```

Notice something interesting.

The model does **not**

generate an entire paragraph at once.

Instead,

it predicts

one token,

then the next,

then the next,

until the response is complete.

---

# Putting Everything Together

A simplified LLM architecture looks like this.

```text
                User Prompt
                     │
                     ▼
              Tokenization
                     │
                     ▼
              Token Embeddings
                     │
                     ▼
            Transformer Model
      (Self-Attention + Neural Layers)
                     │
                     ▼
         Probability Distribution
                     │
                     ▼
            Next Token Generated
                     │
                     ▼
         Repeat Until End of Response
                     │
                     ▼
             Final AI Response
```

This pipeline powers nearly every modern Large Language Model.

---

# Real-World Example

Imagine asking ChatGPT

```
Explain Redis.
```

The system

- Converts the prompt into tokens.
- Maps tokens into embeddings.
- Processes them through Transformer layers.
- Computes probabilities for the next token.
- Generates one token at a time.
- Repeats the process until the explanation is complete.

Although the response appears instantaneous,

the model is continuously predicting the next token throughout the generation process.

# Key Takeaways

- Large Language Models (LLMs) are deep learning models trained to predict the next token in a sequence.
- Modern LLMs are built on the **Transformer Architecture**, introduced in the "Attention Is All You Need" paper.
- **Self-Attention** enables models to understand relationships between words across an entire sequence.
- **Tokens** are the basic units processed by LLMs, and tokenization converts text into model-readable units.
- The **Context Window** defines how much information a model can consider during inference.
- **Embeddings** transform tokens into numerical vectors that capture semantic meaning.
- **Prompt Engineering** improves model responses by providing clearer instructions and context.
- **Model Parameters** store the knowledge learned during training and determine a model's capabilities.
- **Prompting** customizes model behavior through instructions, while **Fine-Tuning** permanently updates the model using additional training.
- During inference, an LLM generates responses **one token at a time** through repeated next-token prediction.
