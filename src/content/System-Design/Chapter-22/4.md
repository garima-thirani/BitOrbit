# Introduction

In the previous part, we learned how Vector Databases store embeddings and perform semantic search.

But another important question arises.

> **How does an AI model answer questions about information it was never trained on?**

Imagine a company with

- Internal Documentation
- Employee Handbooks
- Technical Specifications
- Support Tickets
- Product Manuals

None of this private information exists inside GPT or Claude.

Yet employees expect an AI assistant to answer questions about it.

This is exactly the problem Retrieval-Augmented Generation (RAG) solves.

Instead of forcing the AI model to memorize everything,

RAG allows it to retrieve relevant information when needed.

---

# Why Do We Need RAG?

Large Language Models have enormous knowledge,

but they have important limitations.

They

- Do not know your company's private data.
- Cannot continuously learn new information.
- May generate incorrect facts.
- Have fixed training cut-off dates.
- Cannot memorize every document ever written.

Suppose you ask

> "What is our company's vacation policy?"

The LLM has never seen your employee handbook.

Without external knowledge,

it cannot answer correctly.

---

# Real-Life Analogy

Imagine asking a lawyer

about a company's internal contract.

Even if the lawyer is highly experienced,

they will first retrieve the contract,

read it,

and then answer.

The lawyer doesn't memorize every legal document.

Similarly,

RAG allows an AI model to retrieve relevant documents before generating a response.

---

# What is Retrieval-Augmented Generation (RAG)?

Retrieval-Augmented Generation is an AI architecture that combines

- Information Retrieval
- Vector Databases
- Large Language Models

Instead of relying only on model memory,

the system retrieves relevant documents

and includes them in the prompt before inference.

---

# High-Level RAG Architecture

```text
               User Question
                      │
                      ▼
             Embedding Model
                      │
                      ▼
             Vector Database
                      │
          Retrieve Relevant Documents
                      │
                      ▼
          Prompt Construction
                      │
                      ▼
             Large Language Model
                      │
                      ▼
              Final Response
```

Notice something important.

The LLM

does not search.

The Vector Database performs retrieval.

The LLM performs reasoning and generation.

---

# Why is RAG Better than Fine-Tuning?

Suppose your documentation changes every day.

Should you retrain the LLM every morning?

Of course not.

Training large models

can take

- Days
- Weeks
- Millions of dollars

Instead,

RAG simply updates the vector database.

No model retraining is required.

---

# Prompting vs Fine-Tuning vs RAG

| Prompting | Fine-Tuning | RAG |
|------------|-------------|-----|
| Uses Existing Knowledge | Learns New Knowledge | Retrieves External Knowledge |
| No Training | Expensive Training | No Training Required |
| Limited Context | Permanent Changes | Dynamic Knowledge |
| Fast | Slow | Fast |

For most enterprise applications,

RAG is the preferred solution.

---

# The Complete RAG Pipeline

A production RAG system consists of two phases.

## Offline Phase

Knowledge is prepared before users ask questions.

## Online Phase

Knowledge is retrieved during inference.

---

# Offline Pipeline

```text
Documents

↓

Chunking

↓

Embeddings

↓

Vector Database
```

This happens once,

or whenever documents change.

---

# Online Pipeline

```text
User Query

↓

Embedding

↓

Similarity Search

↓

Relevant Documents

↓

Prompt Construction

↓

LLM

↓

Response
```

The retrieval process typically takes only a few milliseconds.

---

# Document Chunking

Large Language Models have limited context windows.

Imagine uploading

a 2,000-page textbook.

The entire book cannot fit into the model's context.

Instead,

the document must be divided into smaller pieces.

This process is called

**Chunking.**

---

# What is Document Chunking?

Chunking divides large documents

into smaller,

manageable sections

before generating embeddings.

---

# Example

Original Document

```text
Cloud Computing Guide

200 Pages
```

After Chunking

```text
Chunk 1

Introduction
```

```text
Chunk 2

Networking
```

```text
Chunk 3

Storage
```

```text
Chunk 4

Security
```

Each chunk receives its own embedding.

---

# Why Chunking Matters

Imagine asking

```
Explain Kubernetes Pods.
```

The AI only needs

the Kubernetes chapter,

not the entire book.

Smaller chunks improve

- Retrieval Speed
- Context Quality
- Embedding Accuracy

---

# Real-Life Analogy

Imagine a library.

Books are organized into chapters,

not treated as one enormous document.

Finding one chapter is much easier than searching the entire book.

---

# Embedding Generation

After chunking,

each chunk is converted into an embedding.

```text
Chunk

↓

Embedding Model

↓

Vector
```

These vectors are stored

inside the Vector Database.

---

# Example

Chunk

```
Redis is an in-memory cache.
```

Embedding

```text
[0.42, -0.13, 0.91, ...]
```

The AI never searches raw text.

It searches embeddings.

---

# Retrieval Layer

When a user asks a question,

the same embedding model converts the query into a vector.

The Vector Database performs

Similarity Search

and retrieves

the most relevant chunks.

---

# Example

User asks

```
How does Redis improve performance?
```

Retrieved Chunks

- Redis Architecture
- Cache Patterns
- Cache Invalidation

These become the context

for the LLM.

---

# Real-Life Analogy

Imagine searching a textbook.

You first locate

the relevant chapters,

then begin reading.

The Retrieval Layer behaves similarly.

---

# Re-ranking

Similarity Search isn't always perfect.

Suppose

20 relevant documents

are retrieved.

Some are more useful than others.

The system therefore performs

**Re-ranking.**

---

# What is Re-ranking?

Re-ranking evaluates retrieved documents

and sorts them

from most relevant

to least relevant.

Only the highest-ranked documents

are sent to the LLM.

---

# Example

Retrieved Documents

```text
Redis Basics

Score 0.82
```

```text
Redis Cluster

Score 0.95
```

```text
Memcached

Score 0.74
```

After Re-ranking

```text
1. Redis Cluster

2. Redis Basics

3. Memcached
```

The LLM receives

only the best context.

---

# Prompt Construction

The retrieved documents

must now be combined

with the user's question.

This process is called

**Prompt Construction.**

---

# Example Prompt

```text
Context

Redis is an in-memory distributed cache.

Redis Cluster partitions data across nodes.

Question

How does Redis improve application performance?
```

Notice that

the model receives

both

the user's question

and

the retrieved knowledge.

---

# Context Injection

Adding retrieved knowledge

into the prompt

is called

**Context Injection.**

Without context,

the model relies only on its training.

With context,

the model answers

using the retrieved documents.

---

# Real-Life Analogy

Imagine a student

taking an open-book exam.

Instead of answering from memory,

the student consults the textbook first.

Context Injection provides the AI with its textbook.

---

# Hallucination Reduction

One of the biggest challenges in AI systems is

**Hallucination.**

---

# What is a Hallucination?

A hallucination occurs when an LLM confidently generates information that is incorrect or fabricated.

Example

```
Who invented Kubernetes?
```

Without proper context,

the model may generate an incorrect answer.

---

# How RAG Reduces Hallucinations

Instead of relying on memory,

the model retrieves

verified documents

and answers using them.

Grounding the response in trusted knowledge

dramatically reduces hallucinations.

Notice that RAG reduces hallucinations,

but it does not eliminate them entirely.

---

# Hybrid Search

Keyword Search

and

Vector Search

both have strengths.

Many production systems combine them.

This approach is called

**Hybrid Search.**

---

# Example

User searches

```
Redis Sentinel configuration
```

Keyword Search

finds exact configuration terms.

Vector Search

finds semantically similar documentation.

The results are merged,

producing higher-quality retrieval.

---

# Metadata Filtering

Documents often contain metadata.

Examples

- Department
- Language
- Author
- Creation Date
- Access Level

Retrieval systems can filter results

using this metadata.

---

# Example

Suppose an employee asks

```
Vacation Policy
```

Filters

```text
Department

↓

Human Resources
```

```text
Language

↓

English
```

```text
Year

↓

2025
```

The Vector Database searches

only relevant documents.

This improves both speed

and accuracy.

# Real-World Example

Imagine Perplexity AI.

A user asks

> "What were the major announcements from Apple this week?"

Instead of relying solely on its pretrained knowledge,

the system

- Searches recent news articles.
- Converts them into embeddings.
- Retrieves the most relevant documents.
- Re-ranks the results.
- Constructs a prompt containing trusted sources.
- Sends the prompt to the LLM.
- Generates a summarized answer grounded in current information.

Because the response is based on retrieved documents,

it is significantly more accurate than relying only on the model's internal knowledge.

This same architecture powers

- Enterprise AI Assistants
- GitHub Copilot
- Customer Support Bots
- Internal Knowledge Bases
- Document Search Systems

# Key Takeaways

- Retrieval-Augmented Generation (RAG) combines Vector Databases with Large Language Models to provide grounded, up-to-date responses.
- RAG avoids expensive retraining by retrieving external knowledge at inference time.
- The RAG pipeline consists of document preparation (chunking, embeddings, indexing) and online retrieval (query embedding, similarity search, prompt construction, generation).
- Document Chunking divides large documents into smaller sections that can be embedded and retrieved efficiently.
- Embedding Generation converts both documents and user queries into vectors for semantic search.
- The Retrieval Layer finds the most relevant document chunks using vector similarity.
- Re-ranking improves retrieval quality by selecting the best candidate documents before generation.
- Prompt Construction and Context Injection provide the LLM with relevant information, enabling grounded responses.
- Hybrid Search combines keyword search with semantic vector search to improve retrieval accuracy.
- Metadata Filtering restricts searches to relevant subsets of data, improving both speed and precision.
- RAG significantly reduces hallucinations by grounding responses in retrieved knowledge, making it the foundation of most production AI applications today.
