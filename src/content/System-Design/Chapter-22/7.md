# From Chatbots to Agents

Think about ChatGPT.

You ask

```
Explain Kubernetes.
```

It generates an answer.

Conversation ends.

Now imagine asking

```
Find the cheapest flight to Tokyo next month,
compare three airlines,
book the best one,
and email me the itinerary.
```

A normal chatbot cannot complete this task.

It requires

- Planning
- Multiple Decisions
- External Tools
- Memory
- Execution

This is an AI Agent.

---

# What is an AI Agent?

An AI Agent is an AI system that can

- Understand goals
- Plan tasks
- Use external tools
- Make decisions
- Maintain memory
- Execute actions
- Adapt based on results

Unlike traditional chatbots,

agents are **goal-driven** rather than **prompt-driven**.

---

# Real-Life Analogy

Imagine hiring two people.

Person A

answers questions.

Person B

takes responsibility for completing tasks.

If you say

> "Plan my vacation."

Person A explains how vacations are planned.

Person B

- searches flights,
- compares hotels,
- creates an itinerary,
- books reservations,
- sends confirmation emails.

The second person behaves like an AI Agent.

---

# Chatbot vs AI Agent

| Chatbot | AI Agent |
|----------|-----------|
| Answers Questions | Completes Tasks |
| Single Prompt | Multi-Step Planning |
| No Actions | Executes Actions |
| No Tool Usage | Uses External Tools |
| Stateless | Uses Memory |
| Reactive | Goal-Oriented |

# AI Agent Architecture

Every AI Agent consists of several components.

```text
               User Goal
                    │
                    ▼
              Goal Understanding
                    │
                    ▼
                 Planning
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
      Memory     Tool Use   Reasoning
          │         │         │
          └─────────┼─────────┘
                    ▼
              Action Execution
                    │
                    ▼
             Observe Result
                    │
                    ▼
             Goal Completed
```

Unlike a chatbot,

an agent repeatedly

plans,

acts,

observes,

and improves.

---

# Planning

Planning is the most important capability of an AI Agent.

Instead of immediately generating a response,

the agent first determines

how to solve the problem.

---

# Example

User asks

```
Plan a three-day trip to Paris.
```

The agent might create a plan.

```
Step 1

Find flights

↓

Step 2

Compare hotels

↓

Step 3

Create itinerary

↓

Step 4

Estimate budget

↓

Step 5

Generate final report
```

Instead of one response,

the problem is decomposed into smaller tasks.

---

# Real-Life Analogy

Imagine building a house.

Nobody starts laying bricks immediately.

First,

an architect creates a blueprint.

Planning serves the same purpose.

---

# Agent Loop

Most AI Agents continuously execute

a reasoning loop.

```text
Think

↓

Plan

↓

Act

↓

Observe

↓

Repeat
```

This continues

until the goal is achieved.

# Memory

Humans remember previous experiences.

Agents also require memory.

Without memory,

every conversation starts from scratch.

---

# Types of Memory

AI Agents commonly use

- Short-Term Memory
- Long-Term Memory

---

# Short-Term Memory

Short-term memory stores

the current conversation

or task.

Example

```
User

"My favorite language is Python."
```

Later

```
Recommend Python libraries.
```

The agent remembers

the earlier conversation.

---

# Long-Term Memory

Long-term memory stores

information across multiple sessions.

Examples include

- User Preferences
- Past Conversations
- Frequently Used APIs
- Work History
- Project Knowledge

---

# Real-Life Analogy

Imagine your family doctor.

They remember

- Allergies
- Medical History
- Previous Treatments

This long-term knowledge

helps provide better care.

AI agents use memory similarly.

---

# Tool Calling

Large Language Models

cannot directly

- search Google,
- execute SQL,
- send emails,
- call REST APIs,
- run Python code.

Instead,

they request external tools.

---

# What is Tool Calling?

Tool Calling allows an LLM

to invoke external software

during reasoning.

---

# Example

User asks

```
What's the weather in Tokyo?
```

Instead of guessing,

the agent

calls

```
Weather API
```

receives live data,

then generates the answer.

---

# Real-Life Analogy

Imagine a financial advisor.

Instead of memorizing stock prices,

they open Bloomberg,

check live data,

then answer.

Tool Calling works exactly the same way.

---

# Function Calling

Function Calling

is a structured version

of Tool Calling.

Instead of producing plain text,

the LLM generates

structured function arguments.

---

# Example

User says

```
Book a meeting tomorrow at 3 PM.
```

The model generates

```json
createMeeting(
  date="Tomorrow",
  time="3 PM"
)
```

The application executes the function,

then returns the result.

The model decides **what** should happen.

The software decides **how** it happens.

# MCP (Model Context Protocol)

As AI ecosystems grow,

models need a standard way

to communicate

with external tools.

This led to

**Model Context Protocol (MCP).**

---

# What is MCP?

MCP is an open protocol

that standardizes

how AI models interact with

- Databases
- File Systems
- IDEs
- APIs
- Browsers
- Business Applications

Instead of creating custom integrations

for every tool,

applications expose capabilities

through a common interface.

---

# Real-Life Analogy

Think about USB.

Without USB,

every device

would require a unique connector.

USB standardized communication.

MCP aims to become

the equivalent standard

for AI tools.

---

# Real-World Example

Consider Cursor IDE.

A developer asks

> "Refactor this project to use dependency injection."

Cursor doesn't simply generate code.

Instead, it

1. Reads the project structure.
2. Builds an understanding of the codebase.
3. Searches relevant files.
4. Plans the required modifications.
5. Calls editing tools.
6. Updates multiple files.
7. Verifies the changes.
8. Explains what was modified.

This is far beyond traditional text generation.

It is an AI Agent performing a sequence of coordinated actions.

Similar architectures power

- GitHub Copilot Workspace
- Devin
- Claude Computer Use
- OpenAI Operator
- Enterprise AI Assistants

# Key Takeaways

- AI Agents are goal-oriented systems that plan, reason, use tools, maintain memory, and execute actions.
- Unlike traditional chatbots, agents can solve multi-step problems autonomously.
- Planning decomposes complex goals into manageable tasks before execution.
- Memory enables agents to retain context within a conversation and across multiple sessions.
- Tool Calling allows agents to interact with external systems such as APIs, databases, browsers, and code execution environments.
- Function Calling provides structured interfaces between LLMs and software applications.
- Multi-Agent Systems divide complex work among specialized agents coordinated through orchestration.
- Agent Orchestration manages task assignment, execution order, dependency resolution, and result aggregation.
- Model Context Protocol (MCP) standardizes how AI models communicate with tools and external systems.
- Modern AI products like Cursor, GitHub Copilot, Devin, Claude Computer Use, and OpenAI Operator rely heavily on agent architectures rather than standalone LLMs.
