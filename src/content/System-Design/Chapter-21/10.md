# Step 1 — Understand Requirements First

Never jump into architecture immediately.

Always clarify

- Functional Requirements
- Non-Functional Requirements
- Scale
- Latency
- Availability
- Consistency
- Budget
- Timeline

Remember Chapter 1.

Requirements always drive architecture.

---

# Step 2 — Choose the Right Database

Ask yourself

```text
Structured Data?

↓

SQL
```

```text
Flexible Schema?

↓

Document Database
```

```text
High Write Throughput?

↓

Wide Column Database
```

```text
Relationships?

↓

Graph Database
```

```text
Key Value Access?

↓

Redis / DynamoDB
```

Technology should follow data requirements.

---

# Step 3 — Decide Whether You Need a Cache

Ask

```text
Repeated Reads?

↓

Redis
```

```text
Frequently Accessed Data?

↓

Cache
```

```text
Read Heavy Workload?

↓

Cache + Read Replicas
```

Not every application requires Redis.

---

# Step 4 — Decide Whether Messaging is Required

Ask

```text
Can Users Wait?

↓

Yes

↓

Synchronous REST
```

```text
No

↓

Message Queue
```

Need Event Streaming?

↓

Kafka

Need Task Queue?

↓

RabbitMQ / SQS

| Requirement | Technology |
|-------------|------------|

# Step 7 — High Availability Checklist

Ask

- Multiple Availability Zones?
- Load Balancer?
- Database Replication?
- Backups?
- Health Checks?
- Auto Scaling?
- Disaster Recovery?

Never design a production system with a single point of failure.

---

# Step 8 — Security Checklist

Every production system should answer

- Who are you? (Authentication)
- What can you access? (Authorization)
- Is communication encrypted? (TLS)
- Are secrets protected? (Vault/KMS)
- Is least privilege enforced? (IAM/RBAC)
- Is the API protected? (WAF)

---

# Step 9 — Observability Checklist

Every production system should include

- Metrics
- Logs
- Traces
- Dashboards
- Alerts
- Correlation IDs
- SLOs

If you cannot observe a system,

you cannot reliably operate it.

---

# Step 10 — Deployment Checklist

Modern systems should support

- Automated Testing
- CI/CD
- Rolling Updates
- Canary Releases
- Rollbacks
- Feature Flags

Deployment should never require logging into production servers.

---

# Common Interview Mistakes

Avoid these mistakes

- Starting architecture before understanding requirements.
- Choosing technologies because they are popular.
- Ignoring scalability assumptions.
- Forgetting security.
- Forgetting monitoring.
- Ignoring failure scenarios.
- Overengineering simple systems.
- Not explaining trade-offs.

Interviewers care more about reasoning than memorization.

# Key Takeaways

- Architecture decisions should always be driven by requirements, not technology trends.
- Every production system should be scalable, secure, observable, and automatable.
- Think in terms of trade-offs rather than perfect solutions.
- Always justify *why* you selected a particular technology.
- Successful system design interviews reward structured thinking and clear communication more than memorizing individual tools.
