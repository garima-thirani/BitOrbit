Imagine sending a postcard.

Anyone handling the postcard can read the message.

# Transport Layer Security (TLS)

Whenever you visit

```
https://amazon.com
```

or

```
https://github.com
```

your browser establishes a secure connection.

This security protocol is called

**Transport Layer Security (TLS).**

---

# What is TLS?

TLS encrypts communication between two systems.

It provides

- Confidentiality
- Integrity
- Authentication

No one between the client and server can easily read or modify the data.

---

# Example

Without TLS

```text
Browser

↓

Internet

↓

Website
```

Every intermediate network could potentially inspect the data.

With TLS

```text
Browser

⇄ Encrypted Communication ⇄

Website
```

The transmitted information becomes unreadable to attackers.

---

# Real-Life Analogy

Imagine speaking to someone in a room full of people.

Everyone can hear your conversation.

Now imagine speaking inside a soundproof room.

Only the intended listener hears you.

TLS creates that soundproof room on the Internet.

---

# TLS Handshake

Before encrypted communication begins,

the client and server establish trust.

A simplified process looks like this.

```text
Client

↓

Hello

↓

Server

↓

Certificate

↓

Key Exchange

↓

Secure Session Established

↓

Encrypted Communication
```

This process happens automatically within milliseconds.

---

# Mutual TLS (mTLS)

TLS verifies

only the server.

But what if two backend services communicate?

Should they trust each other automatically?

No.

Both services should verify identities.

This is called

**Mutual TLS (mTLS).**

---

# What is mTLS?

Mutual TLS allows

both sides

to authenticate each other.

Instead of

```
Client → Server
```

only the server proving its identity,

both participants exchange certificates.

```text
Service A

⇄

Service B
```

Both authenticate.

Both encrypt.

---

# Real-Life Analogy

Imagine entering a secure military base.

Normally,

visitors show identification.

With mTLS,

both

- the visitor

and

- the security officer

verify each other's identity.

Trust works in both directions.

---

# TLS vs mTLS

| TLS | mTLS |
|------|------|
| Server Authentication | Mutual Authentication |
| Browser → Website | Service → Service |
| HTTPS | Zero Trust Networking |
| Common on Public Internet | Common in Microservices |

Earlier,

when we studied Service Mesh,

Istio automatically enabled mTLS between microservices.

This is one of its biggest advantages.

# Encryption

TLS encrypts communication,

but encryption is used far beyond networking.

Databases,

storage systems,

backups,

and cloud disks also encrypt data.

---

# What is Encryption?

Encryption converts readable information

(Plaintext)

into

unreadable information

(Ciphertext)

using an encryption key.

Only someone with the correct key can recover the original data.

---

# Example

Plaintext

```text
Password123
```

↓

Encryption

↓

Ciphertext

```text
7A91C4EFD...
```

Without the key,

the original message cannot be recovered.

---

# Real-Life Analogy

Imagine locking valuables inside a safe.

The safe represents encryption.

The key unlocks the original contents.

---

# Encryption Types

Modern systems generally use

### Symmetric Encryption

The same key encrypts and decrypts data.

Examples

- AES
- ChaCha20

Very fast.

Commonly used for

- Databases
- Files
- TLS Session Encryption

---

### Asymmetric Encryption

Uses

- Public Key
- Private Key

The public key encrypts.

Only the private key decrypts.

Examples

- RSA
- ECC

Widely used for

- TLS Handshakes
- Digital Certificates
- Digital Signatures

---

# Hashing

Hashing is often confused with encryption.

They solve different problems.

---

# What is Hashing?

Hashing converts input into a fixed-size output.

Unlike encryption,

hashing is

**one-way.**

The original value cannot realistically be recovered.

---

# Example

```text
Password123
```

↓

SHA-256

↓

```text
A5F38D...
```

Even a tiny change

produces an entirely different hash.

---

# Real-Life Analogy

Imagine putting fruit into a blender.

Once blended,

you cannot reconstruct the original apple or banana.

Hashing behaves similarly.

---

# Why Hash Passwords?

Suppose a database stores

```
Password123
```

in plain text.

If attackers steal the database,

they immediately know everyone's password.

Instead,

systems store

```
SHA-256(Password123)
```

or, preferably,

strong password hashes like

- bcrypt
- Argon2
- scrypt

Even administrators should never know user passwords.

---

# Encryption vs Hashing

| Encryption | Hashing |
|-------------|----------|
| Reversible | One-Way |
| Uses Keys | No Decryption Key |
| Protects Confidentiality | Verifies Integrity |
| Files, Databases | Password Storage |

A common interview mistake is confusing these two concepts.

Remember

Encryption protects data.

Hashing verifies data.

---

# Digital Signatures

Suppose Alice sends a contract to Bob.

How can Bob verify

- Alice really sent it?
- Nobody modified it?

This is solved using

**Digital Signatures.**

---

# What is a Digital Signature?

A Digital Signature proves

- Authenticity
- Integrity
- Non-Repudiation

It guarantees

- who sent the message
- that it wasn't modified

---

# Real-Life Analogy

Imagine signing a legal document.

Anyone can photocopy the document,

but only your signature proves authenticity.

Digital Signatures work the same way.

---

# Digital Signature Workflow

```text
Document

↓

Hash

↓

Private Key Signs Hash

↓

Signature

↓

Receiver Uses Public Key

↓

Verification
```

If even one character changes,

verification fails.

# Identity and Access Management (IAM)

Imagine a company with

- Developers
- Database Administrators
- Security Teams
- Interns

Should everyone receive Administrator privileges?

Absolutely not.

Cloud providers solve this using

**Identity and Access Management (IAM).**

---

# What is IAM?

IAM manages

- Users
- Roles
- Permissions
- Policies

It answers

> **Who can access which cloud resources?**

---

# Real-Life Analogy

Imagine a university.

Students,

Professors,

and Administrators

all enter the same campus.

Each group has different permissions.

IAM follows exactly the same principle.

---

# IAM Components

Typical IAM systems contain

- Users
- Groups
- Roles
- Policies

Policies define permissions.

Roles bundle permissions together.

Users assume roles.

---

# Example

```text
Developer

↓

Can Deploy Applications

Cannot Delete Databases
```

```text
Database Administrator

↓

Can Manage Databases

Cannot Modify Billing
```

Every user receives only the permissions they need.

This is called

**Least Privilege Access.**

# Secrets Management

Applications require sensitive credentials such as

- Database Passwords
- API Keys
- OAuth Secrets
- JWT Signing Keys
- TLS Certificates

Should these values be stored inside source code?

Absolutely not.

---

# The Problem

Imagine uploading

```text
AWS_SECRET_KEY
```

to GitHub.

Attackers immediately gain access to your cloud account.

Secrets must never be stored inside applications.

---

# What is Secrets Management?

Secrets Management securely stores,

rotates,

and distributes confidential credentials.

Applications retrieve secrets when needed.

Developers never hardcode them.

---

# Real-Life Analogy

Imagine a hotel.

Guests don't receive master keys to every room.

Instead,

the reception securely manages all keys.

Guests receive temporary access only when necessary.

Secrets Management works similarly.

---

# HashiCorp Vault

One of the most popular Secrets Management systems is

**HashiCorp Vault.**

---

# What is Vault?

Vault securely stores

- Passwords
- Certificates
- Tokens
- Encryption Keys
- Database Credentials

Applications request secrets dynamically.

Vault returns temporary credentials.

---

# Vault Workflow

```text
Application

↓

Vault

↓

Temporary Secret

↓

Database
```

Secrets remain centralized and secure.

---

# AWS Key Management Service (KMS)

Managing encryption keys manually is difficult.

Cloud providers therefore offer managed key services.

---

# What is AWS KMS?

AWS Key Management Service (KMS)

creates,

stores,

rotates,

and manages encryption keys.

Applications use these keys to encrypt

- S3 Objects
- RDS Databases
- EBS Volumes
- Secrets

without exposing the actual keys.

---

# Real-Life Analogy

Imagine a bank vault.

Customers store valuables.

The bank manages the master keys securely.

Customers never handle the vault mechanisms themselves.

KMS performs the same role for cloud encryption.

---

# Complete Security Architecture

A production cloud security architecture looks like this.

```text
                User
                  │
                  ▼
          Authentication
                  │
                  ▼
         OAuth / OIDC / JWT
                  │
                  ▼
          Authorization (IAM)
                  │
                  ▼
         Application Services
                  │
     ┌────────────┼─────────────┐
     ▼            ▼             ▼
  TLS/mTLS    Secrets       Encryption
                  │             │
                  ▼             ▼
             Vault / KMS     Databases
```

Each layer protects a different aspect of the system.

# Key Takeaways

- **TLS** encrypts communication between clients and servers, while **mTLS** authenticates both communicating parties and is widely used in microservice architectures.
- **Encryption** protects sensitive data by converting plaintext into ciphertext that can only be recovered using the correct key.
- **Hashing** is a one-way operation used primarily for integrity verification and secure password storage.
- **Digital Signatures** verify both the authenticity and integrity of data using public-key cryptography.
- **Identity and Access Management (IAM)** controls who can access cloud resources using users, roles, and policies.
- **Secrets Management** prevents sensitive credentials from being hardcoded into applications and enables secure secret distribution.
- **HashiCorp Vault** centralizes and securely manages passwords, certificates, API keys, and temporary credentials.
- **AWS KMS** provides managed encryption key generation, storage, rotation, and lifecycle management.
- Modern production systems combine **IAM, Vault, KMS, TLS, mTLS, Encryption, and Hashing** to build secure, enterprise-grade cloud architectures.
