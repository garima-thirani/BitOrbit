# What is Observability?

Observability is the ability to understand the internal state of a system by analyzing its outputs.

Those outputs include

- Metrics
- Logs
- Traces

Together,

they allow engineers to answer questions such as

- Why is latency increasing?
- Which service is failing?
- Where is the bottleneck?
- Which request caused the error?
- How can we fix it?

---

# Monitoring vs Observability

Although people often use these terms interchangeably,

they are different.

| Monitoring | Observability |
|------------|---------------|
| Detects problems | Explains problems |
| Predefined Dashboards | Explore Unknown Failures |
| Reactive | Investigative |
| Answers "What happened?" | Answers "Why did it happen?" |

Monitoring raises alarms.

Observability enables debugging.

---

# The Three Pillars of Observability

Modern observability is built upon three fundamental signals.

```text
            Observability

      ┌──────────┼──────────┐
      ▼          ▼          ▼

   Metrics      Logs      Traces
```

Each answers different questions.

Together,

they provide a complete picture of system behavior.

---

# Metrics

Metrics are numerical measurements collected over time.

Examples include

- CPU Usage
- Memory Usage
- Request Rate
- Response Time
- Error Rate
- Disk Usage

Metrics are lightweight

and continuously collected.

---

# Example

Imagine monitoring an API.

Every minute,

you record

| Time | CPU Usage |
|------|-----------|
| 10:00 | 20% |
| 10:01 | 24% |
| 10:02 | 31% |
| 10:03 | 65% |
| 10:04 | 92% |

The increasing CPU usage indicates rising system load.

---

# Real-Life Analogy

These measurements are metrics.

They summarize your health over time.

# Logs

Metrics summarize system behavior.

Logs explain individual events.

A log records

- What happened

# Traces

Modern applications consist of many microservices.

A single user request may travel through

- API Gateway
- User Service
- Payment Service
- Notification Service
- Database

Understanding this journey is difficult.

This is where Traces become valuable.

---

# What is a Trace?

A Trace follows a single request

as it moves through an entire distributed system.

Instead of observing one service,

it observes

the complete request lifecycle.

---

# Real-Life Analogy

Imagine ordering food online.

The order progresses through

Restaurant

↓

Kitchen

↓

Delivery Partner

↓

Customer

Tracking the complete journey helps identify delays.

Distributed Tracing follows the same idea.

---

# Example Trace

```text
User Request

↓

API Gateway

15 ms

↓

User Service

10 ms

↓

Payment Service

220 ms

↓

Database

180 ms

↓

Response
```

Immediately,

we can identify

the Payment Service as the bottleneck.

---

# Metrics vs Logs vs Traces

Each signal answers different questions.

| Signal | Purpose |
|----------|----------|
| Metrics | Overall Health |
| Logs | Individual Events |
| Traces | Request Journey |

Imagine an application slowdown.

Metrics reveal

CPU increased.

Logs reveal

database timeout errors.

Traces reveal

which service caused the delay.

Together,

they explain the complete problem.

# Prometheus

Collecting metrics manually is impossible.

Production systems require automated monitoring.

One of the most popular monitoring systems is

**Prometheus.**

---

# What is Prometheus?

Prometheus is an open-source monitoring system.

It periodically collects metrics

from applications

and stores them in a time-series database.

---

# How Prometheus Works

```text
Application

↓

Metrics Endpoint

↓

Prometheus

↓

Time-Series Database
```

Prometheus repeatedly "scrapes"

application metrics.

---

# Example Metrics

```text
cpu_usage

memory_usage

http_requests_total

http_request_duration

database_connections
```

These values are continuously collected.

---

# Prometheus Pull Model

Unlike many monitoring tools,

Prometheus follows a

**Pull Model.**

```text
Prometheus

↓

Requests Metrics

↓

Application
```

The application doesn't push data.

Prometheus periodically collects it.

---

# Why Prometheus?

Prometheus is widely adopted because it provides

- High Performance
- Flexible Query Language (PromQL)
- Alerting Integration
- Kubernetes Support
- Time-Series Storage

It has become the industry standard for cloud-native monitoring.

Imagine Uber.

A rider requests a trip.

- API Gateway

# Key Takeaways

- **Observability** is the ability to understand a system's internal state using its outputs.
- Monitoring detects problems, while Observability explains their root causes.
- The three pillars of observability are **Metrics**, **Logs**, and **Traces**.
- **Metrics** provide numerical measurements that summarize system health.
- **Logs** record individual events and errors that occur within applications.
- **Traces** follow requests as they travel across distributed systems, making bottlenecks easy to identify.
- **Prometheus** is the industry-standard monitoring system for collecting and storing time-series metrics.
- **Grafana** visualizes metrics through dashboards, helping engineers quickly identify production issues.
- Modern cloud-native systems combine Metrics, Logs, and Traces to achieve complete operational visibility.
