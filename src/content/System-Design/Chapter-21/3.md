# Introduction

In the previous part, we designed a secure cloud network using

- VPCs
- Subnets
- Internet Gateways
- NAT Gateways
- Load Balancers

But a network by itself does nothing.

We now need resources that actually run our applications.

Questions naturally arise.

- Where does our application execute?
- Where do we store files?
- Where does our database run?
- How do we scale automatically?
- How do we recover from failures?

Cloud providers answer these questions through managed services.

Instead of building everything from scratch,

developers use ready-made infrastructure services.

---

# Why Managed Services Exist

Imagine launching an e-commerce website.

Without managed services,

you would need to manually

- Buy servers
- Install operating systems
- Configure databases
- Set up storage
- Create backups
- Monitor hardware
- Replace failed disks

This work has nothing to do with your business.

You want to sell products,

not maintain infrastructure.

Cloud providers automate these operational tasks.

---

# Real-Life Analogy

Imagine opening a coffee shop.

You could

- Build the building
- Install plumbing
- Generate electricity
- Construct furniture

Or,

you could rent a fully equipped commercial space.

You simply bring your coffee machines and start serving customers.

Managed services work exactly the same way.

---

# Cloud Compute

Every application eventually needs a computer to execute its code.

Cloud providers offer multiple ways to run applications.

The two most common approaches are

- Virtual Machines
- Serverless Computing

---

# Amazon EC2

The most fundamental compute service in AWS is

**Amazon Elastic Compute Cloud (EC2).**

---

# What is EC2?

EC2 is a virtual machine running inside AWS.

Instead of purchasing a physical server,

you launch a virtual server within minutes.

You choose

- CPU
- Memory
- Storage
- Operating System

AWS provisions the machine automatically.

---

# Real-Life Analogy

Imagine renting an apartment.

You choose

- Number of bedrooms
- Floor
- Location

The building already exists.

You simply move in.

EC2 works similarly.

You rent virtual servers instead of buying physical hardware.

---

# Typical Use Cases

EC2 is commonly used for

- Web Servers
- Backend APIs
- Machine Learning
- Batch Processing
- Game Servers
- Enterprise Applications

Whenever you need complete control over the operating system,

EC2 is a strong choice.

---

# EC2 Architecture

```text
Application

↓

Operating System

↓

EC2 Instance

↓

AWS Infrastructure
```

Developers manage

- Operating System
- Application
- Dependencies

AWS manages

- Hardware
- Networking
- Data Centers

---

# Auto Scaling

Imagine your application normally serves

```
1,000 Users
```

Suddenly,

a marketing campaign brings

```
500,000 Users.
```

Should engineers manually create hundreds of EC2 instances?

That would be far too slow.

Cloud providers solve this using **Auto Scaling.**

---

# What is Auto Scaling?

Auto Scaling automatically increases or decreases the number of compute instances based on demand.

Example

```text
Morning

↓

2 EC2 Instances
```

```text
Peak Hours

↓

20 EC2 Instances
```

```text
Late Night

↓

2 EC2 Instances
```

Resources grow and shrink automatically.

---

# Real-Life Analogy

Imagine a supermarket.

During weekends,

additional checkout counters open.

Late at night,

only one counter remains.

The supermarket adjusts its resources based on customer demand.

Auto Scaling follows the same principle.

---

# Auto Scaling Workflow

```text
Traffic Increases

↓

CPU Utilization Rises

↓

Auto Scaling Policy Triggered

↓

New EC2 Instances Created

↓

Load Balancer Distributes Traffic
```

When demand decreases,

unused instances are terminated automatically.

---

# AWS Lambda

Not every application requires permanent servers.

Suppose you want to

- Resize uploaded images
- Process payments
- Send emails
- Generate PDFs

These tasks execute only when an event occurs.

Running dedicated servers would waste resources.

---

# What is AWS Lambda?

AWS Lambda is a **serverless compute service.**

Instead of managing servers,

developers upload code.

AWS executes that code whenever an event occurs.

You never manage infrastructure.

---

# Real-Life Analogy

Imagine hiring a taxi.

You don't purchase the vehicle.

You simply request transportation when needed.

When the journey ends,

the taxi leaves.

Lambda works the same way.

Servers exist only while code is executing.

---

# Lambda Architecture

```text
Event

↓

Lambda Function

↓

Business Logic

↓

Response
```

No server management is required.

---

# Common Lambda Use Cases

Lambda is widely used for

- File Processing
- Notifications
- API Backends
- Image Processing
- Scheduled Tasks
- Event Processing

---

# EC2 vs Lambda

| EC2 | Lambda |
|------|---------|
| Virtual Machine | Serverless Function |
| Always Running | Runs on Demand |
| Full OS Control | No Server Management |
| Suitable for Long-running Applications | Suitable for Event-driven Workloads |

Both services have important roles in cloud architecture.

---

# Amazon S3

Applications generate enormous amounts of files.

Examples include

- Images
- Videos
- PDFs
- Documents
- Backups
- Logs

Traditional file systems become difficult to manage at scale.

Cloud providers solve this using Object Storage.

---

# What is Amazon S3?

Amazon Simple Storage Service (S3)

is highly durable object storage.

Unlike a traditional file system,

S3 stores objects inside buckets.

Examples

- Profile Photos
- Product Images
- Video Files
- Backups
- Machine Learning Models

---

# Real-Life Analogy

Imagine a massive warehouse.

Instead of organizing products by shelves,

every package receives a unique identifier.

Workers retrieve packages using that identifier.

S3 stores objects in a similar manner.

---

# S3 Characteristics

S3 provides

- High Durability
- Massive Scalability
- Versioning
- Lifecycle Policies
- Encryption
- Global Accessibility

Many organizations store petabytes of data in S3.

---

# Amazon RDS

Applications also require databases.

Instead of installing PostgreSQL manually,

AWS offers

**Amazon Relational Database Service (RDS).**

---

# What is RDS?

RDS is a managed relational database service.

AWS automatically handles

- Installation
- Patching
- Backups
- Monitoring
- Replication
- Failover

Developers simply use the database.

---

# Real-Life Analogy

Imagine renting an apartment with maintenance included.

If plumbing fails,

the landlord fixes it.

You don't repair the building yourself.

RDS follows the same philosophy.

---

# Supported Databases

RDS supports

- PostgreSQL
- MySQL
- MariaDB
- Oracle
- SQL Server

All managed by AWS.

---

# Amazon ElastiCache

Databases are often too slow for frequently accessed data.

Earlier in this handbook,

we learned about Redis.

AWS provides a managed Redis service called

**ElastiCache.**

---

# What is ElastiCache?

ElastiCache is a managed in-memory caching service.

It supports

- Redis
- Memcached

without requiring engineers to manage cache servers.

---

# Typical Use Cases

- Session Storage
- Leaderboards
- API Response Caching
- Shopping Cart Data
- Frequently Accessed Records

---

# Terraform

Imagine deploying

- EC2
- VPC
- RDS
- S3
- Load Balancers

manually every time.

Human errors become inevitable.

Infrastructure should be automated.

---

# What is Terraform?

Terraform is an **Infrastructure as Code (IaC)** tool.

Instead of manually creating cloud resources,

developers describe infrastructure using configuration files.

Terraform provisions everything automatically.

---

# Real-Life Analogy

Imagine an architect.

Instead of building every house manually,

they create blueprints.

Construction teams build identical houses from those blueprints.

Terraform treats infrastructure as blueprints.

---

# Terraform Workflow

```text
Terraform Configuration

↓

Terraform Plan

↓

Cloud Provider

↓

Infrastructure Created
```

Everything becomes

- Repeatable
- Version Controlled
- Automated

---

# Multi-Region Architecture

Earlier,

we learned about Regions.

Most applications begin in a single Region.

However,

large organizations often deploy across multiple Regions.

---

# Why Multiple Regions?

Benefits include

- Lower Latency
- Disaster Recovery
- Regulatory Compliance
- Global Availability

Users connect to the nearest Region,

reducing response times.

---

# Real-Life Analogy

Imagine an international bank.

Instead of one headquarters,

it operates branches across

- New York
- London
- Singapore
- Sydney

Customers visit the nearest branch.

Cloud applications follow the same strategy.

---

# Multi-Region Architecture

```text
Users

↓

Nearest Region

↓

Regional Load Balancer

↓

Application

↓

Regional Database
```

Each Region can operate independently.

---

# Disaster Recovery

Even cloud providers occasionally experience failures.

Applications must prepare for

- Region Failure
- Data Corruption
- Human Error
- Cyberattacks

This is the purpose of Disaster Recovery.

---

# Disaster Recovery Strategies

Common strategies include

- Automated Backups
- Cross-Region Replication
- Infrastructure as Code
- Database Snapshots
- Failover Mechanisms

Production systems regularly test these recovery procedures.

# Real-World Example

Imagine Instagram.

When a user uploads a photo,

the request flows through

```text
User

↓

Load Balancer

↓

Auto Scaled EC2 Backend

↓

Lambda Creates Thumbnails

↓

S3 Stores Images

↓

RDS Stores Metadata

↓

ElastiCache Stores Popular Posts
```

Meanwhile,

Terraform manages the infrastructure,

Auto Scaling handles traffic spikes,

and backups are replicated across Regions for disaster recovery.

# Key Takeaways

- **EC2** provides virtual machines with full operating system control, making it suitable for traditional applications and long-running workloads.
- **Auto Scaling** automatically adjusts the number of compute instances based on application demand, balancing performance and cost.
- **AWS Lambda** enables serverless computing by executing code only when events occur, eliminating server management.
- **Amazon S3** provides highly durable, scalable object storage for files, backups, media, and logs.
- **Amazon RDS** simplifies relational database management by automating backups, maintenance, replication, and failover.
- **Amazon ElastiCache** offers managed Redis and Memcached services to improve application performance through in-memory caching.
- **Terraform** treats infrastructure as code, enabling automated, repeatable, and version-controlled cloud provisioning.
- **Multi-Region deployments** improve global performance, availability, and disaster recovery by distributing workloads geographically.
- **Disaster Recovery** ensures applications can recover from catastrophic failures through backups, replication, failover, and infrastructure automation.
