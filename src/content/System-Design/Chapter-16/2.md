# Engineering Notes

## Events Represent Facts

An event

describes

something

that has

already happened.

It should

never express

what another service

must do.

This distinction

keeps

systems

loosely coupled

and allows

new subscribers

to be added

without changing

existing producers.

---

## Pub/Sub Encourages Independent Evolution

One of the

greatest strengths

of Pub/Sub

is that

services

can evolve

independently.

A publisher

may never know

how many

subscribers exist,

and subscribers

can be deployed,

updated,

or removed

without modifying

the publisher.

# Interview Questions & Solutions

## Question 1

### Question

What is the difference between a queue and Pub/Sub?

### Ideal Answer

A queue distributes each message to a single consumer, making it suitable for task processing. Pub/Sub broadcasts each event to all interested subscribers, making it ideal for event distribution across multiple independent services.

---

## Question 2

### Question

Why is Pub/Sub commonly used in microservices?

### Ideal Answer

Pub/Sub decouples producers from consumers. Publishers only emit events, while subscribers independently process those events. This allows services to scale, evolve, and fail independently without affecting one another.

---

## Question 3

### Question

Why should events be immutable?

### Ideal Answer

Events represent historical facts. Changing previously published events can produce inconsistent system behavior. If information changes, a new event should be published rather than modifying an old one.

---

## Question 4

### Question

What is the fan-out pattern?

### Ideal Answer

The fan-out pattern allows a single published event to be delivered to multiple subscribers simultaneously. Each subscriber processes its own copy independently.

---

## Question 5 (FAANG)

### Question

Design an event-driven architecture for a global e-commerce platform.

### Ideal Answer

The Order Service publishes an `OrderPlaced` event to an event bus. Independent services such as Payment, Inventory, Shipping, Notifications, Analytics, Fraud Detection, and Recommendations subscribe to the Orders topic. Each service processes events independently, supports retries, scales horizontally, maintains idempotent consumers, monitors subscriber lag, and uses versioned immutable event schemas for long-term compatibility.

# Revision Notes

- Publish–Subscribe enables one publisher to broadcast events to multiple independent subscribers.
- Topics organize related events.
- Publishers do not know who subscribes to their events.
- Subscribers independently process event copies.
- Event-driven architectures reduce coupling between services.
- Events should be immutable and versioned over time.
- Monitoring subscriber lag, throughput, and delivery failures is critical in production.
