# Engineering Notes

## Event Streams Never End

Unlike

event streams

are effectively

This means

Instead,

---

## Time Is More Complex Than It Appears

Distributed systems

clock differences,

Using

and windowing

to produce

# Interview Questions & Solutions

## Question 1

### Question

What is the difference between batch processing and stream processing?

### Ideal Answer

Batch processing collects data and processes it periodically, making it suitable for offline analytics and reports. Stream processing handles events continuously as they arrive, enabling low-latency applications such as fraud detection, monitoring, and recommendation systems.

---

## Question 2

### Question

Why is event time preferred over processing time?

### Ideal Answer

Event time reflects when an event actually occurred, whereas processing time reflects when it was processed. Event time produces more accurate results when network delays or out-of-order events occur.

---

## Question 3

### Question

What is windowing in stream processing?

### Ideal Answer

Windowing divides an infinite event stream into finite groups for processing. Common window types include tumbling windows for fixed intervals, sliding windows for overlapping analysis, and session windows for grouping user activity.

---

## Question 4

### Question

Why are watermarks necessary?

### Ideal Answer

Watermarks define how long the system should wait for late-arriving events before finalizing a window. They balance result accuracy against processing latency.

---

## Question 5 (FAANG)

### Question

Design a real-time fraud detection pipeline for a global payment platform.

### Ideal Answer

Use Kafka as the event ingestion layer, Apache Flink for stateful stream processing, event-time semantics with watermarks to handle delayed transactions, session windows for user activity analysis, checkpointing for fault recovery, replicated Kafka clusters for durability, Redis for low-latency lookups, and dashboards for live monitoring. Scale processing horizontally and monitor backpressure, checkpoint duration, and processing latency.

# Revision Notes

- Stream processing continuously processes events with very low latency.
- Kafka Streams is a lightweight stream processing library for Kafka, while Apache Flink is a distributed stream processing engine.
- Stateful processing maintains information across events, enabling advanced analytics and fraud detection.
- Event time provides more accurate results than processing time when events arrive late.
- Windowing enables infinite streams to be processed in finite groups.
- Watermarks manage late events before windows are finalized.
- Checkpointing enables fault recovery without losing processing progress.
