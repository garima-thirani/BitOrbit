# Interview Questions & Solutions

## Question 1

### Question

Why does RabbitMQ use exchanges instead of sending messages directly to queues?

### Ideal Answer

Exchanges separate message routing from message storage. Producers send messages to exchanges, which use routing rules to deliver messages to one or more queues. This provides flexibility, supports multiple routing patterns, and keeps producers loosely coupled from consumers.

---

## Question 2

### Question

What is the difference between Amazon SQS Standard and FIFO queues?

### Ideal Answer

Standard queues provide nearly unlimited throughput with at-least-once delivery and best-effort ordering. FIFO queues guarantee message ordering and support deduplication but have lower throughput, making them suitable for financial and order-processing systems.

---

## Question 3

### Question

Why are Dead Letter Queues important?

### Ideal Answer

Dead Letter Queues isolate messages that repeatedly fail processing, preventing infinite retry loops and allowing engineers to inspect and resolve problematic messages without affecting normal traffic.

---

## Question 4

### Question

When should RabbitMQ be preferred over Kafka?

### Ideal Answer

RabbitMQ is better suited for task queues, request-response workflows, complex routing, and low-latency message delivery where event replay is not required.

---

## Question 5 (FAANG)

### Question

Design the messaging infrastructure for a global e-commerce platform.

### Ideal Answer

Use Kafka for event streaming such as analytics, recommendation pipelines, and audit logs. Use RabbitMQ for workflow-driven tasks including email notifications, payment processing, and order fulfillment. Use Amazon SQS for AWS-native microservices where operational simplicity is preferred. Configure acknowledgments, retries, visibility timeouts, dead-letter queues, monitoring, and idempotent consumers to ensure reliable processing under high load.

# Revision Notes

- RabbitMQ is a message broker optimized for flexible message routing using exchanges.
- Exchanges route messages to queues through bindings and routing keys.
- Amazon SQS is a fully managed cloud messaging service.
- Standard SQS queues maximize throughput, while FIFO queues guarantee ordering.
- Visibility timeouts prevent multiple consumers from processing the same message simultaneously.
- Dead Letter Queues isolate repeatedly failing messages for later inspection.
- Kafka, RabbitMQ, and SQS complement one another and are often used together in large distributed systems.
