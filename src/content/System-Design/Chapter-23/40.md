# Detecting File Changes

Dropbox continuously watches the local file system.

Whenever a file changes:

```text
File Modified

↓

Filesystem Event

↓

Sync Client

↓

Upload
```

Modern operating systems provide filesystem notifications such as:

- inotify (Linux)
- FSEvents (macOS)
- ReadDirectoryChangesW (Windows)

These are more efficient than repeatedly scanning directories.

---

# Synchronization Cycle

Every device repeatedly performs:

```text
Detect Changes

↓

Upload Changes

↓

Check Server

↓

Download Updates

↓

Repeat
```

This creates continuous synchronization.

---

# Metadata First

Synchronization begins with metadata.

Example:

```text
Filename

Version

Timestamp

Hash
```

The client first compares metadata.

Only if differences exist

does it download file blocks.

---

# Why Metadata First?

Imagine a

```text
5 GB
```

video.

Comparing hashes is much faster than downloading gigabytes of data.

Metadata acts as a lightweight synchronization layer.

---

# Push vs Pull Synchronization

There are two approaches.

## Polling

```text
Client

↓

Server

↓

Any Changes?

↓

Repeat
```

Simple,

but wasteful.

---

## Push Notifications

```text
File Updated

↓

Server

↓

Push Notification

↓

Client Downloads Changes
```

Much more efficient.

Dropbox primarily uses push notifications combined with periodic synchronization checks.

# Conflict Resolution

Now consider the hardest problem.

Suppose:

Alice edits

```text
budget.xlsx
```

on her laptop.

At the same time,

she edits the same file

on her desktop.

Which version wins?

---

# Why Conflicts Occur

Example:

```text
Laptop

↓

Version A

------------------

Desktop

↓

Version B
```

Both versions are valid.

Automatically overwriting one version could destroy user data.

---

# Dropbox's Strategy

Instead of choosing one version,

Dropbox preserves both.

Example:

```text
budget.xlsx

budget (Alice's conflicted copy).xlsx
```

The user manually resolves the conflict.

---

# Why Not Merge Automatically?

For plain text,

automatic merging may be possible.

For:

- Excel files
- Photoshop files
- Videos
- Databases

automatic merging is often impossible.

Creating a conflicted copy is safer than corrupting data.

---

# High Availability

Synchronization services are stateless.

```text

↓
```

---

# Failure Recovery

Suppose an upload server crashes.

Since uploads are chunked,

only unfinished chunks are retried.

```text
Chunk 1 ✓

Chunk 2 ✓

Chunk 3 ✗

↓

Retry Chunk 3
```

The entire file does not restart.

# Trade-offs

## Chunking

Advantages:

- Parallel uploads
- Resume support

Disadvantages:

- Additional metadata

---

## Delta Sync

Advantages:

- Lower bandwidth
- Faster synchronization

Disadvantages:

- More complex synchronization logic

---

## Deduplication

Advantages:

- Lower storage cost

Disadvantages:

- Hash computation overhead

---

## Push Notifications

Advantages:

- Fast synchronization

Disadvantages:

- Requires persistent connections

---

## Conflict Copies

Advantages:

- Prevents data loss

Disadvantages:

- Requires manual resolution

# Common Interview Questions

---

## Why Chunk Files?

To support:

- Parallel uploads
- Resume after failures
- Efficient Delta Sync

---

## Why Delta Sync?

Uploading only modified chunks minimizes bandwidth usage and improves synchronization speed.

---

## Why Separate Metadata?

Metadata changes frequently,

while file contents remain unchanged.

Separating them enables independent scaling.

---

## Why Store Chunks Instead of Whole Files?

Chunks enable:

- Deduplication
- Parallel transfer
- Incremental synchronization
- Efficient storage

---

## How Does Dropbox Handle Conflicts?

Rather than overwriting data,

Dropbox creates a conflicted copy,

allowing users to manually reconcile changes.

---

# Real-World Example

Imagine four offices sharing a filing cabinet.

Whenever someone updates a document,

only the modified pages are photocopied and sent to the other offices.

If two offices edit the same page simultaneously,

both copies are preserved until someone decides how to merge them.

Dropbox follows the same principle:

synchronize only the changes,

never risk silently losing user data.

# Key Takeaways

- Dropbox synchronizes files by comparing metadata before transferring data blocks.
- Files are divided into chunks to support resumable, parallel uploads and efficient Delta Sync.
- Push notifications allow other devices to synchronize changes quickly without constant polling.
- Conflict resolution prioritizes data preservation by creating conflicted copies instead of overwriting user edits.
- Metadata and file contents are stored separately, enabling independent scaling and efficient synchronization.
- Multi-region replication, object storage, monitoring, and stateless synchronization services provide high availability and durability.
- Dropbox demonstrates how distributed storage, synchronization, and efficient bandwidth utilization combine to create a seamless multi-device experience.
