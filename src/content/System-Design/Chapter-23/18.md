# Step 5 — Explain Persistent Connections

One of the first questions interviewers ask:

> **Why WebSockets instead of HTTP?**

Answer:

HTTP opens and closes a connection for every request.

Messaging applications exchange thousands of small messages.

Keeping one connection open eliminates repeated connection setup.

---

# HTTP vs WebSocket

```text
HTTP

Request

↓

Response

↓

Closed
```

```text
WebSocket

Open

↓

Message

↓

Message

↓

Message

↓

Still Open
```

Persistent communication dramatically reduces latency.

# Step 6 — Explain Message Routing

Messages follow this path.

```text
Alice

↓

Connection Server

↓

Message Service

↓

Presence Lookup

↓

Bob's Server

↓

Bob
```

The sender never communicates directly with the recipient.

Everything passes through WhatsApp's infrastructure.

---

# Step 7 — Explain Redis

Redis stores rapidly changing data.

Examples:

- Online users
- Last Seen
- Typing status
- Active sessions

Question:

Why not store this in PostgreSQL?

Because presence information changes millions of times every second.

Redis is optimized for this workload.

---

# Step 8 — Explain Offline Messaging

Suppose Bob is offline.

The system stores messages.

```text
Alice

↓

Database

↓

Pending Queue

↓

Bob Connects

↓

Deliver
```

Offline messaging greatly improves reliability.

---

# Step 9 — Explain End-to-End Encryption

Interviewers frequently ask:

> **Can WhatsApp read your messages?**

Answer:

No.

The message is encrypted on Alice's device,

forwarded unchanged,

and decrypted only on Bob's device.

```text
Alice

↓

Encrypt

↓

Server

↓

Forward

↓

Bob

↓

Decrypt
```

Servers transport ciphertext only.

---

# Step 10 — Explain Media Sharing

Never send large files through chat servers.

Instead:

```text
Upload Media

↓

Object Storage

↓

Generate Secure URL

↓

Send URL

↓

Receiver Downloads
```

This dramatically reduces load on messaging infrastructure.

---

# Step 11 — Explain Kafka

Uploading media or sending messages generates events.

Instead of directly invoking:

- Notifications
- Analytics
- Monitoring

publish an event.

```text
Message

↓

Kafka

↓

Consumers
```

Benefits:

- Loose coupling
- Independent scaling
- Retry capability

# Common Interview Questions

---

## Why WebSockets?

Because messaging requires:

- Low latency
- Bidirectional communication
- Persistent connections

HTTP is inefficient for this pattern.

---

## Why Redis?

Presence changes constantly.

Redis provides:

- Fast lookups
- Low latency
- High throughput

Perfect for session state.

---

## Why Kafka?

Because one message triggers multiple downstream systems.

Instead of synchronous calls,

Kafka distributes events asynchronously.

---

## Why Object Storage?

Videos and images can be hundreds of megabytes.

Object storage is cheaper,

more scalable,

and highly durable.

---

## How Do Offline Messages Work?

Store them.

Deliver after reconnection.

Simple,

reliable,

fault tolerant.

---

## How Do Read Receipts Work?

Recipient opens chat.

```text
Read Event

↓

Server

↓

Sender

↓

Blue Ticks
```

---

## How Do You Prevent Duplicate Messages?

Every message has a unique identifier.

```text
Message ID

↓

Already Processed?

↓

Ignore Duplicate
```

This makes delivery idempotent.

---

## How Do You Preserve Ordering?

Assign sequence numbers.

Example:

```text
101

102

103
```

Recipients display messages in sequence order.

---

## How Would You Scale Group Chats?

Instead of sending directly,

publish delivery tasks.

```text
Group Message

↓

Queue

↓

Workers

↓

Recipients
```

Workers scale horizontally.

# Alternative Architectures

---

## HTTP Polling

```text
Client

↓

Request

↓

Any Messages?
```

Advantages:

- Simple

Disadvantages:

- High latency
- Wasted requests

---

## Long Polling

Connection stays open.

Improvement over polling,

but still less efficient than WebSockets.

---

## WebSockets

Persistent,

bidirectional,

low latency.

Best choice for messaging.

---

# Database Choices

---

## SQL

Advantages:

- Strong consistency
- Transactions

Disadvantages:

- Horizontal scaling challenges

---

## Cassandra

Advantages:

- Massive write throughput
- Horizontal scalability

Disadvantages:

- Eventual consistency

Many large messaging systems prefer Cassandra for message storage because of its scalability.

# Common Mistakes

Many candidates lose marks because they:

---

## Mistake 1

Jump directly into WebSockets.

Start with requirements.

---

## Mistake 2

Ignore offline users.

Offline delivery is a core requirement.

---

## Mistake 3

Forget ordering guarantees.

Messaging systems must preserve conversation order.

---

## Mistake 4

Ignore duplicate delivery.

Retries happen.

Idempotency is essential.

---

## Mistake 5

Treat media like text.

Large files require a completely different pipeline.

---

## Mistake 6

Forget security.

Messaging applications require encryption from the beginning.

# Key Takeaways

- WhatsApp is fundamentally a real-time distributed messaging platform.
- Persistent WebSocket connections enable low-latency communication.
- Redis manages highly dynamic presence and session information.
- Offline queues, acknowledgements, retries, and idempotency ensure reliable message delivery.
- Object storage and CDNs efficiently handle large media files.
- End-to-End Encryption ensures only participants can read messages.
- Kafka enables asynchronous processing for notifications, analytics, and monitoring.
- Multi-region deployment, replication, and observability make WhatsApp resilient and highly available.
