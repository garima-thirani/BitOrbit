# Introduction

Instagram is one of the most frequently discussed large-scale systems in System Design interviews because it combines almost every concept you've learned throughout this handbook.

Unlike a URL Shortener, Instagram is not a single service.

It is a collection of multiple distributed systems working together.

Examples include:

- User Management
- Photo Upload
- Video Processing
- Feed Generation
- Likes
- Comments
- Stories
- Notifications
- Search
- Messaging
- Recommendations

Each subsystem has different scaling requirements.

Some are read-heavy.

Some are write-heavy.

Some require real-time communication.

Others rely on asynchronous processing.

Designing Instagram means learning how multiple distributed systems collaborate to create a seamless user experience.

# Understanding the Problem

At first glance,

Instagram appears simple.

Users:

- Upload photos
- Follow friends
- Scroll feeds

However,

behind every action lies a distributed workflow.

For example,

uploading a single image triggers multiple services.

```text
Upload Image

↓

Authentication

↓

Image Validation

↓

Object Storage

↓

Image Processing

↓

Thumbnail Generation

↓

Metadata Storage

↓

Feed Update

↓

Notification Service

↓

Recommendation Updates
```

A single user action becomes a pipeline involving many independent systems.

# Capacity Estimation

Assume

500 Million DAU.

---

## Photo Uploads

```text
500 Million

×

3

=

1.5 Billion Uploads/day
```

---

## Feed Requests

```text
500 Million

×

200

=

100 Billion Feed Requests/day
```

Immediately,

we notice something important.

Feed reads greatly outnumber uploads.

Instagram is an extremely **read-heavy** system.

---

## Likes

```text
500 Million

×

100

=

50 Billion Likes/day
```

---

## Comments

```text
500 Million

×

20

=

10 Billion Comments/day
```

---

## Media Storage

Assume

Average Image Size

```
5 MB
```

Daily Storage

```text
1.5 Billion

×

5 MB

≈

7.5 Petabytes/day
```

Clearly,

media cannot be stored inside a relational database.

We'll need object storage and a CDN.

# Key Takeaways

- Instagram is a collection of multiple distributed systems rather than a single application.
- Feed generation, media storage, notifications, and recommendations each present unique scaling challenges.
- The system is heavily read-oriented, making caching and CDNs essential.
- Media storage requires object storage rather than traditional relational databases.
- Capacity estimation guides architectural decisions before selecting technologies.
- The next step is designing the high-level architecture and understanding how Instagram processes uploads and serves content at internet scale.
