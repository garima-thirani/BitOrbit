# Complete URL Creation Flow

Suppose Alice wants to shorten

```
https://openai.com/blog/chatgpt
```

The request flows through the system.

```text
Client

↓

API Gateway

↓

Authentication

↓

URL Creation Service

↓

Generate ID

↓

Base62 Encoding

↓

Store Mapping

↓

Database

↓

Return

↓

https://tiny.ly/AbC91X
```

This operation is relatively infrequent.

The system prioritizes correctness over speed.

# Complete Redirect Flow

Now Bob clicks

```
https://tiny.ly/AbC91X
```

The request follows this path.

```text
Client

↓

↓

↓

Redis

↓

Cache Hit?

│

├── Yes

│      ↓

│ Return Redirect

│

└── No

       ↓

Database

↓

Update Redis

↓

↓

↓

```

Notice something important.

The user is redirected **before** analytics processing completes.

This keeps latency extremely low.

# Alternative Design 1 — Random String Generator

Instead of Base62,

we could generate random codes.

```text
Random Generator

↓

ABX72Q
```

Advantages

- Difficult to predict
- No sequential IDs

Disadvantages

- Collision detection required
- Database lookup on every generation
- Slower at large scale

---

# Alternative Design 2 — Hashing the URL

We could compute

```
MD5(URL)
```

or

```
SHA256(URL)
```

Advantages

- Deterministic
- Same URL → Same Hash

Problems

- Hashes are long
- Hash collisions are possible
- Difficult to create custom aliases

---

# Alternative Design 3 — Distributed ID Generator

Instead of using a database ID,

we could use

Snowflake.

```text
Timestamp

↓

Machine ID

↓

Sequence

↓

Unique Number

↓

Base62
```

Advantages

- No centralized bottleneck
- Better for distributed deployments

Disadvantages

- More complex implementation

Large-scale production systems often prefer this approach.

# Trade-offs

Every architecture involves trade-offs.

---

## SQL vs NoSQL

SQL

Advantages

- Strong consistency
- ACID transactions
- Simpler schema

NoSQL

Advantages

- Better horizontal scaling
- Flexible schema
- Massive write throughput

---

## Cache Size

Large cache

Advantages

- Higher hit rate
- Lower latency

Disadvantages

- Higher memory cost

---

## Analytics

Synchronous

Advantages

- Immediate updates

Disadvantages

- Slower redirects

Asynchronous

Advantages

- Fast user experience

Disadvantages

- Eventual consistency

---

## Predictable IDs

Sequential IDs

Advantages

- Easy generation

Disadvantages

- Guessable

Random IDs

Advantages

- Harder to guess

Disadvantages

- Collision checks

# Real-World Architecture — Twitter t.co

Twitter shortens every external URL.

When someone tweets

```
https://example.com
```

Twitter converts it into

```
https://t.co/abc123
```

This enables Twitter to

- Track clicks
- Scan links for malware
- Protect users
- Measure engagement

Notice that the URL Shortener also becomes a security layer.

# Common Interview Follow-Up Questions

Interviewers rarely stop after the initial design.

Typical follow-up questions include:

---

## What if Redis crashes?

Fallback to the database.

Gradually rebuild the cache.

---

## What if one database shard becomes full?

Split the shard.

Redistribute data.

Update routing.

---

## How would you support custom aliases?

Before creating

```
tiny.ly/openai
```

verify that

```
openai
```

does not already exist.

---

## How would you support URL expiration?

Store

```
expires_at
```

in the database.

Reject expired requests during redirects.

---

## How would you delete malicious URLs?

Maintain a blacklist.

Delete mappings.

Invalidate Redis cache.

---

## How would you support billions of URLs?

- Sharding
- Read Replicas
- Distributed ID Generation
- Redis Cluster
- Multi-Region Deployment

---

## How would you improve latency?

- Redis
- CDN
- Regional Deployments
- Better Indexes
- Connection Pooling

# Key Takeaways

- A production-ready URL Shortener consists of multiple specialized services rather than a single application.
- Redirect requests should always be optimized for low latency using Redis and efficient indexing.
- Analytics must be processed asynchronously through Kafka to avoid impacting user experience.
- Base62 encoding provides compact, URL-friendly identifiers, while distributed ID generators can improve scalability.
- High availability is achieved using load balancers, replication, Multi-AZ deployments, and failover mechanisms.
- Monitoring, logging, security, and rate limiting are essential production concerns.
- Every architectural decision involves trade-offs, and interviewers value your reasoning more than a single "correct" answer.
- The URL Shortener demonstrates how databases, caching, messaging, cloud infrastructure, and observability work together to build a real-world distributed system.
