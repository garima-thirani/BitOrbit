# Introduction

Imagine opening Instagram, Facebook, LinkedIn, or X (formerly Twitter).

Within a fraction of a second,

your personalized feed appears.

It contains:

- Posts from friends
- Pages you follow
- Advertisements
- Suggested content
- Trending topics

Every user sees a completely different feed.

Generating this feed in real time for billions of users is one of the hardest problems in distributed systems.

# Feed Generation

There are two primary approaches.

## Fan-out on Write

When Bob creates a post:

```text
Bob Posts

↓

Copy Post ID

↓

Alice's Timeline

↓

Charlie's Timeline

↓

David's Timeline
```

The feed is precomputed.

---

### Advantages

- Extremely fast reads
- Feed already prepared
- Excellent user experience

---

### Disadvantages

- Expensive writes
- Millions of copies for celebrities
- Higher storage usage

---

# Fan-out on Read

Instead of precomputing,

the feed is built when requested.

```text
Alice Opens Feed

↓

Find Following

↓

Fetch Recent Posts

↓

Merge

↓

Sort

↓

Display
```

---

### Advantages

- Cheap writes
- Minimal duplication
- Lower storage

---

### Disadvantages

- Slow reads
- Higher CPU usage
- Complex merging

---

# Comparison

| Fan-out on Write | Fan-out on Read |
|------------------|-----------------|
| Fast reads | Slow reads |
| Expensive writes | Cheap writes |
| Higher storage | Lower storage |
| Better for normal users | Better for celebrities |

Neither strategy is universally best.

---

# Hybrid Approach

Modern systems combine both.

Normal users:

```text
Fan-out on Write
```

Celebrities:

```text
Fan-out on Read
```

This provides the best balance.

---

# The Celebrity Problem

Suppose Taylor Swift posts.

Followers:

```text
100 Million
```

Should the system immediately copy the post

100 million times?

No.

Instead,

the post is generated dynamically

when followers open their feeds.

This avoids enormous write amplification.

---

# Timeline Cache

Frequently accessed feeds are cached.

```text
User

↓

Redis

↓

Timeline
```

Instead of rebuilding the feed repeatedly,

recent results are served from cache.

---

# Cache Structure

Example:

```text
Alice

↓

[Post 1]

[Post 2]

[Post 3]

[Post 4]
```

Only post IDs are cached.

Full post details are fetched separately.

---

# Why Cache IDs Instead of Posts?

Posts can change.

Examples:

- Likes increase
- Comments added
- Post deleted

Caching only IDs avoids stale content and reduces memory usage.

---

# Feed Ranking

A feed is not simply chronological.

The Ranking Service scores posts.

Possible ranking signals:

- Recency
- Likes
- Comments
- Shares
- Watch Time
- Relationship Strength
- User Interests
- ML Prediction

Higher-scoring posts appear earlier.

---

# Ranking Pipeline

```text
Candidate Posts

↓

Feature Extraction

↓

ML Ranking Model

↓

Score

↓

Sort

↓

Final Feed
```

The model continuously learns from user behavior.

---

# Infinite Scrolling

Feeds use cursor-based pagination.

```text
Feed

↓

Next Cursor

↓

Next Page

↓

Next Cursor
```

Offset pagination becomes inefficient at scale.

---

# Complete Feed Request Flow

```text
User Opens App

↓

Feed Service

↓

Timeline Cache

↓

Cache Hit?

│

├── Yes → Return Feed

│

└── No

↓

Fetch Posts

↓

Ranking

↓

Cache Timeline

↓

Return Feed
```

# Design Decisions

| Problem | Solution |
|----------|----------|
| Fast Reads | Fan-out on Write |
| Celebrity Posts | Fan-out on Read |
| Personalization | Ranking Service |
| Repeated Reads | Timeline Cache |
| Infinite Scroll | Cursor Pagination |
| Recommendations | ML Ranking |

# Interview Tips

Interviewers often ask:

> **"Why don't Facebook or Instagram use only Fan-out on Write?"**

A strong answer is:

> "Fan-out on Write provides excellent read performance, but it doesn't scale for celebrity accounts with millions of followers because every post would need to be copied millions of times. Modern social networks use a hybrid approach—precomputing feeds for ordinary users while generating feeds dynamically for celebrity accounts."

# Key Takeaways

- A News Feed is generated dynamically rather than stored as a single object.
- Fan-out on Write provides fast reads but expensive writes.
- Fan-out on Read reduces write amplification but increases read latency.
- Modern systems use a hybrid strategy to handle both normal users and celebrities efficiently.
- Timeline caches store post IDs for fast feed retrieval while avoiding stale content.
- Machine learning ranking determines the order of posts shown to each user.
- Cursor-based pagination enables efficient infinite scrolling.
- The next step is designing the production architecture that powers large-scale social feeds.
