# Introduction

Until now, our system supports:

- Text Messages
- Message Delivery
- Read Receipts
- Group Chats
- Offline Messaging
- Message Ordering

However, modern messaging applications support much more.

Users send:

- Photos
- Videos
- Voice Notes
- Documents
- Stickers
- GIFs

Unlike text messages,

media files are much larger.

A text message may be

```
1 KB
```

A video might be

```
150 MB
```

Clearly,

they cannot be treated the same way.

---

# Why Not Send Media Through Chat Servers?

Imagine Alice sends Bob a

```
500 MB Video
```

If every video passed through the Message Service,

the servers would quickly become overloaded.

Instead,

WhatsApp separates

```text
Messages

↓

Chat Infrastructure
```

and

```text
Media Files

↓

Object Storage
```

This separation dramatically improves scalability.

---

# Media Upload Pipeline

Suppose Alice uploads a photo.

The upload follows this path.

```text
Alice

↓

Media Service

↓

Object Storage

↓

Generate URL

↓

Message Service

↓

Bob
```

Notice something important.

Only the **link** is sent through the messaging infrastructure.

The image itself is stored elsewhere.

---

# Real-Life Analogy

Imagine sending someone a book.

Instead of carrying the entire book yourself,

you send them the address of the library.

The recipient goes there and collects it.

WhatsApp works similarly.

Instead of embedding large files inside every message,

it sends a secure reference.

---

# Media Storage

Media is stored inside object storage.

Examples include:

- Amazon S3
- Google Cloud Storage
- Azure Blob Storage

Object storage provides:

- Massive scalability
- Low cost
- High durability
- Automatic replication

---

# Media Database

The messaging database stores metadata only.

Example

| Message ID | Media URL | Type |
|------------|-----------|------|
| 10231 | media/abc123 | Image |
| 10232 | media/xyz891 | Video |

The actual file remains in object storage.

---

# Download Flow

Suppose Bob opens the image.

```text
Bob

↓

Media URL

↓

Object Storage

↓

Download Image
```

Notice that Chat Servers are no longer involved.

This significantly reduces server load.

---

# Why Use a CDN?

Imagine

10 million users

view the same video.

Without caching,

every request reaches object storage.

Instead,

WhatsApp places a CDN in front.

```text
Bob

↓

Nearest CDN

↓

Cached Image

↓

Object Storage (Cache Miss)
```

Benefits:

- Lower latency
- Lower storage cost
- Better user experience

# End-to-End Encryption

One of WhatsApp's defining features is

End-to-End Encryption.

This means

Only

Alice

and

Bob

can read the message.

Even WhatsApp cannot.

---

# Why Encrypt?

Imagine sending

```
My bank password is ...

```

Without encryption,

any server handling the message could read it.

Encryption prevents this.

---

# Real-Life Analogy

Think of a locked box.

Alice locks the box.

Only Bob owns the key.

The courier can transport the box,

but cannot open it.

WhatsApp acts like the courier.

---

# Traditional Encryption

Without End-to-End Encryption,

messages look like this.

```text
Alice

↓

Encrypted

↓

Server Decrypts

↓

Reads Message

↓

Encrypts Again

↓

Bob
```

The server can see everything.

---

# End-to-End Encryption

With E2EE,

the flow changes.

```text
Alice

↓

Encrypt

↓

Server

↓

Forward

↓

Bob

↓

Decrypt
```

The server never decrypts the message.

It simply forwards encrypted data.

---

# Simplified Encryption Flow

```text
Hello Bob

↓

Encrypt

↓

X9A81LK...

↓

Server

↓

Forward

↓

Decrypt

↓

Hello Bob
```

Servers see only encrypted bytes.

---

# Public Key Cryptography

Every user owns two keys.

```text
Public Key

Private Key
```

The public key is shared.

The private key never leaves the device.

---

# Sending an Encrypted Message

Alice wants to message Bob.

```text
Bob's Public Key

↓

Encrypt Message

↓

Server

↓

Bob's Private Key

↓

Decrypt
```

Only Bob possesses the private key.

---

# Why Can't WhatsApp Read Messages?

Because WhatsApp never receives

Bob's private key.

It only forwards encrypted packets.

Even database administrators cannot decrypt messages.

---

# Group Encryption

Group chats introduce additional complexity.

Instead of encrypting once,

the message is encrypted separately for group members.

Modern implementations optimize this process using secure group protocols.

# Push Notifications

Suppose Bob closes WhatsApp.

How does he know Alice sent a message?

Push Notifications.

---

# Notification Flow

```text
Alice

↓

Message Service

↓

Notification Service

↓

Apple Push Notification Service

↓

Android Firebase Cloud Messaging

↓

Bob
```

The phone wakes up,

opens WhatsApp,

and downloads pending messages.

---

# Why Separate Notifications?

Sending push notifications involves external providers.

We don't want message delivery waiting for Apple or Google.

Instead,

notifications happen asynchronously.

---

# Kafka Event Pipeline

Every message generates events.

```text
Message Sent

↓

Kafka

↓

Notification

Analytics

Backup

Monitoring
```

Each service consumes the event independently.

---

# Why Kafka?

Without Kafka,

the Message Service must call

- Notification Service
- Analytics
- Backup
- Monitoring

directly.

One slow service delays everything.

Kafka decouples the architecture.

# Real-Life Example

Imagine Alice sends Bob:

- 20 text messages
- 5 images
- 2 videos
- 1 PDF

The system works as follows:

- Text messages travel through Message Servers.
- Images upload to Object Storage.
- Secure URLs are generated.
- Bob receives encrypted message metadata.
- Bob downloads media from the nearest CDN.
- Kafka updates analytics.
- Push notifications wake Bob's phone if he's offline.

All of this happens within seconds while maintaining end-to-end encryption.

# Interview Tips

Interviewers often ask:

> **"If WhatsApp cannot read messages, how can it deliver them?"**

A strong answer is:

> "WhatsApp servers only forward encrypted packets. The sender encrypts the message using the recipient's public key, and only the recipient's private key can decrypt it. The server acts as a secure transport layer, not a trusted intermediary."

This demonstrates an understanding of both distributed systems and security.

# Key Takeaways

- Large media files are stored in object storage rather than chat databases.
- Messages contain secure references to media instead of embedding the files.
- End-to-End Encryption ensures only the sender and receiver can read messages.
- WhatsApp servers forward encrypted packets without decrypting them.
- Push notifications wake offline devices using platform notification services.
- Kafka enables asynchronous processing for notifications, analytics, and monitoring.
- Separating messaging, media, encryption, and notifications allows independent scaling.
- The next step is designing a globally distributed, fault-tolerant WhatsApp infrastructure capable of serving billions of users.
