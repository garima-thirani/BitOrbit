# Introduction

In the previous part,

we learned that Netflix streams videos from a CDN.

But another question arises.

Imagine Alice starts watching a movie.

Initially,

she has

```
100 Mbps
```

internet.

Suddenly,

Now her speed becomes

```
3 Mbps
```

Should Netflix:

- Stop the movie?
- Restart playback?
- Continue buffering forever?

None of these provide a good experience.

Instead,

Netflix **changes the video quality automatically**.

Most users don't even notice.

This is called

**Adaptive Bitrate Streaming (ABR).**

---

# The Fundamental Problem

Suppose Netflix stores only one version.

```
4K

40 Mbps
```

Users with slow internet cannot watch it.

Now suppose Netflix stores only

```
480p

1 Mbps
```

Users with fast internet receive blurry video.

Clearly,

one version cannot satisfy everyone.

---

# Solution

Store multiple versions.

```text
Movie

↓

240p

480p

720p

1080p

4K
```

Now the player chooses the best one.

---

# Real-Life Analogy

Imagine a restaurant.

Instead of serving only one pizza size,

it offers:

- Small
- Medium
- Large

# Video Encoding

Movies are originally recorded in extremely high quality.

Example:

```text
RAW Movie

↓

500 GB
```

Impossible to stream.

Netflix compresses the video.

This process is called

**Encoding**.

---

# What is Encoding?

Encoding converts

```text
Huge Video

↓

Compressed Video
```

while preserving acceptable quality.

Example:

```text
500 GB

↓

5 GB
```

Huge reduction.

---

# Encoding Pipeline

```text
Original Video

↓

Encoder

↓

Compressed Video

↓

Object Storage
```

This happens long before users press Play.

---

# What is Transcoding?

Encoding creates one version.

Transcoding creates

many versions.

```text
Original

↓

240p

480p

720p

1080p

4K
```

Netflix performs transcoding once,

then stores every version.

---

# Why Multiple Bitrates?

Different internet speeds require different bitrates.

| Resolution | Typical Bitrate |
|------------|-----------------|
| 240p | 300 kbps |
| 480p | 1 Mbps |
| 720p | 3 Mbps |
| 1080p | 5 Mbps |
| 4K | 15–25 Mbps |

The player switches between them.

---

# Storage Challenge

Suppose one movie becomes

```text
5 Versions
```

Instead of

```
5 GB
```

Netflix may now store

```
25 GB
```

per movie.

Storage increases dramatically,

but playback quality improves enormously.

---

# Why Segment Videos?

Netflix does not stream:

```text
Entire Movie.mp4
```

Instead,

it divides videos into small chunks.

Example:

```text
Movie

↓

Segment1.ts

Segment2.ts

Segment3.ts

Segment4.ts
```

Each segment lasts

2–6 seconds.

---

# Benefits of Segmentation

Suppose the network slows down.

Instead of replacing the entire movie,

Netflix simply downloads

the next segment

at a lower quality.

Very efficient.

---

# Segment Structure

Example:

```text
1080p

↓

Seg1

Seg2

Seg3

Seg4

Seg5
```

Similarly,

```text
720p

↓

Seg1

Seg2

Seg3

Seg4

Seg5
```

Every quality contains identical time boundaries.

---

# Why Equal Segment Boundaries?

Suppose Netflix switches from

1080p

to

720p.

The player can continue at

Segment 18

without restarting.

---

# Manifest File

Before downloading video,

Netflix downloads a tiny manifest.

Example:

```text
movie.m3u8
```

or

```text
movie.mpd
```

The manifest contains:

- Available qualities
- Segment URLs
- Bitrates
- Duration

---

# HLS

One popular streaming protocol is

**HTTP Live Streaming (HLS).**

Developed by Apple.

Flow:

```text
Player

↓

Manifest (.m3u8)

↓

Segment List

↓

Download Segments
```

Each segment uses normal HTTP.

---

# HLS Example

```text
Movie

↓

movie.m3u8

↓

segment1.ts

segment2.ts

segment3.ts
```

The player downloads segments individually.

---

# MPEG-DASH

Another popular protocol is

**MPEG-DASH**.

Instead of

```
.m3u8
```

it uses

```
.mpd
```

Otherwise,

the idea is similar.

---

# HLS vs DASH

| HLS | DASH |
|------|------|
| Apple | Open Standard |
| m3u8 | mpd |
| TS / fMP4 | fMP4 |
| Widely Supported | Widely Supported |

Netflix supports multiple protocols depending on the device.

# Buffering

The player never waits until the current segment ends.

Instead,

it downloads future segments.

```text
Playing

↓

Buffered

↓

Buffered

↓

Buffered
```

This prevents interruptions.

---

# Playback Buffer

Example:

```text
Currently Playing

↓

Next 20 Seconds

↓

Already Downloaded
```

If bandwidth temporarily drops,

playback continues using the buffer.

---

# Buffer Size Trade-offs

Large Buffer

Advantages:

- Fewer interruptions

Disadvantages:

- Slow startup

---

Small Buffer

Advantages:

- Fast startup

Disadvantages:

- More buffering

Netflix balances both.

---

# Startup Optimization

Netflix prioritizes

startup speed.

Instead of immediately choosing

4K,

the player often begins at

720p

or

1080p,

then upgrades quality.

Users prefer

fast playback

over perfect quality.

# Digital Rights Management (DRM)

Movies are expensive.

Netflix must prevent piracy.

This is handled using

**Digital Rights Management (DRM).**

---

# What is DRM?

Instead of storing videos as plain files,

Netflix encrypts them.

```text
Video

↓

Encrypt

↓

CDN

↓

Encrypted Segments
```

---

# Playback with DRM

```text
Player

↓

License Request

↓

License Server

↓

Key

↓

Decrypt

↓

Play Video
```

Without the license,

the video cannot be played.

---

# Popular DRM Systems

Examples:

- Google Widevine
- Microsoft PlayReady
- Apple FairPlay

Different devices use different DRM systems.

---

# DRM Benefits

Protects against:

- Unauthorized downloads
- Piracy
- Content theft
- Subscription sharing

# Interview Tips

Interviewers often ask:

> **"How does Netflix change video quality without restarting the movie?"**

A strong answer is:

> "Netflix stores multiple encoded versions of every video. Each version is divided into aligned segments. During playback, the client continuously measures available bandwidth and requests the next segment at the most appropriate bitrate using HLS or MPEG-DASH. Since segment boundaries are identical across all qualities, switching resolutions is seamless."

This demonstrates an understanding of adaptive streaming and media delivery.

# Key Takeaways

- Netflix stores multiple encoded versions of every video for different network conditions.
- Transcoding creates multiple resolutions and bitrates from a single source video.
- Videos are divided into small segments to enable efficient streaming and adaptive quality changes.
- HLS and MPEG-DASH use manifest files to describe available streams and segment locations.
- Adaptive Bitrate Streaming continuously adjusts video quality based on available bandwidth.
- Buffering and intelligent startup strategies reduce playback interruptions.
- DRM protects premium content using encryption and license-based playback.
