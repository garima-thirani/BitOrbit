# High-Level Architecture

A simplified Netflix architecture looks like this.

```text
                           Users
                              │
                              ▼
                         Global DNS
                              │
                              ▼
                       API Gateway
                              │
 ┌────────────┬────────────┬────────────┬────────────┐
 ▼            ▼            ▼            ▼
User      Metadata     Playback   Recommendation
Service    Service      Service      Service
 │            │            │            │
 ▼            ▼            ▼            ▼
Redis     Metadata DB   CDN/OpenConnect ML Models
                         │
                         ▼
                  Object Storage
```

Every service has one responsibility.

# User Service

Responsible for:

- Login
- Authentication
- Subscription
- Profiles

Before streaming,

Netflix verifies:

- User exists
- Subscription is active
- Device is authorized

---

# Metadata Service

Metadata is everything

except the video.

Examples:

```text
Movie Title

Description

Cast

Genre

Duration

Thumbnail
```

These are tiny compared to videos.

---

# Why Separate Metadata from Video?

Suppose someone searches

```
Interstellar
```

Netflix only needs:

- Title
- Poster
- Rating

It does NOT need the 20 GB movie.

Keeping metadata separate improves performance dramatically.

---

# Object Storage

Videos are stored in

Object Storage.

Examples:

- Amazon S3
- Netflix Internal Storage

Object storage provides:

- High durability
- Massive scalability
- Cheap storage
- Easy replication

---

# Why Not Store Videos in SQL?

Suppose one movie is

```
20 GB
```

SQL databases are optimized for

structured records,

not massive binary objects.

Object storage is the correct solution.

---

# Real-Life Analogy

Imagine a library.

The catalog contains:

- Title
- Author
- Shelf Number

The actual book sits elsewhere.

Metadata is the catalog.

Object Storage is the bookshelf.

---

# Playback Service

The Playback Service coordinates streaming.

Responsibilities:

- Validate subscription
- Locate video
- Select CDN
- Generate playback token
- Return streaming URL

It does NOT stream video itself.

---

# Playback Flow

Suppose Alice clicks

```
Play
```

```text
Alice

↓

Playback Service

↓

Validate User

↓

Locate Video

↓

Choose CDN

↓

Return Streaming URL
```

After that,

the client communicates directly with the CDN.

---

# Why Return a URL?

Streaming servers should not become bottlenecks.

Instead of proxying video,

Netflix simply returns

```
https://cdn.netflix.com/video123
```

The player downloads directly.

---

# CDN (Content Delivery Network)

A CDN stores copies of videos

close to users.

Instead of

```text
India

↓

USA

↓

Video
```

the request becomes

```text
India

↓

Mumbai CDN

↓

Video
```

Latency decreases dramatically.

---

# Why CDNs Matter

Suppose

50 million people

watch the same movie.

Without CDNs,

every request reaches central storage.

With CDNs,

most requests never leave the local region.

---

# Real-Life Example

Imagine ordering pizza.

Would the restaurant prepare every pizza in New York?

No.

Every city has local branches.

CDNs work the same way.

---

# Netflix Open Connect

Netflix built its own CDN called

**Open Connect**.

Instead of relying entirely on cloud providers,

Netflix deploys servers inside ISP networks.

```text
User

↓

ISP

↓

Open Connect Server

↓

Video
```

The video may travel only a few kilometers.

---

# Benefits of Open Connect

- Lower latency
- Reduced internet congestion
- Lower bandwidth cost
- Better streaming quality

This is one of Netflix's biggest engineering innovations.

---

# Cache Hit vs Cache Miss

Suppose Alice requests a movie.

### Cache Hit

```text
User

↓

Nearby CDN

↓

Video
```

Fast.

---

### Cache Miss

```text
User

↓

CDN

↓

Object Storage

↓

Cache

↓

User
```

Future requests become faster.

# Video Segmentation

Netflix does **not** stream an entire movie as one file.

Instead,

videos are divided into small pieces.

```text
Movie

↓

Segment 1

Segment 2

Segment 3

Segment 4
```

Each segment usually lasts

2–10 seconds.

---

# Why Segment Videos?

Suppose the internet disconnects.

Only one segment must be downloaded again,

not the entire movie.

Segmentation also enables adaptive quality,

which we'll discuss in the next part.

---

# Interview Tips

Interviewers often ask:

> **"Why doesn't Netflix stream videos directly from its application servers?"**

A strong answer is:

> "Application servers handle business logic such as authentication and playback authorization. Large video files are served directly from geographically distributed CDNs like Netflix Open Connect. This reduces latency, lowers bandwidth costs, and prevents application servers from becoming bottlenecks."

This demonstrates understanding of separation of concerns and scalable content delivery.

# Key Takeaways

- Netflix separates metadata from video content for efficiency.
- Videos are stored in durable object storage rather than databases.
- CDNs deliver content from locations close to users, dramatically reducing latency.
- Netflix Open Connect is a specialized CDN deployed inside ISP networks.
- Videos are divided into small segments to enable efficient streaming and adaptive quality.
- The Playback Service authorizes streaming and returns CDN URLs, but does not stream the video itself.
- Stateless services, Redis caching, and regional deployments enable Netflix to scale globally.
- The next step is understanding adaptive bitrate streaming, video encoding, and playback optimization.
