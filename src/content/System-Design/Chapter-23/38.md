# Social Graph

A social network is fundamentally a graph.

```text
Alice

↓

Bob

↓

Charlie

↓

David
```

Each edge represents a relationship.

Example:

```text
Alice

↓

Follows

↓

Bob
```

The Social Graph stores these relationships.

---

# Graph Representation

Instead of storing:

```text
Alice's Feed
```

we store:

```text
Alice

↓

Following

↓

Bob

Charlie

David
```

The feed can then be generated from these relationships.

---

# Graph Database

The Social Graph may use:

- Neo4j
- JanusGraph
- Amazon Neptune

or a distributed graph built on top of Cassandra or MySQL.

The goal is efficient traversal of follower relationships.

---

# Feed Cache

Building a feed repeatedly is expensive.

Instead,

Redis stores recently generated timelines.

```text
User

↓

Redis

↓

Post IDs
```

Notice that Redis stores **only Post IDs**, not the complete posts.

---

# Why Store IDs?

Suppose a post receives:

- 500 new likes
- 20 comments

If the full post were cached,

every cached copy would need updating.

Instead:

```text
Redis

↓

Post ID

↓

Fetch Latest Post
```

This keeps cache entries small and avoids stale data.

---

# Feed Refresh

Feeds can be refreshed in two ways.

## Pull Model

```text
User Opens App

↓

Generate Feed

↓

Display
```

Advantages:

- Fresh content
- Simple

Disadvantages:

- Higher latency

---

## Push Model

```text
New Post

↓

Generate Feed

↓

Update Cache
```

Advantages:

- Instant loading

Disadvantages:

- Expensive writes

---

Modern systems combine both.

# Ranking Service

A feed is more than a chronological list.

The Ranking Service computes a relevance score.

Example features:

- Relationship strength
- Recency
- Likes
- Comments
- Shares
- Watch time
- User interests
- Device type
- Session history

Each candidate post receives a score.

---

# Ranking Pipeline

```text
Candidate Posts

↓

Feature Extraction

↓

ML Model

↓

Score

↓

Sort

↓

Feed
```

The highest-ranked posts appear first.

# Recommendation Service

Not every post comes from someone the user follows.

Recommendation systems insert:

- Suggested accounts
- Reels
- Videos
- Groups
- Advertisements

The recommendation engine expands the candidate set before ranking.

# Celebrity Optimization

Suppose a celebrity has:

```text
80 Million Followers
```

Fan-out on Write becomes impractical.

Instead:

```text
Celebrity Post

↓

Store Once

↓

Generate During Read
```

Only active users receive the post.

---

# Feed Refresh Strategy

A common production strategy is:

```text
Open Feed

↓

Load Cached Feed

↓

Background Refresh

↓

Merge New Posts

↓

Update Timeline
```

The user sees content immediately while fresh posts are loaded asynchronously.

---

# Cache Invalidation

One of the hardest problems in distributed systems.

Suppose Bob deletes a post.

The cache still contains its ID.

The Feed Service must:

```text
Cache

↓

Validate

↓

Missing?

↓

Remove
```

This keeps timelines consistent.

# Trade-offs

## Fan-out on Write

Advantages:

- Fast reads
- Excellent user experience

Disadvantages:

- High write amplification
- Poor for celebrities

---

## Fan-out on Read

Advantages:

- Low storage
- Cheap writes

Disadvantages:

- Higher read latency
- More CPU usage

---

## Timeline Cache

Advantages:

- Fast response
- Lower database load

Disadvantages:

- Cache invalidation complexity

---

## Machine Learning Ranking

Advantages:

- Better engagement
- Personalized feeds

Disadvantages:

- Higher computational cost
- Model training complexity

# Common Interview Questions

---

## Why use Redis?

Redis stores frequently accessed timelines,

reducing database reads and improving latency.

---

## Why store Post IDs instead of Posts?

Post IDs require much less memory and avoid stale cached content.

---

## How do you handle celebrity accounts?

Use Fan-out on Read for celebrities and Fan-out on Write for ordinary users.

---

## Why Kafka?

Kafka distributes new post events to multiple downstream systems such as:

- Feed generation
- Notifications
- Analytics
- Recommendations

without tightly coupling services.

---

## Why use Cursor Pagination?

Cursor-based pagination scales much better than OFFSET queries for large datasets and supports infinite scrolling efficiently.

# Key Takeaways

- A News Feed is generated from the social graph rather than stored as a single object.
- Modern social networks combine **Fan-out on Write** and **Fan-out on Read** to balance write amplification and read latency.
- Redis timeline caches significantly reduce feed generation time.
- Kafka enables asynchronous processing for feed generation, notifications, recommendations, and analytics.
- Machine learning ranking personalizes each user's feed based on engagement and relevance signals.
- Multi-region deployment, replication, and monitoring ensure high availability and low latency at global scale.
- The News Feed is one of the best examples of combining graph data, caching, messaging, and ranking into a production-scale distributed system.
