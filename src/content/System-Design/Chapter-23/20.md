---

# What is a Race Condition?

A race condition occurs when two processes attempt to modify the same resource simultaneously.

Example:

```text
Ride Request A

↓

Driver B

↑

Ride Request B
```

Without synchronization,

Driver B might receive both requests.

---

# Preventing Double Assignment

Uber temporarily locks the selected driver.

```text
Driver B

↓

Lock Driver

↓

Send Request

↓

Wait

↓

Accepted?

↓

Unlock
```

Only one ride request can own the lock.

---

# Redis Distributed Lock

A simple implementation uses Redis.

```text
SET

Driver123

LOCKED

EX 15
```

Meaning:

- Lock Driver 123
- Automatically expire after 15 seconds

If another request arrives,

it cannot acquire the lock.

---

Other customers cannot purchase it until:

- The reservation expires

# Interview Tips

Interviewers often ask:

> **"How do you prevent two passengers from getting the same driver?"**

A strong answer is:

> "When the Matching Service selects a driver, it acquires a distributed lock (commonly using Redis). The driver is temporarily reserved while the request is sent. If the driver accepts, the ride is confirmed. If the request times out or is rejected, the lock is released and the next candidate is selected."

This demonstrates understanding of concurrency control in distributed systems.

- Driver assignment requires distributed locking to prevent race conditions.

- GPS updates continuously refresh passenger maps and ETA calculations.
- Surge Pricing balances demand and supply using dynamic pricing algorithms.
- Payments, ratings, and ride history are handled by dedicated services.
