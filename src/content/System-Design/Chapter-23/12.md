# Step 5 — Explain Media Storage

One of the first questions interviewers ask is

> Why not store images inside PostgreSQL?

Explain.

Databases are optimized for structured data.

Object Storage is optimized for large binary objects.

Therefore,

Instagram stores

```text
Metadata

↓

Database
```

```text
Images

↓

Object Storage
```

---

# Step 6 — Explain Feed Generation

Discuss both strategies.

## Fan-out on Read

Generate feeds when users request them.

Advantages:

- Fresh data
- Cheap writes

Disadvantages:

- Expensive reads

---

## Fan-out on Write

Generate feeds when posts are uploaded.

Advantages:

- Extremely fast reads

Disadvantages:

- Expensive writes

---

## Hybrid Strategy

Instagram combines both.

```text
Normal Users

↓

Fan-out on Write

---------------------

Celebrity Accounts

↓

Fan-out on Read
```

This is usually the expected interview answer.

---

# Step 7 — Explain Redis

Redis exists because

```
Feed Requests

>>

Photo Uploads
```

Feeds are read repeatedly.

Redis caches:

- Feed
- User Profile
- Like Counts
- Story Metadata

This minimizes database traffic.

---

# Step 8 — Explain Kafka

Every upload generates events.

Instead of directly calling

- Notification Service
- Search Service
- Recommendation Service

the Upload Service simply publishes

```
Photo Uploaded
```

Kafka distributes the event.

Benefits:

- Loose coupling
- Retry support
- Independent scaling

# Common Interview Questions

Interviewers often ask follow-up questions.

---

## Why Object Storage?

Because media files are:

- Large
- Immutable
- Cheap to store
- Easily replicated

Databases are not optimized for this workload.

---

## Why Redis?

Because feed generation is expensive.

Redis stores:

```
Feed Cache

↓

Fast Retrieval
```

---

## Why Kafka?

Because uploads trigger multiple downstream systems.

Kafka prevents synchronous communication.

---

## Why CDN?

Imagine

100 million users

viewing the same image.

Without a CDN,

every request reaches object storage.

With a CDN,

the image is served from nearby edge locations.

Latency decreases dramatically.

---

## Why Separate Services?

Instead of

```text
One Giant Server
```

Instagram uses

```text
Feed

Upload

Notification

Search

Recommendation
```

Each scales independently.

---

## What Happens if Redis Fails?

Fallback to the database.

Rebuild the cache gradually.

Users experience slower responses,

not complete failure.

---

## What Happens if Kafka Fails?

Uploads should still succeed.

Possible strategies:

- Retry
- Local Queue
- Dead Letter Queue
- Replay Events

User experience takes priority.

---

## How Would You Support Reels?

Introduce:

- Video Processing Pipeline
- Video Transcoding
- Streaming CDN
- Recommendation Model

The overall architecture remains similar.

---

## How Would You Support Live Streaming?

Add:

- Streaming Ingest Servers
- Video Encoding
- HLS/DASH Packaging
- Streaming CDN

Live streaming is a separate subsystem.

# Common Mistakes

Many candidates lose marks because they:

---

## Mistake 1

Immediately drawing Kafka.

Always begin with requirements.

---

## Mistake 2

Ignoring capacity estimation.

Without numbers,

architectural choices become arbitrary.

---

## Mistake 3

Using every technology.

Not every system requires:

- Kafka
- Kubernetes
- Redis
- Elasticsearch

Use technologies only when they solve a problem.

---

## Mistake 4

Ignoring CDN.

Media-heavy applications almost always require a CDN.

---

## Mistake 5

Ignoring the Celebrity Problem.

Interviewers often expect discussion about

Fan-out on Read

vs

Fan-out on Write.

# Key Takeaways

- Instagram is a collection of specialized distributed systems rather than a single application.
- Object Storage and CDNs are essential for serving billions of media files efficiently.
- Feed generation is solved using a hybrid Fan-out strategy combined with Redis caching.
- Kafka enables asynchronous communication between independent services.
- Horizontal scaling, sharding, and multi-region deployments allow Instagram to support hundreds of millions of users.
- Monitoring, observability, and disaster recovery are essential production concerns.
- The architecture demonstrates how distributed systems, caching, messaging, cloud infrastructure, and AI combine to power one of the world's largest social media platforms.
