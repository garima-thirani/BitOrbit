# Introduction

Imagine opening WhatsApp.

You type

```
Hello!
```

and press Send.

Within milliseconds,

your friend—who might be thousands of kilometers away—receives the message.

To the user,

it feels almost magical.

But behind that single tap,

a massive distributed system is at work.

The message must:

- Reach the correct user.
- Arrive within milliseconds.
- Be delivered in order.
- Be encrypted.
- Be stored safely.
- Be synchronized across devices.
- Be delivered even if the receiver is offline.

Unlike Instagram,

where users consume content,

WhatsApp is built around **real-time communication**.

That makes the architecture fundamentally different.

# Messaging vs Traditional Web Applications

Most web applications follow a request-response model.

Example:

```text
Browser

↓

Request

↓

Server

↓

Response
```

Once the response is sent,

the connection closes.

Messaging applications work differently.

Users stay connected continuously.

```text
Alice

────────────── Connected ──────────────

↓

WhatsApp Server

↑

────────────── Connected ──────────────

Bob
```

Instead of opening a new connection for every request,

WhatsApp maintains a persistent connection.

This enables instant communication.

---

# Real-Life Analogy

Think about making a phone call.

Once the call is established,

both people remain connected.

Neither person dials again for every sentence.

WebSockets work similarly.

A connection is established once,

and messages flow continuously in both directions.

# Non-Functional Requirements

---

## Low Latency

Messages should arrive almost instantly.

Target:

```text
< 100 ms
```

---

## High Availability

Messaging applications should remain available continuously.

Target:

```text
99.99%
```

---

## Scalability

Support:

- Billions of users
- Billions of messages
- Millions of simultaneous connections

---

## Durability

Messages should never disappear after delivery.

---

## Reliability

Messages should not be:

- Lost
- Duplicated
- Delivered out of order

---

## Security

Every message should be encrypted.

Only sender and receiver should read its contents.

# Concurrent Connections

Suppose

```
500 Million

Concurrent Users
```

Unlike traditional web applications,

# Read vs Write Ratio

Unlike Instagram,

WhatsApp has a much more balanced workload.

Every message creates:

- One write
- One or more reads

Messaging systems require optimizing both.

# Key Takeaways

- WhatsApp is fundamentally a **real-time messaging system**, not a traditional web application.
- Persistent connections are essential for low-latency communication.
- Messaging systems must guarantee reliability, ordering, durability, and security.
- Capacity planning must account for billions of messages and hundreds of millions of simultaneous connections.
- Features such as offline delivery, read receipts, typing indicators, and multi-device sync significantly increase architectural complexity.
- The next step is designing the core architecture that enables instant message delivery at global scale.
