# Introduction

When users open Instagram,

they expect something magical.

Within milliseconds,

their home page is filled with fresh posts from friends.

Yet behind that simple scroll lies one of the most challenging problems in System Design.

Unlike a URL Shortener,

Instagram doesn't simply fetch one record.

It has to answer questions like:

- Who does this user follow?
- Which posts should appear?
- Which order should they appear?
- Which posts are already seen?
- Which advertisements should be inserted?
- Which posts should be recommended?

This entire process happens in just a few hundred milliseconds.

---

# The Feed Problem

Suppose Alice follows

- Bob
- Charlie
- David

When Alice opens Instagram,

the Feed Service must collect posts from all three users.

```text
Alice

↓

Who does Alice follow?

↓

Bob

Charlie

David

↓

Latest Posts

↓

Merge Posts

↓

Sort

↓

Return Feed
```

This seems simple.

Until we scale it.

Imagine

500 Million users

refreshing their feeds every few minutes.

The system now performs billions of feed generations every day.

---

# Why Feed Generation is Difficult

The feed must satisfy several goals simultaneously.

- Low latency
- Fresh content
- Personalized ranking
- Scalability
- High availability

These goals often conflict.

For example,

showing the newest posts is easy.

Showing the **most relevant** posts is much harder.

---

# Naive Approach

A beginner might design the feed like this.

```text
Open Instagram

↓

Query Followers

↓

Query Posts

↓

Sort

↓

Return Feed
```

Every refresh performs multiple database queries.

For millions of users,

this quickly overwhelms the database.

---

# The Two Main Strategies

There are two common approaches.

```text
Fan-out on Read
```

and

```text
Fan-out on Write
```

Every social network uses one or both of these.

---

# Fan-out on Read

In this approach,

the feed is generated

when the user opens Instagram.

Example

```text
Alice Opens App

↓

Fetch Following List

↓

Fetch Posts

↓

Merge

↓

Sort

↓

Return Feed
```

Nothing is precomputed.

---

# Advantages

- Fresh content
- Low storage
- Easy to update ranking
- Simple writes

---

# Disadvantages

- Slow feed generation
- Expensive reads
- Database pressure

---

# Real-Life Example

Imagine going to a restaurant.

Instead of preparing food beforehand,

the chef starts cooking only after you order.

Fresh?

Yes.

Fast?

Not always.

Fan-out on Read works similarly.

---

# Fan-out on Write

Instead of building the feed later,

we build it

when someone uploads a post.

Suppose Bob uploads a photo.

Instead of waiting,

Instagram immediately pushes that post

into every follower's feed.

```text
Bob Uploads Photo

↓

Find Followers

↓

Insert Into Feed Cache

↓

Followers Open App

↓

Feed Already Ready
```

The expensive work happens during upload,

not during reads.

---

# Advantages

- Extremely fast feed loading
- Excellent user experience
- Database reads reduced

---

# Disadvantages

Imagine

Cristiano Ronaldo

with

600 million followers.

One upload now requires

600 million feed updates.

Writes become extremely expensive.

---

# Real-Life Example

Imagine a newspaper.

Instead of printing newspapers after every customer orders,

they print them early in the morning.

Customers simply pick one up.

Reads become extremely fast,

but publishing becomes more expensive.

---

# Which Strategy Does Instagram Use?

The answer is

both.

Instagram uses a hybrid approach.

Most users

↓

Fan-out on Write

Celebrity accounts

↓

Fan-out on Read

This avoids updating hundreds of millions of feeds every time a celebrity posts.

---

# Celebrity Problem

Suppose Cristiano Ronaldo uploads one photo.

Should Instagram immediately update

600 million feed caches?

Probably not.

Instead,

Instagram delays feed generation.

```text
Celebrity Upload

↓

Store Post

↓

Followers Open App

↓

Generate Feed
```

This dramatically reduces write amplification.

---

# Hybrid Feed Architecture

```text
                  User Upload
                       │
         ┌─────────────┴─────────────┐
         ▼                           ▼
 Normal User                  Celebrity
         │                           │
         ▼                           ▼
 Fan-out Write               Fan-out Read
         │                           │
         └─────────────┬─────────────┘
                       ▼
                  Feed Service
                       │
                       ▼
                     Redis
```

This combines the strengths of both approaches.

---

# Redis Feed Cache

Generating a feed repeatedly is expensive.

Instead,

Instagram caches feeds.

```text
Alice Feed

↓

Redis

↓

Posts 1-100
```

When Alice refreshes,

Redis immediately returns the feed.

---

# Cache-Aside Pattern

```text
User

↓

Redis

↓

Feed Found?

│

├── Yes

│

│ Return Feed

│

└── No

↓

Generate Feed

↓

Store in Redis

↓

Return Feed
```

Most feed requests never reach the database.

---

# Feed Cache Structure

Redis might store

```text
UserID

↓

Sorted List of Post IDs
```

Example

```text
Alice

↓

Post101

Post98

Post76

Post41
```

The actual post metadata is fetched separately.

---

# Why Store Post IDs Instead of Images?

Images are large.

Redis is memory.

Memory is expensive.

Instead,

Redis stores only references.

```text
Redis

↓

Post IDs
```

Database

↓

Metadata

Object Storage

↓

Images

This keeps memory usage manageable.

# Feed Ranking

Modern Instagram feeds are not chronological.

Instead,

they are ranked.

Possible ranking signals include

- User interactions
- Likes
- Comments
- Shares
- Watch time
- Relationship strength
- Time of upload
- AI recommendations

The Feed Service combines these signals.

---

# Simplified Ranking Pipeline

```text
Candidate Posts

↓

Feature Extraction

↓

Ranking Model

↓

Sort

↓

Top Results
```

Modern ranking often uses Machine Learning.

---

# Feed Pagination

Loading

10,000 posts

at once

would waste bandwidth.

Instead,

Instagram uses pagination.

Example

```http
GET /feed?cursor=abc123
```

Returns

20 posts.

The next request loads the following page.

---

# Infinite Scrolling

Instead of page numbers,

Instagram uses cursors.

```text
Feed

↓

20 Posts

↓

Scroll

↓

Next Cursor

↓

20 More Posts
```

This avoids expensive OFFSET queries.

---

# Scaling the Feed Service

Initially,

one Feed Server is enough.

```text
Users

↓

Feed Server

↓

Redis
```

Eventually,

traffic increases.

```text
           Load Balancer

        ┌──────┼──────┐

        ▼      ▼      ▼

Feed1 Feed2 Feed3
```

Because feed servers are stateless,

horizontal scaling is straightforward.

---

# Scaling Redis

Eventually,

one Redis server becomes insufficient.

```text
Redis Cluster

↓

Shard 1

Shard 2

Shard 3
```

Feed caches are partitioned by User ID.

---

# Scaling the Database

Follower relationships continue growing.

Instagram introduces

- Read Replicas
- Sharding
- Connection Pools

This prevents one database from becoming a bottleneck.

Large-scale systems often include:

# Real-World Example

Suppose Taylor Swift uploads a photo.

Millions of followers open Instagram simultaneously.

Instead of pushing the photo into every user's feed immediately,

Instagram stores the post.

As followers open the app,

their feeds are generated dynamically.

This avoids millions of unnecessary writes.

Meanwhile,

your friend with

200 followers

uses Fan-out on Write,

since updating 200 feeds is inexpensive.

This hybrid strategy allows Instagram to efficiently support both ordinary users and celebrities.

---

# Interview Tips

Interviewers almost always ask:

> "Would you choose Fan-out on Read or Fan-out on Write?"

A strong answer is:

> "I'd use a hybrid strategy. Fan-out on Write for normal users because it provides low-latency reads, and Fan-out on Read for celebrity accounts to avoid massive write amplification."

This demonstrates practical engineering thinking rather than theoretical knowledge.

# Key Takeaways

- Feed generation is one of the most challenging problems in large-scale system design.
- Fan-out on Read generates feeds when users request them, reducing writes but increasing read latency.
- Fan-out on Write precomputes feeds during uploads, providing faster reads at the cost of higher write amplification.
- Instagram uses a hybrid strategy, combining both approaches based on user characteristics.
- Redis stores feed caches to minimize database queries and reduce latency.
- Feed ranking combines multiple signals to personalize the user experience.
- Cursor-based pagination enables efficient infinite scrolling.
- Horizontal scaling, Redis clustering, and database sharding allow the Feed Service to support billions of requests.
