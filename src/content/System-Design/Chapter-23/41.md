# Prefix Search

Autocomplete is based on prefixes.

Example:

```text
system
```

Prefixes:

```text
s

sy

sys

syst

syste

system
```

The Trie stores all these prefixes efficiently.

---

# Why Not SQL?

Suppose we execute:

```sql
SELECT *

WHERE query LIKE 'sys%'
```

against

```text
500 Million Rows
```

for every keystroke.

This would be far too slow.

A specialized data structure is needed.

---

# Trie (Prefix Tree)

A Trie stores characters instead of complete words.

Example:

```text
          (root)
          /   \
         s     c
         |
         y
         |
         s
         |
         t
         |
         e
         |
         m
```

Every path from the root forms a prefix.

---

# Example

Store:

```text
system

systems

syntax

sync
```

Trie:

```text
(root)

  |

  s

 / \

y   y

|   |

s   n

|   |

t   c

|
e

|

m
```

Shared prefixes reduce storage.

---

# Searching a Trie

Suppose the user types:

```text
sys
```

Traversal:

```text
root

↓

s

↓

y

↓

s
```

Now return all words below this node.

Example:

```text
system

systems

system design
```

Time complexity depends only on the prefix length.

---

# Time Complexity

Searching a Trie takes:

```text
O(L)
```

Where:

```text
L = Prefix Length
```

Not:

```text
Number of Words
```

This makes Tries extremely efficient.

# Redis Cache

Popular prefixes are cached.

Example:

```text
sys

↓

Redis

↓

Top Suggestions
```

This avoids repeatedly traversing the Trie.

---

# Why Cache Prefixes?

Prefixes such as:

```text
a

s

t

re

co
```

are requested millions of times.

Caching dramatically reduces latency.

# Real-World Example

Imagine a librarian.

Instead of searching every book in the library,

the librarian has an alphabetical index.

When you ask for books beginning with:

```text
sys
```

the librarian immediately opens the "sys" section,

rather than checking every title.

A Trie works in exactly the same way.

---

# Interview Tips

Interviewers often ask:

> **"Why is a Trie better than a database query for autocomplete?"**

A strong answer is:

> "Autocomplete performs prefix searches on every keystroke. A Trie organizes words by shared prefixes, allowing lookups in O(L), where L is the length of the prefix. This is significantly faster than scanning database indexes for every character typed."

# Key Takeaways

- Search Autocomplete predicts user queries based on typed prefixes.
- Tries provide efficient O(L) prefix lookups independent of the number of stored queries.
- Ranking determines the most relevant suggestions using popularity, recency, and personalization.
- Redis caches frequently requested prefixes for sub-50 ms responses.
- The next step is scaling autocomplete across billions of searches with distributed tries and intelligent caching.
