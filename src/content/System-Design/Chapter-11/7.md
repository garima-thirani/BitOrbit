# Interview Questions & Solutions

## Question 1

### Question

What is Event-Driven Architecture?

### Ideal Answer

Event-Driven Architecture is an architectural style where services communicate by publishing and consuming events instead of making direct synchronous calls. This creates loose coupling, improves scalability, and enables independent service evolution.

---

## Question 2

### Question

What is the difference between Choreography and Orchestration?

### Ideal Answer

Choreography is decentralized, where each service independently reacts to events. Orchestration uses a central workflow engine that coordinates the sequence of operations. Choreography offers greater flexibility, while orchestration provides better visibility and control.

---

## Question 3

### Question

Why should events be immutable?

### Ideal Answer

Events represent historical facts that have already occurred. Keeping them immutable ensures auditability, replayability, and consistency across distributed systems. Any changes should be represented as new events rather than modifying existing ones.

---

## Question 4

### Question

What is the difference between Domain Events and Integration Events?

### Ideal Answer

Domain Events represent business events within a bounded context, while Integration Events are intended for communication between different systems or domains. Integration events are often derived from domain events and may contain only the information needed by external consumers.

---

## Question 5 (FAANG)

### Question

Design an event-driven architecture for a global online marketplace.

### Ideal Answer

Use an event bus such as Kafka or Pulsar. Core services publish domain events like `OrderCreated`, `PaymentCompleted`, and `ShipmentDelivered`. Inventory, Billing, Notifications, Fraud Detection, Analytics, Recommendations, and Customer Support subscribe independently. Include schema versioning, idempotent consumers, correlation IDs for tracing, durable event storage for replay, and monitoring for consumer lag and failed events. Use choreography for loosely coupled workflows and orchestration only for complex business processes requiring centralized coordination.

# Revision Notes

- Event-Driven Architecture enables services to communicate through immutable business events.
- Producers publish events without knowing consumers.
- An Event Bus decouples producers and consumers.
- Choreography distributes workflow logic across services, while orchestration centralizes it.
- Domain Events capture internal business facts; Integration Events communicate across systems.
- Event replay, versioning, and correlation IDs are essential for reliable production systems.
- EDA improves both technical scalability and organizational scalability.
