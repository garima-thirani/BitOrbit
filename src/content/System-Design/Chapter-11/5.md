# Interview Questions & Solutions

## Question 1

### Question

Why does RabbitMQ use Exchanges instead of sending messages directly to queues?

### Ideal Answer

Exchanges decouple producers from queues and apply routing rules. Producers publish messages once, while exchanges determine which queues should receive them based on routing keys, patterns, or headers. This provides flexibility and loose coupling.

---

## Question 2

### Question

What is the difference between Direct, Fanout, and Topic Exchanges?

### Ideal Answer

A Direct Exchange routes messages using exact routing-key matches. A Fanout Exchange broadcasts every message to all bound queues. A Topic Exchange routes messages using wildcard pattern matching, allowing flexible event subscriptions.

---

## Question 3

### Question

Why are durable queues and persistent messages both required?

### Ideal Answer

A durable queue ensures the queue definition survives broker restarts, while persistent messages ensure the message contents are written to disk. Reliable messaging requires both; otherwise either the queue or the messages may be lost after a restart.

---

## Question 4

### Question

What is the purpose of a Dead Letter Exchange?

### Ideal Answer

A Dead Letter Exchange receives messages that cannot be processed successfully after retries, have expired, or violate queue limits. This isolates problematic messages while allowing the rest of the system to continue processing normally.

---

## Question 5 (FAANG)

### Question

Design the messaging layer for an online payment platform using RabbitMQ.

### Ideal Answer

Publish payment events to a Direct Exchange using routing keys such as `payments.created` and `payments.completed`. Bind durable queues for Payment Processing, Fraud Detection, Notifications, and Audit Logging. Configure persistent messages, acknowledgements, prefetch limits, retry policies with exponential backoff, and a Dead Letter Exchange for permanently failing messages. Deploy RabbitMQ as a clustered environment using quorum queues for fault tolerance and monitor queue depth, ACK rate, and unacknowledged messages for autoscaling and operational visibility.
