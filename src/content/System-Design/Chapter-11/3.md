# Interview Questions & Solutions

## Question 1

### Question

What is the difference between a Queue and a Topic?

### Ideal Answer

A queue distributes each message to one consumer, making it ideal for work distribution. A topic broadcasts each message to all subscribed consumer groups, making it suitable for event-driven systems where multiple independent services react to the same event.

---

## Question 2

### Question

Why are Consumer Groups used?

### Ideal Answer

Consumer groups allow multiple workers to process messages from the same topic in parallel while ensuring that each message is processed only once within the group. Different consumer groups can independently process the same event for different business purposes.

---

## Question 3

### Question

What is event replay?

### Ideal Answer

Event replay allows consumers to reprocess previously stored events. This is useful for recovering after failures, rebuilding application state, or introducing new services that need historical data.

---

## Question 4

### Question

Why should events be named in the past tense?

### Ideal Answer

Events represent facts that have already occurred, such as `OrderCreated` or `PaymentCompleted`. Past-tense naming clearly communicates that the action has already happened, distinguishing events from commands.

---

## Question 5 (FAANG)

### Question

Design the event architecture for an online marketplace.

### Ideal Answer

Use a Pub/Sub broker with topics such as `orders.created`, `payments.completed`, and `shipments.delivered`. Services like Inventory, Billing, Shipping, Analytics, Fraud Detection, Recommendations, and Notifications subscribe independently through separate consumer groups. Enable durable subscriptions with message retention for replay, implement idempotent consumers, use schema versioning for backward compatibility, and monitor consumer lag and throughput for autoscaling.

# Revision Notes

- Publish–Subscribe decouples publishers from subscribers.
- Topics broadcast events to multiple consumer groups.
- Consumer groups provide parallel processing while preserving one processing per group.
- Event replay enables recovery and state reconstruction.
- Durable subscriptions allow disconnected consumers to catch up later.
- Events should describe completed business facts.
- Schema evolution is essential for long-lived event-driven systems.
