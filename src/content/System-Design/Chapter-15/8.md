# Part 1 — Why Caching Exists

## Problem

Applications

become slower

as

traffic increases.

---

Without Cache

```text
User

↓

Application

↓

Database

↓

Disk
```

hits

database.

---

Database

becomes

bottleneck.

---

With Cache

```text
User

↓

Application

↓

Cache

↓

Database
```

Most requests

never

reach

database.

---

# Benefits

✔ Lower latency

✔ Lower database load

✔ Higher throughput

✔ Better scalability

✔ Lower cost

# Part 2 — Cache Patterns

## Cache-Aside

Application

manages

cache.

---

Read

```text
Cache

↓

Miss

↓

Database

↓

Cache
```

---

Write

```text
Database

↓

Delete Cache
```

---

Most common

pattern.

---

# Read-Through

Cache

loads

data

automatically.

---

Application

never

queries

database directly.

---

# Write-Through

```text
Application

↓

Cache

↓

Database
```

Both

updated

together.

---

Strong consistency.

---

# Write-Back

```text
Application

↓

Cache

↓

Later

↓

Database
```

---

Fast writes.

Eventual consistency.

---

# Write-Around

Writes

skip

cache.

---

Useful

for

cold data.

---

# Pattern Comparison

| Pattern | Best Use |
|----------|----------|
| Cache-Aside | Web Applications |
| Read-Through | Managed Cache |
| Write-Through | Banking |
| Write-Back | Analytics |

# Part 5 — Cache Eviction

## Why?

Memory

is limited.

---

Need

space

for

new data.

---

# LRU

Least Recently Used.

---

Removes

oldest

recently unused

object.

---

Best for

web traffic.

---

# LFU

Least Frequently Used.

---

Keeps

popular data.

---

Best for

long-term popularity.

---

# FIFO

First-In

First-Out.

---

Simple,

but

rarely

optimal.

---

# Random

Random eviction.

---

Very simple.

---

# TTL

Expires

after

fixed time.

---

Best

for

time-sensitive

data.

---

# Policy Comparison

| Policy | Removes |
|----------|----------|
| LRU | Least Recent |
| LFU | Least Frequent |
| FIFO | Oldest |
