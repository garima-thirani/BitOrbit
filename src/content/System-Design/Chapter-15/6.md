# Interview Questions & Solutions

## Question 1

### Question

What is a cache stampede?

### Ideal Answer

A cache stampede occurs when many requests simultaneously experience a cache miss for the same popular item, causing all requests to query the database at once and potentially overwhelming it.

---

## Question 2

### Question

What is cache penetration?

### Ideal Answer

Cache penetration happens when requests repeatedly query data that does not exist. Since the cache never contains the missing data, every request reaches the database unless mitigated with techniques such as negative caching or Bloom Filters.

---

## Question 3

### Question

Why are Bloom Filters useful in caching systems?

### Ideal Answer

Bloom Filters quickly determine whether an item definitely does not exist, preventing unnecessary cache and database lookups for invalid requests. They use very little memory and never produce false negatives.

---

## Question 4

### Question

What is the difference between a cache stampede and a cache avalanche?

### Ideal Answer

A cache stampede involves one highly popular key expiring and causing many concurrent database requests. A cache avalanche occurs when many cache keys expire simultaneously, generating a large wave of database traffic across multiple keys.

---

## Question 5 (FAANG)

### Question

Design a caching system that continues operating efficiently even if millions of cache entries expire during peak traffic.

### Ideal Answer

Use randomized TTLs to stagger expirations, refresh-ahead for popular keys, request coalescing with distributed locks to prevent duplicate database queries, Bloom Filters for invalid requests, negative caching for missing data, stale-while-revalidate to serve temporary stale responses, rate limiting and circuit breakers to protect the database, and continuous monitoring of cache hit ratios, lock contention, and expiration events.

# Revision Notes

- Cache stampedes occur when many requests simultaneously miss the same cache entry.
- Cache penetration is caused by repeated requests for non-existent data.
- Bloom Filters efficiently reject invalid lookups before they reach the database.
- Negative caching stores failed lookups temporarily to reduce repeated misses.
- Cache avalanches occur when many cache entries expire together.
- Randomized TTLs, refresh-ahead, and distributed locks are key production techniques.
- Circuit breakers and stale-while-revalidate improve resilience during cache failures.
