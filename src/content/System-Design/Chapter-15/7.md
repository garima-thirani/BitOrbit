# Engineering Notes

## CDNs Reduce Distance, Not Processing Time

A CDN

cannot

make

your application

compute faster.

Instead,

it reduces

the physical distance

between

users

and

cached content,

which often provides

the largest improvement

in perceived performance.

---

## Most Internet Traffic Never Reaches the Origin

Well-designed

CDN deployments

serve

the overwhelming majority

of static requests

directly

from edge servers.

The origin server

only handles

cache misses,

dynamic requests,

and content updates,

dramatically reducing

backend load.

# Interview Questions & Solutions

## Question 1

### Question

Why do CDNs significantly improve website performance?

### Ideal Answer

CDNs cache content at edge servers located close to users, reducing network latency, decreasing origin server load, lowering bandwidth consumption, and improving overall response times.

---

## Question 2

### Question

What is the difference between an origin server and an edge server?

### Ideal Answer

The origin server stores the authoritative copy of content, while edge servers cache copies closer to users. Edge servers serve most requests, contacting the origin only when necessary.

---

## Question 3

### Question

Why are versioned assets preferred over frequent CDN purges?

### Ideal Answer

Versioned assets create new URLs whenever content changes, allowing old cached files to remain valid while clients automatically request the new version. This avoids expensive global cache invalidation and improves cache efficiency.

---

## Question 4

### Question

How does Anycast routing improve CDN performance?

### Ideal Answer

Multiple edge servers advertise the same IP address. Internet routing protocols automatically direct users to the closest or best-performing edge server, reducing latency and improving availability.

---

## Question 5 (FAANG)

### Question

Design the content delivery architecture for a global video streaming platform.

### Ideal Answer

Deploy a CDN with globally distributed edge servers and regional caches. Cache video segments and static assets at the edge with long TTLs and versioned URLs. Use Anycast routing for user requests, adaptive bitrate streaming for varying network conditions, origin servers for cache misses, automatic cache prewarming for popular content, compression, WAF protection, DDoS mitigation, and continuous monitoring of hit ratios, bandwidth, and latency.

# Revision Notes

- A CDN caches content close to users to reduce latency and origin server load.
- Edge servers handle most user requests, while origin servers store authoritative content.
- Static content is ideal for long-term caching, while dynamic content requires shorter TTLs or bypass rules.
- Anycast routing directs users to the nearest edge location automatically.
- Versioned assets reduce the need for expensive global cache invalidation.
- Modern CDNs provide compression, image optimization, HTTPS termination, WAF capabilities, and DDoS protection.
- High CDN hit ratios are essential for scalable global applications.
