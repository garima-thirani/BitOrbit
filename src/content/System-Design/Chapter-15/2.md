# Interview Questions & Solutions

## Question 1

### Question

Why is Cache-Aside the most commonly used caching pattern?

### Ideal Answer

Cache-Aside is simple, flexible, and database-independent. Applications explicitly load data into the cache after a miss, making it easy to integrate with existing systems while minimizing unnecessary cache updates.

---

## Question 2

### Question

What is the difference between Write-Through and Write-Back caching?

### Ideal Answer

Write-Through updates both the cache and the database synchronously, providing strong consistency. Write-Back updates the cache immediately and delays database writes, improving write performance but introducing eventual consistency and the risk of data loss if the cache fails.

---

## Question 3

### Question

When should Write-Around caching be used?

### Ideal Answer

Write-Around is appropriate when newly written data is unlikely to be read soon. It avoids filling the cache with rarely accessed entries, preserving memory for hot data.

---

## Question 4

### Question

Why do many Cache-Aside implementations delete cache entries after database updates instead of updating the cache?

### Ideal Answer

Deleting cache entries reduces consistency problems. The next read automatically loads the latest value from the database and repopulates the cache, avoiding situations where the cache is updated successfully but the database write fails.

---

## Question 5 (FAANG)

### Question

Design the caching strategy for a global e-commerce platform serving hundreds of millions of users.

### Ideal Answer

Use Cache-Aside for product catalogs, Write-Through for user sessions and shopping carts requiring strong consistency, Write-Back for analytics and recommendation pipelines, and Write-Around for infrequently accessed logs. Combine Redis clusters, CDNs, TTL policies, monitoring, and cache invalidation to maintain high performance while ensuring data correctness.

# Revision Notes

- Cache-Aside (Lazy Loading) is the most widely used caching pattern.
- Read-Through delegates cache population to the cache layer.
- Write-Through updates the cache and database together for strong consistency.
- Write-Back (Write-Behind) optimizes write throughput by delaying database updates.
- Write-Around bypasses the cache during writes to avoid caching cold data.
- Each caching strategy represents a different trade-off between latency, consistency, and write performance.
- Large production systems often combine multiple cache patterns across different services.
